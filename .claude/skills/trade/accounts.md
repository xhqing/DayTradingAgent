# 数据源配置参考（老虎 SDK + 港股代码格式）

> 2026-07-15 信号模式精简：AI 只发信号、不管账户 / 资金 / 持仓；盯盘数据走富途 + 老虎。本文件仅保留**老虎 SDK 配置**与**港股代码格式**两条数据源相关参考。

## 港股代码格式（跨源调用）

港股标准代码本就是 **5 位数字**（如 `02800`、`00005`、`03688`），只是大部分第一位是 0。**老虎要求完整 5 位**（`'02800'`），**富途用 `市场.代码` 前缀**（`HK.02800`）。跨源调用若代码不匹配，规则是补 / 省前导 0，不是两套不同体系。

## 老虎 SDK（tigeropen v3.6.0）

- 配置文件：`~/.tigeropen/tiger_openapi_config.properties`（权限 600），含 `tiger_id` / `account` / `license` / `private_key` 等（明文凭证见 `accounts.json` 的 `tiger` 段，已 gitignore）。**密钥轮换（2026-08-17 立）**：老虎开发者平台一个开发者只有一套密钥对，实盘 / 模拟两个下载文件**仅 `account` 字段不同、私钥完全相同**（sha256 对比实测）；官方按「live / paper」提供的两份文件 `tiger_openapi_config_live.properties` / `tiger_openapi_config_paper.properties` 留在 `~/.tigeropen/` 备查，SDK 默认加载的仍是**无后缀主文件**（当前 = paper 副本，默认账户=模拟 17 位号，与「默认模拟、显式切实盘」设计一致）。轮换操作：开发者信息页点「重新生成」→ 下载新配置文件 → 替换本地三个文件（主文件以 paper 版为准）→ 跑 preflight 实测鉴权；**重新生成瞬间旧私钥立即作废**，别在盘中做。建议每 3~6 个月或怀疑泄漏时轮换。
- 加载：`TigerOpenClientConfig(props_path='~/.tigeropen/tiger_openapi_config.properties')`（**须传文件路径非目录**，否则 `QuoteClient()` 报 private key empty）。
- 服务地址：SDK 默认 `https://openapi.tigerfintech.com/gateway`，socket `openapi.tigerfintech.com:9883` ssl。实测 TBNZ 可用，无需手动改 itigerup.com。
- **实盘下单网络环境须满足券商合规要求 + SDK 代理配置（2026-08-14 立，重要；2026-08-23 表述中性化——合规要求本身可提、绕行细节与配置实值见本机配置）**：券商按**指令发出的网络环境**判定下单请求是否受理——不满足要求的地域出口下实盘开仓/加仓会被监管类错误码拒绝（仅允许平仓/减仓/转出），满足要求的出口正常受理（2026-08-14 实测：同一账户同一凭证，受限出口拒单、合规出口受理，拒单原因从监管拦截变为普通资金不足）。判定依据是「指令的网络环境」（非账户属性——此前误判为账户属性，已修正）。**⚠️ 关键实测结论（2026-08-14 当日，App 端坐实）：判定「位置」按流量出口，但必须「全部流量」走合规出口——仅代理 API 网关一个域名不够**。App / 桌面端在只代理单个域名时仍显示受限（客户端用多个域名、分流只覆盖一个时其余仍走本地出口）；客户端使用时须全局代理（或把客户端实际用到的全部域名都加进代理规则）；API 端（SDK）同理须保证所有券商域名走合规出口（当前本机代理白名单的域名规则够用，实值见本机配置；若日后 SDK 目标域名增多需同步补）。**配置三件套**：① 本机代理路由白名单加券商 API 域名规则（⚠️ 规则须按本机代理工具要求的格式写——格式不对会被生成配置时静默丢弃、规则不落地，2026-08-14 踩过）→ 改后重启代理；② SDK 代码层挂代理（`trade_utils_tiger.py` 的 `apply_proxy`，config.json 的 `proxy` 节控制，默认 live_only 仅实盘走代理——**SDK 用 urllib3.PoolManager、不读 HTTP(S)_PROXY 环境变量**，环境变量对 SDK 无效，curl/requests 认、urllib3 不认）；③ 盘前检查代理状态 + 实盘下单前实跑 `get_assets` 确认请求正常受理。**socket 长连接（9883 行情推送）不走 HTTP 代理**，如需代理须另行处理（~~当前未用到~~ 2026-08-17 已处理：裸 socket 直连在 IP 白名单下被拒 `code=4 access forbidden`，`apply_socket_proxy` 已把 socket.create_connection socks 化走本机代理 socks 口，见下条白名单节）。
- **老虎 IP 白名单 + 代理节点（2026-08-17 上线；2026-08-23 表述中性化——节点清单与白名单镜像只存本机配置，正文不写 IP 实值）**：老虎开发者信息页 **IP 白名单已配置生效**（开发者账号级、`;` 分隔、不区分资金账户——同时锁模拟 + 实盘的 API 调用出口，只管 API 不影响 App）。**SDK 全流量走代理**（config.json `apply_scope: all`，金丝雀设计：模拟盘断 = 提前暴露代理 / 白名单 / 节点问题，实盘不踩同一坑；**2026-08-21 起实盘须先解锁才挂代理**——见下方「实盘误开防护」节，模拟盘金丝雀不受影响）。**节点清单与白名单镜像存本机配置**（config.json `proxy.tiger_whitelist`，与老虎开发者信息页同步维护）——节点入口 IP、节点域名体系、节点↔IP 对应关系均为运维细节，不在公开文档展开（订阅节点 IP 会不定期变动，**变动后须同步改老虎白名单**：白名单只认 IP 不认域名；模拟盘金丝雀先断报警 = 更新信号）。**生效验证（2026-08-17）**：模拟盘走代理行情 + 资产查询通、实盘走代理资产查询通、非白名单出口直连被拒「access forbidden: request ip is not in ip whitelist」——白名单真实拦截生效。**运维口径（2026-08-19 起改为守护自动化；2026-09-01 T133/T128 修订为全量清单 + 可最小化面板）**：[`proxy_guard.py`](scripts/proxy_guard.py) 自动做「漂移检测（节点全景以 `xpilot node list` 实查为准、失败回退 nodes.json）+ 当前节点漂出时自动 `xpilot switch` 切白名单内节点恢复 + 响铃弹**可最小化提醒面板**（AppKit 面板 [`scripts/alert_panel.swift`](scripts/alert_panel.swift)、编译产物 tmp/——可最小化到 Dock 点图标唤回，替代 osascript 模态窗「置顶不可最小化」的遮挡问题；产物缺失自动现场编译、无 Xcode CLT 时回退 osascript）给**当前全部可用 IP 清单**（实查全部节点出口 IP——老虎白名单有数量上限，旧口径只给漂移新 IP、用户只能逐个补且旧 IP 无法清理会占满额度；新口径支持「先清空 → 一次性全量粘贴」）」，preflight 启动时与 monitor_watcher 盘中每 10 秒各跑一次（watcher 2026-08-21 空转警报删除后白名单检测是其唯一保留功能）。**剩余人工动作（2026-08-19 晚改为按钮确认制，2026-09-01 起为全量重配制，仅一步）**：面板提示加白时去老虎开发者信息页 → IP 白名单：**先清空已有全部白名单 IP，再一次性粘贴面板给的全部可用 IP**（老虎无白名单 API、无法全自动），完成后**回面板点「已添加」**——proxy_guard 收到点击信号自动把 config.json 的 `tiger_whitelist` **全量替换**为面板清单（与老虎页「先清空再全量加入」操作对应；旧合并口径会残留老虎页已清掉的死 IP、本地与老虎页脱节）。点「取消」/ 面板超时 = 暂不同步、5 分钟后再提醒。⚠️ 只有点击才代表老虎页已按清单重配——没改就点会让本地与老虎页不一致（守护漂移判定失真）。全漂出时守护报「全漂出警报」（退出码 2）、必须人工加白。

- **实盘误开防护：会话级解锁 + 网络层物理拒单（2026-08-21 立）**：auto 模式防 AI「不小心」开仓到实盘（误传 `--account live`、上下文残留、混淆型失守——2026-08-18 实证散文双闸会失守，工具在场全守住）。**默认态（无解锁文件）实盘物理不可达，两道检查点**：① 6 个下单脚本（open/close/move_stop × 港美）前置闸——解析到 `--account live` 且解锁无效 → `{ok:false, blocked_by:"live_locked"}` 拒单；② `apply_proxy` 实盘解锁闸——当前账户是实盘且解锁无效 → **跳过挂代理保持本地直连** → 老虎 IP 白名单在**连接层**拒（本地出口不在白名单，实测「access forbidden」——比订单层监管拦截更强、不受老虎政策变动影响）。模拟盘路径零改动（照旧走代理，金丝雀保留、`apply_scope: all` 不动）。**授权链（AskUserQuestion 点击即解锁）**：① AI 发 AskUserQuestion（问题须含打码号 `67****91` 或「--account live」+「实盘」+ 授权范围——含糊提问 hook 不写凭证）→ ② 用户点「确认授权」→ PostToolUse hook [`live_auth_witness.py`](../../hooks/live_auth_witness.py)（matcher AskUserQuestion）见证真实点击、写 10 分钟短时凭证 `live-auth.<sid>.local`（**按会话 ID 分文件**，2026-08-24 立——多会话并行授权互不偷凭证；HMAC 密钥 = accounts.json `tiger.live_unlock_salt`，用后即焚、一次点击只换一次解锁）→ ③ `python3 scripts/live_unlock.py verify-auth` 验凭证 → 写解锁文件 `live-unlock.<sid>.local`（token = sha256(salt + 实盘账户号 + 到期戳 + session_id)，24h 自动过期、绑定本会话 sid——并行会话各持各的解锁文件互不覆盖、resume 换 sid 自动作废需重新授权；**为什么要分文件（2026-08-24 实盘早盘实测竞态）**：原单文件下会话 B 解锁会覆盖 A 的解锁文件、授权凭证会被先到的 verify-auth 消费，与「多会话并行各授权各解锁」设计意图冲突）→ 焚凭证。**人工终端场景**（用户自己在终端跑 live 脚本、环境无 session_id）：读写 `live-unlock.manual.local`（人工终端之间共享该文件，用户自己操作自己电脑，无 AI 越权面）。**撤销**：`python3 scripts/live_unlock.py revoke`（删本会话文件即收回，24h 自动过期兜底）；整体收回全部会话 `revoke --all`。**为什么防得住混淆型失守**：关键不在「AI 不能写解锁文件」而在「AI 写了也无效」——token 原料（salt + 实盘账户号）存 accounts.json 内部（permissions.deny 挡 Read + secret_guard 挡 Bash 读取），AI 上下文只有打码号、造不出合法 token；「跳过提问直接建文件」也无效——无 hook 见证凭证，verify-auth 拒绝（`no_fresh_authorization`）。**实测验证（2026-08-21）**：PostToolUse 对 AskUserQuestion 触发且 payload 含 tool_response.answers（临时 hook 写日志坐实）；全 6 脚本误传 `--account live` 全部 `live_locked` 拒单；无解锁时 `load_config(account='live')` 实测不挂代理（stderr 打印未解锁提醒）、模拟盘照旧挂代理；授权链端到端（点击→凭证→解锁→焚毁→revoke）全通；会话绑定三场景（本会话 ok / 其它会话 bad_token / 人工终端放行）全对。**残余边界（如实保留）**：① 环境变量可被命令行覆盖（`CLAUDE_CODE_SESSION_ID=sid_A python3 …` 冒用会话身份）——须先翻 transcript 拿 UUID 再定向构造，属多步蓄意动作、混淆态 AI 走不出；② 自写代码手动挂代理 + 实盘号 = 主动绕过，本机各层可被逐步攻破——券商侧白名单 + 监管拒单两道兜底（AI 够不到的地方）；③ 实盘日开窗（解锁后 24h 内走合规出口、监管拦截不再生效）为设计内窗口，钥匙在用户手里。

**⚠️ WebSocket 行情推送链路补挂代理（2026-08-17 晚修）**：白名单上线当日 13:28 起 `ws_segment.py`（老虎 PushClient，`ssl://openapi.tigerfintech.com:9883`）全部连不上——`code=4 access forbidden`。**根因**：PushClient 在 SDK transport 层用 `socket.create_connection` 裸 TCP + TLS 建链，**不走 `apply_proxy` 换掉的 `web_utils.http_pool`（那只管 REST）**；白名单上线前 WS 直连也放行、上线后直连出口（本地出口）被拒——WS 从未走过代理，白名单把这个盲区暴露了。**修复**：`trade_utils_tiger.py` 新增 `apply_socket_proxy(proxy_url)`——把进程内 `socket.create_connection` monkeypatch 成「先经 xpilot socks5（127.0.0.1:1080）建链」（http 代理端口 1087 按约定 −7 = socks 1080），`apply_proxy` 挂 REST 代理时自动连带调用（`load_config` 路径全覆盖）；`ws_segment.py` 也单独调用（它直接用 TigerOpenClientConfig、不走 load_config）。socks 端口不通 / PySocks 不可用时保留直连并 stderr 警告（不炸进程）。**修复后实测（2026-08-17 20:17）**：ws_segment 8 秒段连接 + 订阅成功（盘外无行情推送属预期）；同进程 REST（ProxyManager）+ WS（socks）双链路均通；实盘走代理查资产 net_liquidation 与 buying_power 均 USD 1.5 万 / 5.9 万量级、查询正常（精确值不写入被跟踪文件）。**实盘下单不受此盲区影响**（下单走 REST、一直在代理内）——但该事故印证金丝雀设计的价值：模拟盘 WS 先断 = 提前暴露，实盘下单链路无感。
- **订单时间字段三件套（2026-08-13 立，复盘 / 时点核对必看）**：老虎订单对象（`get_orders()` 返回）有**三个**时间字段，含义不同，**复盘核对成交时点必须取 `trade_time`、严禁取 `update_time`**：
  - `order_time`：下单（提交）时刻。
  - `trade_time`：**成交时刻**——复盘算持仓时长、核对「是否盘中成交」、填 CSV 的 `entry_time`/`exit_time` 都该取这个（毫秒 Unix 时间戳，换算用 `datetime.fromtimestamp(ts/1000, tz=UTC+8)` 港股 / 美股按交易所时区）。
  - `update_time`：订单**最后一次被系统更新**的时刻（含日内结算、批处理、状态回写），**不是成交时间**——实测曾显示凌晨 0:07（港股根本不交易），用它当成交时间必错。
  - **踩坑经过（2026-08-13 实盘账户查 4 条历史订单）**：手动换算时误用 `update_time`，把 2025-05-14 港股盘中 09:44 成交的阿里单算成了 05-16 凌晨 00:07；改用 `trade_time` 后时间全部正确落在港股盘中（09:44 买、11:39 卖）。`review.py` 的 `entry_time`/`exit_time` 是从复盘 CSV **手填**读的（不从订单对象自动取），故脚本本身无此 bug，但人工填时务必从 `trade_time` 取、勿取 `update_time`。
  - **资产查询的 `summary.timestamp` 是另一回事**（`get_assets()` summary 段的时间戳，用于判「账户是否开通资产权限」：`net_liquidation=0 且 timestamp=None` → 未开通），与订单成交时间无关，勿混淆。
- **行情权限**：港股 Level1 免费（`get_stock_briefs` 可用、与富途交叉验证一致）。**美股无行情权限**（TBNZ 报 `4000: permission denied`）。✅ **港股 Lv2（10 档）实测可用**（2026-07-10 盘中：`subscribe_depth_quote` 返回 ask/bid 各 10 档，含 price/volume/orderCount；expire=-1 永久免费。depth 未见经纪队列，broker 需富途）。代码骨架见 `tiger-websocket.md`。
