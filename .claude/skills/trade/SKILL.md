# Trade

AI 用富途 OpenD / 老虎 SDK（盯盘行情数据主力，Level2 盘口 / 经纪队列 + 资金流 + WebSocket 毫秒级推送）做港股 / 美股日内交易的执行规范。**信号模式：AI 只发买卖信号、用户手动执行，AI 不管账户、不下单、不核实资金 / 持仓**。盯盘数据走富途 + 老虎（资金流富途更优：含 super 超大单 + 分钟序列 + 十大买卖经纪）。所有规则来自 2026-07-03 实战复盘，**交易亏钱可接受，但事实错误和违规操作是 bug、不可接受**。

## 触发条件

当用户提出以下任一意图时激活本 skill：
- 盯盘 / 看盘 / 分析标的走势 / 给买卖信号
- 发开仓信号 / 平仓信号（AI 不直接下单，只发信号由用户手动执行）
- 交易复盘 / 统计信号胜率 / 赔率 / EV
- 任何涉及富途 OpenD / 老虎 SDK 的盯盘数据操作

## 第一原则：事实先验证，再说结论（最高优先级）

这是一切交易判断的地基，违反这条等于在沙地上盖楼。**凭推测当事实输出，比交易亏钱更不可接受**（2026-07-03 用户多次纠正）。具体执行：

1. **接触任何标的代码，第一件事用富途 `get_market_snapshot([code])` 查 `name` 字段确认真身**，再谈分析。港股代码本是 5 位数字（如 02800、00005、03688），无语义规律，凭记忆会认错（0823 是领展 REIT 不是汇丰、汇丰是 0005）。代码 + 中文名一起写进汇报。
2. **算术必须实算**，不许心算报数（如以为"400 不是 200 的倍数"，实际 400÷200=2）。
3. **交易日历用富途 `request_trading_days` 查**，不许凭记忆说哪天开盘。港股 7/3+7/5 周末休市、美股 7/3-7/4 独立日休市等都曾搞错过。
4. **API 字段先实跑一次看真实返回结构再用**，不许凭印象猜字段名（如富途 `get_market_snapshot` 返回 DataFrame、老虎 `get_stock_briefs` 也是 DataFrame，按对象属性直取会得 None）。
5. **手续费 / 利率 / 汇率等数字必须有据**，禁止估算报数，查不到标"待查"绝不编数字填进去。
6. **币种符号必须分明**（2026-07-04 用户规矩）：港币一律写 `HK$` 或 `HKD`，**禁止用裸 `$` 表港币**——`$` 在本 skill 默认指美元。报数时须据标的所在市场正确标注币种，美元写 `$` 或 `USD`、港币写 `HK$`/`HKD`，混用会让人误把港币当美元（或反之）。

## 🔒 盯盘恢复协议（Resume Protocol，2026-07-28 立，最高优先级）

盯盘要求**连续**（盘面秒变、信号时效以秒计），但执行环境会**断层**——断网、用户主动暂停再重启、工具故障 / 分类器不可用、会话压缩、长任务占用，任一都可能让 AI 失去时间感知 + 数据过时 + 上下文丢失。**最危险的是用过时数据发"看起来成立"的信号**（2026-07-28 中芯事故根因：13:45 的 snapshot 数据 → 15:34 才响铃发信号，参考价过时 1h49m、响铃实测价也因取价动作被挡而错过，信号最终作废）。

**总则：AI 的内存（对话上下文）不可信，文件才是地面真相。任何时候重新获得执行权，第一动作是从文件重建状态、刷新数据，绝不用断层前的旧数据发信号。**

### 触发条件（任一即跑恢复协议，作为第一动作）

- 收到用户消息唤醒（尤其"继续盯盘 / 继续"类重启指令）
- 后台采样段结束通知唤醒、但距上次段结束明显偏久
- 工具故障 / 分类器不可用 / 断网恢复后
- 会话被压缩、长任务结束后回来
- 自己察觉距上次 `date` / `snapshot` 可能过了较久

**一句话：只要不是连续顺畅的段间循环（段结束 → 读数 → 重启下一段），就先跑恢复协议再继续。**

### 恢复协议五步（封装在 `scripts/resume.py`，跑一次即可）

`python3 scripts/resume.py [标的1,标的2,...]`（可选标的 = 额外 snapshot 刷新现价，如持仓标的）：

1. **`date` 核实真实时间 + 算"距上次活动的时间差"**——上次活动时间 = `tmp/monitor_log_*.csv` 最后采样时间 与 `signals/ring-log.csv` 最后响铃时间的最近者；距现在 ≥ 5 分钟 → 输出 ⚠️ 断层警告。
2. **判市场状态**：港股盘中 / 港股盘外（盘前等开盘 / 收盘则停盯）/ 美股盘中 → 决定能否发信号。
3. **从文件重建上下文**（不靠内存）：读今日 signals 文件（`signals/YYYY-MM-DD-HKT-signals.md` / `-ET-signals.md`）确认当前**未平仓假设持仓**（开仓/加仓批次 + 入场价 + 止损 + 止盈）+ 有无**响铃未取实测价的悬空信号**（距响铃 > 5 分钟未取 → 标注作废或盘后回查，盘中不调 `request_history_kline`）；读 `signals/equity-log.csv` 末行确认当前 equity（算单笔预算 B）。
4. **`snapshot` 刷新所有相关标的现价**——断层前的价一律作废。
5. **处理悬空项**：响铃未取实测价的信号 → 作废或盘后回查；假设持仓在断层期间可能被动触发止损/止盈（现价越过止损/止盈位）→ 标注"大概率被动触发、high/low 待盘后回查确认"，不武断判定，盘后用历史 K 线精确回查、按假设平仓更新 equity。

### 发信号硬前置（针对过时数据发信号的直接补丁，2026-07-28 立）

发任何信号前（`ring.sh` 响铃之前）强制检查：
- 若**距上次 `date` > 2 分钟** → 重新 `date` 核实时间；
- 若**距上次 `snapshot`（该标的）> 2 分钟** → 重新 `snapshot` 取最新价当参考价；
- 不满足 → **禁止发信号**，先 `date` + `snapshot` 刷新再发。

这条与「第一原则·汇报当前时间 / 盘面时点前 date 实测」互补：那个管"话说对没"，本条管"信号参考价过时没"——发信号是真实交易基准，参考价过时 = 用户下单基准错 = 实亏。

### 时间断层哨兵（被动感知，`monitor_segment.py` 内，2026-07-28 立）

`monitor_segment.py` 启动时读各标的 log 最后采样时间，距现在 ≥ 5 分钟（正常段间循环 < 1 分钟）即输出醒目警告："⚠️ 时间断层哨兵：距上次采样 X 分钟，先跑 `resume.py` 重建上下文、刷新现价，禁止直接用断层前旧数据发信号。"——即便 AI 没主动意识到断层，脚本强制提醒（AI 不能只靠记忆执行规定、要靠工具强制，见「盘中动态修正方向」2026-07-27 教训）。

### 🔴 信号模式总则（2026-07-15 初立自主盯盘循环 → 2026-07-16 修订：演练改真实交易；最高优先级，覆盖本段第 4-8 条及下方「用户执行反馈」「信号输出与持仓检查」相关旧描述）

⚠️ **2026-07-16 用户关键澄清：信号 = 真实交易（用户拿信号真实下单、真金白银），不是演练。** 故原「自主演练循环 / 敢于发不完美信号抓演练机会」框架中「为积累样本降低门槛」的倾向作废，改为真实交易的严谨——**质量优先于数量**（见第 3 条）。机制层保留（假设执行不查 positions、响铃最先写文件最后、复盘由用户触发、AI 不下单用户手动执行）。原 2026-07-15 框架 5 条中，第 3 条 2026-07-16 已重写、其余机制保留：

1. **假设执行、不查 positions**：AI 发出任何信号（开仓/加仓/减仓/平仓/移动止损）后，**直接假设用户已按信号执行**（即假设已持仓/已平仓），**不查 positions、不等用户反馈**。用户是否真执行是用户自己的事（用户可能不下单，但 AI 当成已成交继续盯）。用户若真实操作致持仓变化，会**临时主动告知**——只有这时 AI 据实调整；用户没说就按假设持仓盯。
2. **自主循环、不打断用户**：AI 自主跑「盯盘→发信号→记录信号→总结经验教训」循环，不中途停下问用户、不等确认（用户会睡觉/离开）。**港股盘中 + 美股盘中（美东 09:30 开盘后到 16:00 收盘）自主盯**；美股盯到**用户发出停止盯盘指令**或**美东 16:00 收盘**（取先到）为止，停盯前必须主动平仓、不留单（2026-07-19 修订，撤销原「美东 12:00 固定停盯」+「留单 vs 主动平二选一」，见护栏 10）。盯盘由用户指令启动、AI 不自主启动。

   > **⚠️ 盯盘期间禁用 AskUserQuestion / 无人值守自主决策（2026-07-29 用户立）**：盯盘启动后（用户发了盯盘指令），AI 必须**无人值守**自主跑完整循环——用户不一定盯着会话窗口（可能离开/睡觉），AI 所有盯盘决策（换标的/方向/止损/平仓/移损/降频）**自主完成、绝不 AskUserQuestion 中断**（AskUserQuestion 会阻塞等用户、用户不在线就卡死，违反无人值守）。
   > - **无机会自主决策树**（盯盘期间无合格信号时，按序自主执行、不问用户）：① **第一动作换标的**（hot_list 刷新 → 找活跃顺势标的 → snapshot/kline 核实，绝不死盯横盘标的）；② **第二动作降频**（整个市场都无活跃机会时，AI 自主放宽采样间隔到 3-5 分钟，减少消耗、不漏大级别信号；出现信号苗头立即恢复 40 秒密盯）；③ **持续盯到收盘/用户喊停**。
   > - **AskUserQuestion 边界**：盯盘期间（用户发盯盘指令后到喊停/收盘）**禁用**；只在非盯盘场景（盘后复盘、策略讨论、盘前预热方向对齐）可用。2026-07-29 教训：盯盘无信号时用 AskUserQuestion 问「是否继续盯/降频」，阻塞中断盯盘，用户纠正「无人值守、第一动作换标的、第二才降频」。
3. **质量优先、不为积累样本发不完美信号（2026-07-16 修订，原「敢于发不完美信号」作废）**：信号是真实交易（用户真实下单、真金白银），**质量优先于数量——不为「积累样本 / 想开仓」降低门槛**。开仓必须过两道闸（仅 🟢 高置信 + 赔率 ≥ 1.2，见「交易策略纪律」开仓基准与置信度分级），不达标就不发、宁可观望整场。原 2026-07-15「演练阶段敢于发信号、赔率/入场点不完美也发」作废（2026-07-16 SOXL 中置信信号致用户实亏 ~$120 后用户立）。
4. **信号记录到 signals/ 目录（复盘基准，时序：响铃最先 → snapshot 取响铃时刻价 → 最后写文件；港美分开）**：信号文件主要用于复盘 + 用户事后挂止损/查字段（用户下单靠响铃+思考过程预判标的方向，对话不再输出关键字段），故**决定发信号后第一个动作是立马响铃（`ring.sh`）**、第二个动作 snapshot 取响铃时刻价、最后一个动作写信号文件（`log_signal.sh`，完整内容+时间戳；完整时序见「信号格式 · 🔔 信号时序总则」）。港股 `signals/YYYY-MM-DD-HKT-signals.md`、美股 `signals/YYYY-MM-DD-ET-signals.md`（2026-07-15 用户立：港美信号分开记、文件名带 HKT/ET 时区标识，便于分别复盘）。记录必含：发信号时间（**精确到秒**）、标的、**批次（开仓量 / 第 n 次加仓量；减仓 / 平仓 / 移损须注明针对哪个批次）**、方向、量、参考价、止损、止盈、单笔预算、预估 max_loss（响铃后按实测价修正为实际 max_loss）、置信度、依据、风险提示（不写账户 / 资金）。`signals/` 目录 2026-07-15 恢复（2026-07-10 曾 archive 删除）。
5. **复盘由用户指令触发、盘中不复盘（2026-07-16 立，覆盖原「自主复盘」）**：AI **不自主复盘**——**盘中不发任何复盘内容、盘后也不主动复盘**，只有**收到用户明确的复盘指令**才做复盘——按 `references/review-and-evaluation.md` 逐项统计（**样本总量 / 胜率 / 赔率 / EV% / 平均每单盈利金额** + 用户临时指定的其它分析），并点评各笔依据是否站得住、入场止损止盈是否合理、错过哪些机会。原 2026-07-15「盘中及收盘后 AI 自主复盘、不等用户要求」作废。⚠️ 注意区分：**记录信号**（发完信号 append 到 `signals/` 文件）是发信号后的即时动作、**不是复盘**，仍照常做；被限的是「事后分析评价」性质的复盘。
6. **AI 职责边界（2026-07-15 用户细化，最高优先级）**：AI **只负责 ① 发信号 ② 记录 ③ 事后复盘统计（胜率 / 赔率 / EV）**，**不管账户、不下单、不核实资金 / 持仓**。仓位按「单笔预算 B = `risk.risk_fraction` × 当前 equity」选最接近的离散仓位作风控建议（不查实时账户；equity = `initial_equity` + 累积假设盈亏，见硬性护栏 1「单笔预算与 max_loss」「权益更新」）。复盘仍是 AI 的核心职责之一，但**由用户指令触发、盘中不做**（2026-07-16 修订，见第 5 条）——收到复盘指令后，统计每个信号从发出到平仓的**胜率、赔率、EV**（EV=胜率×赔率−败率×1 是**开仓前预估口径**、保守假设亏满 1R；复盘的实际 EV 用真实败赔率 $R_L$、见 `references/review-and-evaluation.md` · 统计量定义，核心判据；**不是简单收益率**）。**默认假设：所有标的都可做空**（资金按 `initial_equity` + 累积盈亏动态算 B，2026-07-26 起不再「资金总是够用」）——发做多 / 做空信号均不犹豫可行性，专注方向与入场点判断。

> 下方「用户执行反馈」（positions 核实 / 等成交反馈）、「信号输出与持仓检查」等章节里 2026-07-15 前的旧描述（如 positions 前置、信号不写 MD），如与本升级冲突均以本升级为准。**AI 仍禁止真实下单**（信号模式不变）。

1. **禁止自动下单**：AI 不得调用任何券商的下单 / 撤单命令（order buy/sell/cancel 等）。所有买卖由用户拿信号后在自家 App 手动执行。
2. **禁止设置条件单**：AI 不得挂任何条件单 / 止损单 / 止盈单（MIT / MO / LIT / LO 一律不挂）。止损价只在开仓信号里**计算并告知**，由用户在 App 自行挂止损。
3. **输出五类信号**（2026-07-18 用户调整：新增加仓/减仓、删除移动止盈）：
   - **开仓信号 🟢（绿色）**：必含 ① 标的（代码 + 中文名，已富途快照核验）② **批次 = 开仓量（第 0 笔交易）** ③ 方向（做多 / 做空）④ 具体开仓量（按「实际 max_loss 最接近单笔预算 B」选 lot_size 整手仓位，见硬性护栏 1「选仓位」）⑤ 开仓参考价 ⑥ **计算出的止损价**（技术位）⑦ 止盈参考 ⑧ **单笔预算**（= risk_fraction × 当前 equity）+ **预估 max_loss**（= 仓位 × 每股止损距，按参考价；响铃后按实测价修正为实际 max_loss）⑨ **预期赔率**（=止盈距÷止损距，≥1.2 才发，2026-07-22 用户立）⑩ 一句话策略依据。
   - **加仓信号 🔵（绿色，标题"加仓"区分）**：**每次加仓 = 另外一笔独立交易**（见「概念区分」），必含 ① 标的 ② **批次（第 n 次加仓）** ③ 方向（加多 / 加空）④ 加仓量（按「实际 max_loss 最接近加仓时的单笔预算 B」选 lot_size 整手仓位，B = risk_fraction × 当时 equity）⑤ 加仓参考价 ⑥ **加仓止损位**（本笔独立止损，独立于其它批次）⑦ **本笔单笔预算 B + 预估 max_loss**（本笔独立、不与原仓合并）⑧ 预期赔率（本笔独立算）⑨ 依据。⚠️ 加仓不再「与原仓合并 max_loss」——每次加仓是独立一笔交易、独立享一个 B、独立止损；同标的多笔交易（开仓 + 各次加仓）各自复盘。
   - **减仓信号 🟠（橙色）= 部分平仓（按批次）**：必含 ① 标的 ② **针对批次（开仓量 / 第一次加仓量 / … / 第 n 次加仓量）** ③ 方向（减多 / 减空）④ 减仓参考价 ⑤ 减仓量 ⑥ 理由（锁利 / 减风险；该批次减仓后剩余仓位仍按原止损管理）。
   - **平仓信号 🔴（红色）= 主动清仓（按批次）**：必含 ① 标的 ② **针对批次（开仓量 / 第一次加仓量 / … / 第 n 次加仓量；清空整个标的则列全部未平批次）** ③ 方向（平多 / 平空）④ 平仓参考价 ⑤ 一句话理由（动能减弱 / 回踩不破前低 / 资金流转正 / 到硬平仓时点 等）。⚠️ **平仓 = 清空该批次的全部持仓**（按批次平；区别于减仓 = 该批次部分平仍有剩余）；止损条件单被动触发不发 🔴、不响铃，只标记记录（2026-07-16 立）——理由里**不含「触及止损」**。
4. **信号 emoji 标识**：开仓 🟢 / 加仓 🔵 / 减仓 🟠 / 平仓 🔴 / 移动止损 🟡（移动止盈 🟠 已于 2026-07-18 取消）。**第一个动作立马响铃（`ring.sh`）、之后 snapshot 取响铃时刻价、最后 `log_signal.sh` 写入对应市场文件**（对话不输出关键字段；港股 `signals/YYYY-MM-DD-HKT-signals.md` / 美股 `signals/YYYY-MM-DD-ET-signals.md`，复盘用；完整时序见「信号格式 · 🔔 信号时序总则」）。
5. **盯盘仍由 AI 做**（最高频采样，见「盯盘节奏」）→ 产生信号；**执行权全在用户**。
6. **AI 职责边界**：分析、盯盘、算仓位 / 止损价、发信号（**第一个动作立马响铃 `ring.sh`、之后 snapshot 取响铃时刻价、最后 `log_signal.sh` 写信号文件（对话不输出关键字段）**：港股 `signals/YYYY-MM-DD-HKT-signals.md` / 美股 `signals/YYYY-MM-DD-ET-signals.md`；完整时序见「信号格式 · 🔔 信号时序总则」）。假设执行、不等用户反馈成交（详见「信号模式总则」第 1、6 条）。**不记账、不实时算盈亏**（复盘时再算）。
7. **账户与下单由用户自决**：AI 不管账户、不下单。用户拿信号后在自家 App 手动执行（用哪个券商 / 账户由用户自决）。
8. **信号时效性：慢决策 / 查询项前置到盯盘启动，发信号零额外延迟（2026-07-13 用户铁律）**：盘中盘面秒变，发信号前任何临时查询 / 思考 / 确认都会让信号发出来时盘面已大变、结论失配。故以下事项**全部前置到盯盘启动时（preflight 阶段）做好，盘中触发信号那一刻直接拿来用、不再临时做**：
   - **汇率**：盯盘启动时就查好当日 USD/HKD 汇率（富途 `get_market_snapshot` 或汇率接口），盘中算美股仓位 / 止损额度直接用预备好的数，**不临时查、不临时换算**。
   - **不反复确认**：拿到最新 `quote`/盘口数据后直接算 + 发信号，**只要信号够快盘面就不会大变**；不为求稳而反复 `quote` / 反复核实拖时间。相关核实（标的分类、quote 实价）已在 preflight / 启动序列做过，发信号时不重复。假设执行、不等用户反馈成交（见「信号模式总则」第 1 条）。
   - 一句话：**信号触发那一刻零额外思考 / 零额外查询**——能前置的全前置，盘中只做「拿最新数据 → 算 → 发」。

## 信号格式（2026-07-30 更新：信号时序改为「响铃最先 → snapshot 取响铃时刻价 → 最后写文件」，删对话输出关键字段、用写文件代替）

### 🔔 信号时序总则（2026-07-29 用户立，覆盖原「先写文件、再响铃」，最高优先级）

用户**时刻盯会话输出（含 AI 思考过程）**，能预判 AI 即将发信号、预判标的+方向+参考价，**时刻准备下单**。故实战下单靠**「听到铃」**（秒级，用户从思考过程已知标的+方向、听到铃即下单），不靠对话关键字段、也不靠信号文件（写文件太慢）。信号文件用于**复盘 + 用户事后挂止损/止盈参考**（完整字段在文件里）。故三步时序：**响铃最先（拍板即响）→ snapshot 取响铃时刻价（成交价）→ 写信号文件（复盘用）**（2026-07-30 用户立：删对话输出关键字段、用写文件代替）：

1. **第一个动作：立马响铃**——拍板决定发信号那一刻，立即调 `ring.sh`（只响一声对应类型提示音 + 记响铃时刻到 `signals/ring-log.csv`，时间精确到秒）。**零延迟**，不等写文件、不等算全部参数、**也不输出对话关键字段**——用户听到铃 = 认定 AI 拍板了（标的+方向从思考过程已知），立即开始下单。
2. **第二个动作：立马 snapshot 取响铃时刻价**——响铃后立即用 `get_market_snapshot` 的 `last_price` 取当前价，作为响铃实测价（成交价近似，详见下「响铃后立即取实测价作为成交价」段）。取价紧跟响铃之后（T0+几秒内）。
3. **最后一个动作：写信号文件**（响铃 + 取价之后）——把完整信号内容（标题 + 表格 + 依据 + 风险提示 + 响铃成交价注释）经 stdin 传给 `log_signal.sh`，写入对应市场文件（港股 `signals/YYYY-MM-DD-HKT-signals.md` / 美股 `signals/YYYY-MM-DD-ET-signals.md`），标题框线内（标题行后、第二条框线前）自动带发信号时间戳（读 `ring-log.csv` 末行 = 响铃时刻，复盘用）。**用户 App 挂止损/止盈、复盘查字段都看信号文件**。

**为什么响铃最先、且和写文件分离（2026-07-29 用户立）**：原 `alert.sh`「写文件 + 响铃」二合一，写文件（构造完整 markdown）有延迟、会让响铃滞后几秒～十几秒；用户实战下单靠响铃（听到即动），响铃滞后 = 下单滞后 = 错过最佳价。拆分后响铃单飞（`ring.sh`，即时），写文件另走（`log_signal.sh`，复盘用、不阻塞下单）。

**`ring.sh` 调用方式**（第一个动作，响铃 + ring-log）：

```bash

# type=open/close/ts（决定音色）；symbol/note 可选，写入 ring-log 备查
```

**`log_signal.sh` 调用方式**（最后一个动作，信号内容经 stdin 传入，写文件 + 时间戳）：

```bash

（完整信号内容：标题 + 表格 + 依据 + 风险 + 响铃成交价，复盘用、也是用户挂止损/查字段的来源——对话不再单独输出关键字段）

```

⚠️ **`alert.sh` 已弃用（2026-07-29）**：原「写文件 + 响铃」二合一脚本 `alert.sh` 已弃用（调用即报错提示用 `ring.sh` + `log_signal.sh`）；SKILL 内所有引用 `alert.sh` 的旧描述以本段新时序为准。

**响铃后立即取实测价作为成交价（2026-07-17 立；2026-07-30 用户立简化：取消价格范围与成交判据，响铃时刻价直接当成交价）**：响铃是用户开始 App 操作的时刻，响铃时刻的市价 ≈ 用户实际成交价。**响铃实测价是确定成交价、算实际 max_loss / 修正赔率、决定后续盯盘逻辑（持仓盯止损 vs 空仓找机会）的唯一依据——不取 = 信号悬空、不知成交价、持仓状态无法确定**。故响铃后**必须立即用 snapshot（`get_market_snapshot` 的 `last_price`）取实测价**——取价紧跟响铃之后（T0+几秒内，新时序第 2 步）。⚠️ **snapshot 的 `last_price` 是「取价时刻」的最新成交价（毫秒级推送）、非严格响铃那一刻的价**——只是响铃后尽快取、尽量接近；要严格响铃时刻价需盘后按 `ring-log` 时间戳回查历史 K/tick（盘中不用 `request_history_kline`，见下「取价禁忌」）。把实测价以一行注释 append 到该条信号末尾（形如 `> 响铃后成交价：$P（HH:MM:SS 取价时刻）`——标注取价时刻、非严格响铃时刻）。

- **成交价 = 响铃时刻价，不算价格范围、不判开仓失败（2026-07-30 用户立，覆盖 2026-07-21 不对称成交范围旧规）**：用户听到铃立马下单（市价或近市价限价），实战下单来不及核对「成交价是否落在某个理论区间」。故**取消价格范围（做多 [参考价−0.8R, 盈亏比=1价] / 做空 [盈亏比=1价, 参考价+0.8R]）的全部计算与判断**——响铃时刻价（实测价）直接作为该笔的成交价，用它算实际 max_loss（= 仓位 × 按实测价的每股止损距）、修正赔率（按实测价重算止盈距÷止损距）、浮盈盯盘。**不再有「开仓失败」判定**：只要用户按信号下了单、响铃时刻价取到了，就假设按该价成交；若用户实际没下单或没成交（券源不足、限价未触等），用户会主动告知，AI 据实调整——默认假设按响铃时刻价成交。
- **为什么取消价格范围**：原「盈亏比=1 价 + 0.8R 不对称区间」理论上是控制成交价赔率底线的精细工具，但实战中用户听到铃秒级下单、根本不看范围；AI 算范围徒增延迟与复杂度，且「开仓失败」判定在急跌行情中频繁误判（如 2026-07-29 做空 MU：响铃 809 → 实测 801.98 被判开仓失败，但 MU 方向完全正确、收盘 739）。取消后：响铃时刻价直接当成交价，简单直接、零额外判断，复盘用真实成交价算实际赔率即可。
- **取实测价的操作禁忌（2026-07-27 立，保留）**：响铃后取实测价**只用 snapshot（`get_market_snapshot` 的 `last_price`）**，**绝不调 `request_history_kline`（历史 K 线接口）**——该接口对美股 1 分钟 K 偶发卡死（与 `capital_distribution` 同类坑），调用会占用会话 120 秒+。响铃后必须立即用 snapshot 取；若响铃当时漏取，事后复盘时再回查历史 K，不在盘中调。
- **旧规作废（2026-07-30 用户立）**：2026-07-21「不对称成交范围（盈亏比=1 价 + 0.8R）」「成交判据」「开仓失败」「区间符号约定」整条作废；响铃时刻价直接当成交价、算实际 max_loss 与修正赔率，不再判是否成交。

**「一笔交易」定义 + 五类信号概念区分（2026-07-18 用户立，2026-07-27 修订：重新定义「一笔交易」、平仓 / 减仓 / 移损须标批次；勿混）**：

- **一笔交易（a trade）= 一次开仓量 或 一次加仓量**（2026-07-27 用户立，为复盘精确计算）：同一标的的头寸按建仓批次拆成多笔独立交易——**开仓量 = 开仓批次（第 0 笔）**，**每次加仓的加仓量 = 另外一笔独立交易（第一次加仓批次、第二次加仓批次…）**。每笔交易各自有独立的入场价、止损、止盈、max_loss、单笔预算 B（每次开仓 / 加仓时按当时 equity × f 算）与盈亏；**复盘时每笔独立算 R-multiple、胜率、EV**。⚠️ 「最多持仓一个标的」不变——同一标的可有 开仓 + N 次加仓 = N+1 笔交易。⚠️ **历史样本口径**（2026-07-27 立）：本定义自 2026-07-27 起执行；此前的历史样本（如 2026-07-17 智谱「开仓 2 手 + 加仓 2 手」）保留旧合并口径（按加权均价合并成 1 笔、未回溯拆分），因事后拆分需原始分笔数据且有主观性。故累计 N 含少量旧口径合并笔，新交易一律按本定义逐笔独立计。
- ① **开仓 🟢** = 空仓时建仓（做多 / 做空），开仓量 = 一笔交易（开仓批次）。
- ② **加仓 🔵** = 已有持仓时增加仓位（同方向追加），**每次加仓量 = 另外一笔独立交易**（独立入场价 / 止损 / max_loss / 预算 B，不再与原仓合并）。
- ③ **减仓 🟠** = 减少某批次的部分仓位（该批次还有剩余）。⚠️ **须注明针对哪个批次**（开仓量 / 第一次加仓量 / … / 第 n 次加仓量）。
- ④ **平仓 🔴** = 清空某批次的所有持仓。⚠️ **须注明针对哪个批次**；要清空整个标的 = 对每个未平批次各发平仓（或一条信号里列清各批次盈亏）。
- ⑤ **移动止损 🟡** = 移某一批次的止损。⚠️ **须注明针对哪个批次**。
- **移动止盈已取消（2026-07-18）**——止盈靠 ① 主动平仓 🔴（按批次）+ ② 移动止损锁利 🟡（按批次）。

## 平仓行为与术语定义（2026-07-07 定义，2026-07-18 信号体系调整：加仓/减仓替换移动止盈）

**两类平仓行为**（开仓都是主动；平仓分主动 / 被动）：

| 行为 | 触发方 | 盈利 | 亏损 |
|---|---|---|---|
| 主动开仓/加仓 | AI 开仓/加仓信号 → 用户 App 操作 | — | — |
| 主动减仓/平仓 | AI 减仓/平仓信号 → 用户 App 操作 | **主动锁利** | **主动锁亏** |
| 被动平仓 | 止损条件单触发（用户在 App 挂） | **被动锁利** | **被动锁亏** |

**关键规则**：

1. **止盈靠两类信号**（2026-07-18 取消移动止盈后）：① **主动平仓 🔴**（AI 判断到目标 / 情况不对，发平仓信号清仓）② **移动止损锁利 🟡**（浮盈中上移止损到盈利区，被动触发锁利）。不再有移动止盈信号。
2. **AI 只给止损价**：随持仓阶段给移动止损价（防守锁下限 + 浮盈时锁利），用户 App 挂/调。AI 不碰任何条件单。
3. **减仓 vs 平仓**：减仓 🟠 = 部分平仓（还有剩余，剩余仓位仍按原止损管理）；平仓 🔴 = 清空所有持仓。
4. **条件单触发 = 被动平仓**：价格到止损位自动触发。被动锁利靠移动止损朝盈利方向移（单向，锁下限）。

**AI 的输出五种**（2026-07-18 调整）：① 开仓 🟢 ② 加仓 🔵 ③ 减仓 🟠 ④ 平仓 🔴 ⑤ 移动止损 🟡。**不挂任何条件单（用户 App 挂）**。

**⚠️ 主动平仓 vs 被动平仓的信号边界（2026-07-16 立）**：
- **主动平仓 → 发 🔴 平仓信号**（AI 判断动能减弱 / 情况不对 / 到硬平仓时点等，需提示用户现在手动平仓）：第一个动作立马调 `ring.sh close` 响铃、之后 snapshot 取响铃时刻价、最后 `log_signal.sh` 写信号文件（对话不输出关键字段；时序见「信号格式 · 🔔 信号时序总则」）。
- **被动平仓（止损 / 止盈条件单触发）→ 不发 🔴、不响铃**，只 ① 对话简短标记一句（「XX 止损/止盈 $Y 触发、成交 ~$Z、亏/盈 $M」）② signals 记录写明「触发价 / 盈亏 / 被动平仓」③ **更新 equity 并在信号文件该笔记录末尾 append 当前总资产**（被动平仓也是交易了结、与主动平仓 / 减仓走同一条「权益更新」流程，见硬性护栏 1）。原因：止损/止盈是用户在 App 挂的条件单，触发时 App 自动执行 + 通知用户，AI 发信号发出来时已触发、没有「提示用户去手动执行」的意义。
- 判别：AI 发出的是「让用户动手平」= 主动 🔴；「用户 App 条件单自己触发了」= 被动 → 只标记。

## 硬性护栏（发信号前逐条自检，违反不得发信号）

1. **单笔预算与 max_loss（固定比例动态下注，2026-07-04 用户新规 → 2026-07-26 修订：固定比例 2% → 2026-07-27 修订：重新定义「单笔预算 / max_loss」两个概念、仓位规则改为「选实际 max_loss 最接近单笔预算」）**。**两个概念先分清、不混用**：
   - **单笔预算（budget，B）= 开仓前由「总资产 × 固定比例 f」算出的下注预算**：B = `config.risk.risk_fraction`（当前 2%）× 当前 equity（初始 `config.risk.initial_equity` = 100000 HKD；preflight 启动时输出当前 B）。这是开仓**之前**定下的「这笔想承担多少风险」的目标值，用来当仓位选择的标尺。
   - **max_loss（M）= 实际开仓之后、开仓价格到止损价格的真实最大损失**：M = 仓位 × 每股止损距（每股止损距按**实际开仓价**算；响铃前用参考价预估、响铃后按实测成交价精算）。这是开仓**之后**实际承担的风险额度，是真实的「这笔最多亏多少」。⚠️ **max_loss 不要求严格 ≤ 单笔预算 B**（见下「选仓位」），它围绕 B 选最近、可略超或略低。
   - **先定止损位**：止损位 = **趋势反转判断位 = 做多/做空逻辑失效的关键位**——价格到这里 = 开仓逻辑不成立了 = 趋势大概率反转 = 该离场。**做多**：开仓逻辑若赖「站上 VWAP / 企稳某支撑」，止损 = **跌破该 VWAP / 企稳支撑**（站不上 VWAP = 多头逻辑失效）；**做空**：开仓逻辑若赖「VWAP 下方 / 遇阻某阻力」，止损 = **站上该 VWAP / 阻力**。**止损的本质是「判断趋势反转」、不是「限制亏损幅度」、更不是「放远兜底防扫」**（2026-07-29 用户立）：让利润奔跑的前提是持仓顺势，止损只在趋势反转时触发（顺势不触发 = 利润奔跑、反转触发 = 离场不逆势扛）。⚠️ **禁止把「前低/新低下方 -X」当止损**——那是**远技术位**、不是逻辑失效点，会导致持仓逆势抗跌大亏。⚠️ **禁止用百分比机械算止损**（-5% 只限幅度不判趋势）。**反面教训（2026-07-29 07709 做多）**：开仓 35.15（逻辑 = 站上 VWAP 35.46 + 企稳），止损放新低 34.80 下方 -1.0 = 33.80（**远技术位、错**），从 35.15 跌到 33.80 逆势扛 -3.8% 大亏；**正解 = 放 VWAP 35.46 下方 35.0**（做多逻辑失效点），跌破 VWAP 即止损 -0.4% 小亏离场、不逆势扛。3x ETF 波动大 → 趋势反转位（形态支撑/VWAP）本身可能较远，**但仍按逻辑失效点定、不按百分比、不人为放远兜底**。
   - **算每股止损距**：做多 = 开仓价 − 止损价；做空 = 止损价 − 开仓价。止损价 ≥ 开仓价（做多）属方向错，不开仓。
   - **选仓位（2026-07-27 修订核心：选实际 max_loss 最接近单笔预算 B 的仓位，不要求 max_loss ≤ B）**：先算连续原始仓位 = 单笔预算 B ÷ 每股止损距（按参考价）；再按 `lot_size` 离散化（港股取整手倍数、不足 1 手不开仓；美股可零股直接取整）；在离散候选里**选使实际 max_loss（= 仓位 × 每股止损距）最接近单笔预算 B 的那个仓位**——max_loss 可略超或略低于 B，只看哪个最接近、不追求严格不超。例：B = 2000 HKD、每股止损距 3、lot_size 200 → 原始 667 股，候选 400 股（max_loss 1200）/ 600 股（1800）/ 800 股（2400），600 股的 1800 最接近 2000 → 选 600 股（max_loss 1800 < B 2000）。⚠️ **f_max 硬上限兜底**：选中的仓位其实际 max_loss 不得超过 `equity × config.risk.f_max`（f_max 是 f 的放大硬上限，preflight 输出「f_max 硬上限」）；若「最接近 B」那一档的 max_loss 已超 f_max 上限，退一档选更小的离散仓位——**f_max 是风控绝对红线，max_loss 可超 B 但不可超 equity × f_max**。
   - **成交价偏离校验（取代旧 buffer，2026-07-27 修订）**：信号参考价（发信号时）≠ 实际成交价（响铃后下单时刻），响铃后按实测成交价重算实际 max_loss（实测价影响每股止损距）；正常不动——选仓位时已基于参考价选了最接近 B 的、成交价小幅偏离属正常、max_loss 仍在 B 附近。仅当成交价偏离使**实际 max_loss 超 f_max 硬上限**才减仓补救（按实测价 + 退档重选）。⚠️ **原 2026-07-17 buffer 方案 A/B（开仓时按 max_loss ×（1−buffer）预留 20-30%）作废**——新规则不追求「严格不超 B」，无需预留 buffer；选最接近即可，硬上限由 f_max 兜底。
   - **美股换算**：HKD 单笔预算 B ÷ 当日真实汇率（`exchange-rate` 命令查，勿估）= USD 单笔预算，再按 USD 选仓位（美股可零股、离散粒度细，max_loss 易接近 B）。
   - **周期**：`loss_limit_scope` 默认 `per_trade`（每笔独立，无日累计上限，但 AI 自行在连亏后控制开仓频率）。
   - **权益更新（2026-07-26 立，固定比例的核心机制；2026-07-27 修订：每笔了结后还要在信号文件记当前总资产）**：**每笔交易了结后**（包括减仓 🟠 部分平仓、主动平仓 🔴 清仓、被动平仓止损 / 止盈触发——凡是兑现盈亏的了结动作都算，不只清仓那一类），当前 equity += 本笔盈亏（港股直接 HKD、美股按当日 USD/HKD 汇率换算 HKD），并**同时写两处**：① **append 一行到 [signals/equity-log.csv](signals/equity-log.csv)**（字段 `date, symbol, P_HKD, equity_after, note`，结构化、preflight 读它算 B）；② **在该笔了结对应的当天信号文件记录末尾 append 一行当前总资产**（港股 `signals/YYYY-MM-DD-HKT-signals.md` / 美股 `signals/YYYY-MM-DD-ET-signals.md`，形如 `> 当前总资产：HK$98,900（本笔后 equity）`，便于人眼回看每笔了结后的账户总值；总资产值 = 本次更新后的 `equity_after`，HKD 口径、与 equity-log 一致）。**当前 equity = equity-log.csv 最新行 `equity_after`**（无记录则 = `initial_equity`）。**起点（2026-07-26 用户选 B 重新开始）**：equity = 100000 HKD、单笔预算 B = 2000 HKD。⚠️ **`reviews/` 累积 trades CSV 是复盘样本（策略 edge 估计的数据源），不等于账户权益**——账户 equity 从 `initial_equity` 起、只记**新机制生效后的实际交易**盈亏；历史 N=20 复盘盈亏不计入账户（用户 2026-07-26 选 B 重新开始）。两份记录用途不同、相互独立。这修订了原「资金总是够用」假设（信号模式总则第 6 条）——现在按实际权益动态算 B：权益缩水→B 自动缩小（复利减速）、权益增长→B 自动放大（复利加速）。
   - **利润 = 赔率 R × max_loss，与标的振幅、价格贵不贵无关（2026-07-15 复盘沉淀，纠正错误认知）**：在「固定比例选仓位」的框架下，盈利 = R × max_loss（R = 止盈距离 ÷ 止损距离），亏损 = max_loss。标的的价格只决定「买几股」（仓位股数 = max_loss ÷ 每股止损距），**不决定赚多少钱**——便宜标的多买几股、贵标的少买几股，只要 R 相同，利润一样。故**选标的不能用「振幅大→利润大」「价格低→仓位好算→利润大」作理由**，这两条都是错的。
   - **做高赔率 R 有两条路，各有约束（2026-07-15 复盘沉淀）**：① 放大止盈——受日内可达范围（振幅）约束，止盈位得真到得了；② 缩小止损——受「不被盘中波动扫掉」约束，太窄会被随机噪音扫成白送。两条路都能抬 R，别只盯着「放大止盈受振幅限制」而忘了「缩小止损」这条路。
   - **杠杆同时影响止盈空间和止损空间——R 是增是减要看两者实际放大倍数、必须实算（2026-07-15 复盘纠正，二次修订严谨化）**：R = 止盈空间 ÷ 止损空间。杠杆（3x）会把止盈空间和止损空间**同时**推大，但 R 是增是减取决于两者放大倍数孰大——分子（止盈）放大倍数 > 分母（止损）则 R 升、相等则不变、< 则降，**不能笼统说「杠杆让 R 降低」或「振幅大让 R 升高」**（同倍数放大时 R 不变）。两者各自的实际值受不同约束：止损空间有「不被盘中波动扫掉」的下限（杠杆标的中盘中噪音大、下限更高，如 SOXL 需 3-5%，见下第 7 条 7/13 教训），止盈空间受「日内可达范围」约束。**故选标的不能凭振幅或杠杆想当然，必须针对每个标的、结合实际入场位 / 止损位 / 止盈位把 R 实算出来再比较**（示例估算、非定律：按各自合理止损宽度，MU 的 R 上限约 2.3-4、SOXL 约 1.6-2.7，换止损/止盈参数结论会变）。选标的的标准是「止损能设多窄（不被扫）× 止盈能到多远」，但要落到实算 R，而非振幅绝对值或杠杆倍数。
   - **仓位无比例上限**：止损位近则仓位大、远则仓位小，均允许，只要实际 max_loss 不超 f_max 硬上限（软目标是 max_loss 尽量接近单笔预算 B，见上「选仓位」）。
2. **止损价必须在开仓信号里给出，由用户在 App 挂止损**（2026-07-07 信号模式）：AI 不挂任何单。开仓信号里的止损价 = 技术位（前低 / 支撑 / 跌破关键价），必须明确算出写进信号，并在信号末尾提示「开仓后请在 App 挂止损 @ $Y」。历史教训：CLI 条件单 MIT / MO / LIT 全 Rejected、状态 `VarietiesNotReported` 不可信，依赖 AI 挂单 = 止损失效裸奔——信号模式后此风险交由用户 App 止损兜底（App 止损单已验证有效）。止损位一旦定了就是纪律，不因盘中情绪滑动。

## 交易策略纪律（2026-07-03 实战教训）

**核心思想：数学期望 EV ≥ 0**（2026-07-06 用户立，最高优先级）：一切交易决策围绕 **EV ≥ 0**（至少不亏），EV > 0 且越大才挣得多。EV 由多笔交易的**胜率 × 赔率**决定——这是能否盈利的地基，方向/风控/纪律都服务于它。

- **开仓基准（2026-07-22 用户修订：预估赔率门槛降为至少 1.2 倍；原 2026-07-16 为 1.5、2026-07-15 为 2）**：开仓必须同时满足 **胜率 > 50% 且 赔率 ≥ 1.2**（止盈距离 ≥ 1.2 × 止损距离）。EV = 胜率×赔率 − 败率×1；赔率 1.2 + 胜率 50% → EV = 0.5×1.2 − 0.5×1 = +0.10（正期望但薄，更依赖胜率把关，故置信度门槛同步收紧到只发高置信，见下条）。⚠️ 赔率门槛历次放宽（≥2 → ≥1.5 → ≥1.2）：**用置信度把关质量、放宽赔率抓更多机会**（置信度取代赔率做主把关；2026-07-22 再放宽到 1.2，是为了不因赔率 1.2–1.5 错过多头日的顺势机会——但赔率越低越依赖胜率与置信度，🟢 高置信 + 顺势仍是硬前提，不为放宽而降质量）。⚠️ **赔率 ≥ 1.2 与「止损给足波动空间」不矛盾**：止损仍按 K 线形态技术位定（前低/支撑，**禁止百分比**；2026-07-29 用户立），3x 杠杆 ETF 波动大 → 选更远的形态支撑位防噪音扫（见下方 2026-07-13 SOXL 止损太近被扫的教训），赔率达标靠的是 **止盈空间 ≥ 1.2 × 止损空间** 这个比例，而不是强行收窄止损——做法是把止盈位放到止损距离的 1.2 倍以上、并确认它在当日日内可达范围内（受振幅约束，到不了的止盈位是空想）。移动止损仍用于浮盈后锁利与进一步放大利润，但**开仓那一刻赔率本身就要 ≥ 1.2，不能指望靠移动止损把一个低赔率的仓补成正期望**。
- **置信度分级——EV 之上的第二道闸（2026-07-13 借鉴 OhMyTradingTeam，2026-07-16 收紧：仅高置信才发开仓）**：EV 判据是"这笔值不值得做"的数学门槛；置信度是"我对这个判断有多大把握"的可靠度分级。**2026-07-16 修订（原「中置信降仓位可发」→「仅高置信发」）：开仓信号只在 🟢 高置信时发，🟡 中置信 / 🔴 低置信都不发开仓信号**（信号是真实交易，置信度把质量关、取代原「降仓位发」）。判级标准：
  - **🟢 高置信（唯一可发开仓的级别）**：信号各维度一致（趋势 + 量价 + 资金流 + 宏观基调同向）、入场点建立在已确认事实（企稳 / 真站稳）、（若有临近重大事件）事件经「事件风险三维度判别」评估不构成对该标的方向的主导性冲击 → 发开仓信号。
  - **🟡 中置信（不发开仓）**：部分维度矛盾或待确认（趋势顺势但量价未配合、资金流与盘口背离、临近数据日但方向不明、已标注反向风险）→ **不发开仓信号**，等确认升到高置信再发（2026-07-16 SOXL 做空定中置信、已标注超大单逆势买风险仍发、致用户实亏 ~$120，用户据此收紧）。
  - **🔴 低置信（不发开仓）**：关键维度矛盾（量价背离 + 资金流反向）、横盘无明确方向、临近重大事件（CPI / 非农 / FOMC / 财报）**且该事件对标的方向主导性强、结果落地前方向难判**（不是机械「有事件就降级」，见下「事件风险三维度判别」）、依据是赌突破 / 赌反转（预测非已确认）→ **不发信号**，等局面明朗。
  - 置信度写入开仓信号「置信度」字段（圆形彩色 emoji 🟢/🟡/🔴 标记，是表格内唯一可保留的 emoji，见「信号格式」）。⚠️ 2026-07-16 起**置信度是硬闸**（仅 🟢 发，🟡/🔴 都不发开仓），不再是「中置信可降仓位发」的软闸。置信度不取代硬护栏（标的分类、时段、max_loss 等仍硬性），但开仓门槛收紧到「🟢 高置信 + 赔率 ≥1.2」两道闸全过才发。
  - **事件风险三维度判别（2026-07-27 立，纠正「有事件就降级」机械判级）**：临近重大事件（CPI / 非农 / FOMC / 财报 / 地缘 / 政策等）时，事件对置信度的影响权重**不能机械「有事件就降级」**，要具体分析三个维度：
    - **① 方向**：事件预期结果对标的的方向（利好 / 利空 / 中性）。与信号方向**相反** → 风险高；**一致**或**中性** → 风险低。
    - **② 程度**：事件结果的市场预期已 price in 多少。预期一致 + 概率高（如 FOMC 79.5% 维持不变）= 大概率已 price in = 实际冲击**小**；预期分歧 / 结果难测 = 冲击**大**。
    - **③ 是否影响主导驱动（最关键）**：先识别标的**当下最主要的价格主导原因**（独立基本面 / 行业周期 / 技术形态 / 资金流 / 还是事件预期本身），再判断事件会不会**改变**这个主导驱动——事件**是**主导驱动本身（如大盘 ETF、无独立逻辑的标的在事件前）→ 事件权重高、结果落地前**降级**；标的有**独立主导驱动**（如板块独立崩、有自身基本面逻辑）且事件**不改变**它 → 事件权重**低**、技术信号效力不被削弱、**不降级**。
  - **判别口诀**：机械「有事件就降级」是错的。要问——**事件会改变这个标的当下的主导驱动吗？会 → 谨慎；不会 → 即便有事件、技术信号效力不打折**。
  - **反面教训（2026-07-27 MU）**：21:53 MU VWAP 927 假突破遇阻、半导体独立崩跌（大盘涨它崩 = 有独立空头驱动），做空信号本应 🟢，但误把「明天 FOMC」机械当降级因素判 🟡 不发。实际：FOMC 79.5% 预期不变（② 程度小）+ 半导体独立崩跌（③ FOMC 不改变独立空头驱动）→ 事件权重低、不该降级。错过入场 925–937 止损的做空点（收盘 899，浮盈 26–38 点）。**根因：没区分「事件主导型标的」和「独立驱动型标的」，把 🟢 高置信里「无临近重大事件」机械执行。**
- **赔率三阶段（2026-07-23 用户立，贯穿开仓→持仓→平仓，赔率公式的统一命名）**：赔率在交易生命周期有三个时点，各自用不同基准价算、名称不同：
  1. **初始预期赔率**（发开仓信号时、开仓前）：用**参考价**算 =（止盈−参考价）÷（参考价−止损）（做多；做空 =（参考价−止盈）÷（止损−参考价））。即开仓信号「预期赔率」字段（见「信号格式」）；开仓前必须先定止盈线 + 止损线才能算出、再判开仓（≥1.2 才发）。
  2. **修正预期赔率**（实际开仓后、响铃实测成交价）：用**响铃实测成交价**重算 =（止盈−实测价）÷（实测价−止损）（做多；做空反向）。反映真实成本下的赔率预期，**响铃后立即算**（见「信号时序总则·响铃后立即取实测价作为成交价」），以注释写入信号文件。
  3. **实际落地赔率**（平仓后）：用**实际盈亏 ÷ 实际 max_loss**（= R-multiple，$R_i=P_i/M$；实际 max_loss = 仓位 ×（止损−实测成交价），按实测成本；实际盈亏 = 仓位 × |开仓实测价 − 平仓实测价|）。已了结的真实赔率，**停盯总结必报**（见「停盯总结」）。
  - **三阶段递进**：预期（参考价）→ 修正（实测成本）→ 落地（真实结果）。三者对比能暴露「预估乐观但落地打折」的问题（如 2026-07-23 阿里 2.30→2.00→0.82R、中芯 3.21→2.20→0.48R，落地远低于预期，根因是没让利润奔跑到止盈就平）。
- **移动止损不撤旧单（2026-07-06 用户）**：移动止损时**只挂新止损单（更紧、更有利位），不撤旧止损单**——旧单留在更宽价位做备用兜底。原理：移动止损单总朝"减小亏损/增加利润"方向调（新单位于更有利价位），价格必先触发新单；若新单失效（Rejected/未承接），旧单兜底。撤旧单 = 自废一层保护。
  - ⚠️ **移动止损只能单向移动**（2026-07-10 用户强调）：只朝**有利方向**（亏损减小 / 利润增加），**永不回撤**——做多止损只上移、做空只下移（做多下移止损 = 扩大风险，禁止）。**移动止损既锁损（亏损时限制亏损）又锁利（盈利时上移到盈利区）**，覆盖持仓全周期。2026-07-18 取消移动止盈后：止盈只靠 ① 主动平仓 🔴（到止盈目标主动清仓）+ ② 移动止损锁利 🟡（浮盈时上移止损到盈利区被动触发）——不再有独立的止盈价条件单。⚠️ **止损价从开仓就设定、时时刻刻都在**（开仓信号含止损价，初始在亏损方向锁损 → 可单向移到盈利方向锁利）。（注：用"成交价"而非"成本价"作参照——空头成本价 = 成交价的相反数即负数，标的价始终正数，正负比"高于/低于"无意义。）
- **开仓后浮盈即移损到保本线（不等"浮盈大"）+ 止损位按 K 线形态定（非百分比，2026-07-29 用户立）**：开仓后只要价格往有利方向走（浮盈 = 涨/跌过开仓价），**立即把止损移到新的趋势反转判断位**（随趋势推进上移；趋势推进后新反转位常落在成本区/盈利区，「保本」是顺带结果、不是目的——**移损的本质是跟随趋势把止损移到新反转位，而非保本**）——不等"浮盈大"。最差保本不亏。**初始止损位按 K 线形态技术位定**（开仓前后的近期低点/支撑/形态位；如 2026-07-28 SOXS 开仓 63.86、止损 62.65 = 开仓前后的 K 线支撑位、**非 -2% 百分比算**）：形态止损位只在「开仓后没涨直接跌、破形态支撑」时触发（小亏）、涨了就移保本（不亏），组合风险 ≤ 远止损 + 不移损。**反面教训（2026-07-28 SOXS 做多 63.86）**：止损死守 3x ETF 5%（60.28 = **-5% 百分比机械算、非形态位**）+ SOXS 开仓后涨到 64+（浮盈）没移损、之后跌到 60.79、远止损没兜住、手动平在最低 → 亏 $246；若按 K 线形态止损 62.65（支撑位）只亏 $97、若浮盈即移保本则不亏（差 $149～$246）。⚠️ **止损位永远按 K 线形态（前低/支撑/跌破关键价）定，禁止用百分比机械算**（-5% 之类脱离盘面结构、无技术意义）；3x ETF 波动大 → 选更远的形态支撑位防噪音扫（不是机械加百分比）。与下条「浮盈大时锁利」配合：**浮盈小 → 移保本、浮盈大 → 锁利到盈利区**。

- **移动止损浮盈大时锁利、不只保本（2026-07-08 SOXL 教训）**：浮盈 ≥2/股 时，移动止损应放到**盈利区**（锁利 1+/股），不只放到成本位（保本）。2026-07-08 做空 SOXL：成本 162.84、浮盈 $96（现价 160.37、2.47/股）时只把止损移到成本 162.84（保本），结果 SOXL 反弹到 162.84 保本出、**$96 浮盈全回吐**。正确做法：浮盈 2.47/股 时止损应移到 **161 附近**（锁利 1+/股 ≈ $39+），反弹触发锁利、不回吐浮盈。原则：**浮盈越大、止损越要往盈利区挪**（保本只是浮盈小时的底线，浮盈大了必须锁利）。
- **锁利大小要动态权衡、不机械固定（2026-07-10 用户纠正）**：浮盈中移动止损，**锁利多（止损紧）= 防回吐但被小反弹扫、错过续顺势的大赔率**（实际剩余赔率降）；**锁利少（止损松）= 让利润奔跑但回吐风险**。不机械"锁 2+/股"或任何固定值，而是**实时预估剩余赔率（止盈空间 ÷ 止损距离）+ 续顺势 vs 反弹概率，动态选锁利位使 EV 最大**。判据：标的波动大（3x ETF）止损要偏松（防小波动扫损）；大趋势强、续顺势概率高 → 锁松让利润奔跑；超跌、反弹概率高 → 锁紧防回吐。**看好后市 → 微锁利 + 宽止盈**（止损放成交价附近、做多略高 / 做空略低于成交价；**止盈位放远、给足空间让利润奔跑**）：被扫也微利保本不亏、不扫吃大涨；微锁利=止损近 + 宽止盈=止盈远 = **高赔率**（止盈空间大 ÷ 止损距离小），配合看好的高胜率使 EV 最大化。⚠️ **微锁利必须搭配宽止盈**，否则"防住回撤却早早平掉大涨潜力"自相矛盾。微锁利程度取决于预判（越看好越松至成本持平、甚至略下方给回撤空间）。⚠️ **使用边界**（2026-07-11 用户，2026-07-16 补强平终点）：**「微锁利 + 宽止盈 + 睡觉让奔跑」仅限美股早盘（北京晚上）用户睡觉时段**；**港股盘中（北京白天，用户与 AI 同步盯盘）不用此法**——止盈止损**时时刻刻据盘面主动动态调整**，不睡觉。⚠️ 「让利润奔跑」的终点是**当日停止盯盘前**（美股用户喊停或 16:00 收盘、港股 16:00 收盘；持仓不过夜、不跨交易日）——宽止盈位要在当日停止盯盘前可达，到不了就在停盯前主动按市价平掉，故宽止盈不能放到停止盯盘之后才到的位置。**锁利位是浮盈中持续重估的变量，不是一次定死**。
- **主动平仓不等固定止盈（2026-07-06 用户教训，最高优先级）**：浮盈中若**情况不对**（动能减弱/资金流边际转正/价量背离/震荡不前/滞涨），**随时 LO 主动平仓锁利**，**绝不死等预设止盈位（如 2 倍赔率）**。用户原话："主动平仓不一定要等到两倍赔率，情况不对随时平仓。" 移动止损只是被动兜底，主动判断离场才是锁利主手段——执着等固定止盈会把已到手的利润还给市场。第一单做空 MU 浮盈 +$212、近5分钟资金流一度转正 +987（动能减弱信号）时未主动平仓，后反弹变亏损 −$92，典型错过。
- **临近停止盯盘的分情况策略（2026-07-19 修订：撤销留单——停盯前一律主动平；原「持有到强平让利润跑尽」「留单赌午盘」整条作废）**：临近当日停止盯盘时点——港股 12:00 午休前 / 港股 16:00 收盘前 / 美股用户喊停或 16:00 收盘前——**停盯前必须主动平仓（不存在留单）**。主动平仓的时机判据：**有持仓**——①**「情况不对」信号**（任一即立即主动平仓锁利）：滞涨 / 动能减弱 / 价量背离 / **加速赶极端（做多持仓：加速赶顶 = 加速上涨 + 破前高 + 远离 VWAP 上方超买；做空持仓：加速赶底 = 加速下跌 + 破前低 + 远离 VWAP 下方超卖——两者原理对称反向、都是动能将竭，属「情况不对」、不是「持续上涨/下跌无滞」）**——剩余时间不多，收益一旦跌下去没足够时间涨回，此时主动平锁利；②**无情况不对信号、趋势仍健康**：可持有到停止盯盘时点前再主动平（让利润多跑一段），但**到停止盯盘时点必须主动平掉、不留单**（2026-07-19 撤销留单策略后，不再有「留单靠条件单兜底」或「持有到账户强平」的选项——停盯前主动平是唯一出路）。2026-07-17 MU 反例（旧规则下的教训，新规则下语境变了）：当时 12:00 停盯、浮盈 +$3071、加速赶顶（11:54-12:00 加速 873→884、破前高 885.93、远离 VWAP 845.70 达 +4.5%）却误判"持续上涨无滞涨"留单赌午盘 → 15:15 破 866 止损仅 +$1060、回吐 ~$2000；**新规则下教训转为**：盘中任何时候出现「加速赶极端 = 动能将竭」就主动平锁利、不等停盯时点——因为现在不存在「留单赌后续」的选项，动能将竭时锁利就是最优。**无持仓**——临近停止盯盘时点开仓要小心：剩余时间少意味着日内可达涨幅有限、止盈空间被压缩，赔率可能凑不到 ≥1.2，开仓前必须重算赔率、不足就不开。一句话：**临近停止盯盘，有仓看「动能是否将竭」决定何时主动平（将竭立即平、仍健康可持有到停盯前），无仓看「剩余时间够不够凑出赔率」决定开不开**。
- **回踩不破前低 = 最佳平仓时刻（2026-07-06 用户）**：做空时价格**回踩前低不破**（= 下跌动能衰竭、买盘承接站住）→ 这才是技术面上最佳主动平仓时刻，优先于固定止盈位；做多时回踩前高/支撑不破 = 加仓或持有时刻。错过这个点位往往由盈转亏。
- **移动止损总原则**：持仓全程移动止损线；当**止损价移过成交价到盈利方向**（做多止损价 > 成交价 / 做空止损价 < 成交价）时，这笔的胜负已锁定（最差不亏），之后让利润奔跑、止盈价朝盈利更深处调。
- **资金流入但价格不涨 = 卖盘更强（2026-07-07 港股复盘，最高优先级）**：资金流（capital inflow）只有伴随**价格同步突破**才是多头确认。若资金持续流入但价格多次冲阻力不过（价量背离），说明上方卖盘在出货、把买单全吃了——这是**离场 / 观望信号，不是入场信号**。2026-07-07 美团第二笔误把「资金流入」当成「突破在即」，七次冲 78.50 失败，亏 −HK$125。
- **阻力三次不过不赌突破（2026-07-07 港股复盘）**：一个阻力被测试 ≥3 次都不破 = 强阻力确认，下次突破概率随测试次数**下降**（不是上升，每次失败都在验证卖盘强度）。想做多就等「真放量突破站稳 + 回踩阻力转支撑不破」，不要在阻力下方提前埋伏赌突破。
- **大单吸筹 + 缓慢震荡上涨时不过早平（2026-07-20 立）**：super 超大单持续大幅净买 + 价格**缓慢震荡上涨**时，super 短期波动（停止活动 / 略降）≠ 反弹结束，不要一见 super 略降就判「动能衰竭」平仓。**离场判据**（任一即可）：① super **真正持续转流出**（大单出货）；② 价格**跌破关键支撑**（如当日低点）；③ **阻力多次不过 + 量缩**（动能真衰竭组合）。super 持平 / 略降但未转流出时倾向持有（让大单吸筹的后续拉升兑现）。⚠️ **场景限定——按上涨速度区分**：本条只适用**缓慢震荡上涨**（持有）；若标的处于**急速上涨（加速赶顶）**则应提早平、不抓顶部（信号模式执行延迟 + 急速反转，见「交易策略纪律 · 临近停止盯盘的分情况策略」加速赶极端条），不能套用本条「持有等 super 转流出」。
- **三角形持续形态未破时持有 / 移损观望、不因遇阻就平（2026-07-20 立，细化上方「阻力三次不过不赌突破」）**：三角形持续形态**未破**时，即使阻力 / 支撑多次遇阻也应**持有 / 移损观望**，不因遇阻就平——**阻力 / 支撑多次遇阻 ≠ 反向信号**，要结合形态斜率判断：遇阻 + **形态破**（支撑 / 阻力线斜率反转）才反向；遇阻 + **形态未破** → 持有 / 移损观望、等突破。形态判据（做多 / 做空对称）：
  - **上升三角形（做多持仓）**：底部支撑线正斜率（低点抬高）+ 顶部阻力线走平（高点不创新高但不回落）+ 夹角向上收敛 → 僵持后大概率**向上突破**。
  - **下降三角形（做空持仓）**：顶部阻力线负斜率（高点降低）+ 底部支撑线走平（低点不再更低）+ 夹角向下收敛 → 僵持后大概率**向下突破**。
  - **怎么用**：形态未破时 ① 不平仓；② 移损跟随形态（做多止损跟随支撑抬升、做空跟随阻力下移）；③ 观望等突破。突破后的急速段按「加速赶极端」提早锁利、不死等；反向回落破形态则移损止损出。⚠️ 本条细化「阻力三次不过不赌突破」——单看阻力次数不够，要结合形态斜率：**形态未破时的遇阻 = 持有信号，不是反向信号**。
- **做多合格入场只有两种（2026-07-07 固化）**：① 回踩支撑企稳反弹（如 2026-07-07 美团 77.50 支撑企稳，+HK$990）；② 突破后回踩阻力转支撑不破。「赌突破」不在其中——前两者依据**已发生的事实**，后者依据**预测**。⚠️ **暴跌低点（超跌区：单日 -8%+ 或从高点 -30%+）做多「回踩企稳」不适用——必须等双底或头肩底（第二个低点不破前低 + 破颈线确认反转）**（2026-07-29 用户立，07709 教训）：暴跌低点的"企稳"极可能是下跌中继而非反转，"新低 N 次不破"只是支撑测试、不是反转形态；开盘 30 分钟内不在暴跌标的开多（双底/头肩底需时间构筑、6 分钟形不成）。**反面教训（2026-07-29 07709）**：从高点 -48% 暴跌、开盘 6 分钟用"新低 11 次不破 + 回踩企稳"开多 = 抄在暴跌低点接飞刀，随后跌破新低亏 -1R；正解 = 等双底/头肩底（第二低点不破前低 + 破颈线）再开。

- **量价正向确认作为开仓前置（2026-07-13 借鉴 Livermore 量价法则）**：上面「资金流入但价格不涨 = 卖盘更强」讲的是**背离**（资金进但价不涨 = 卖盘在出货，离场信号）；这里补**正向配合**（开仓确认信号）：顺势**做多要求放量**（上涨带量 = 买盘真主动）、**做空要求放量下跌或缩量反弹**（下跌带量 = 卖盘真主动）。**无量突破不可信**——价涨但量没跟上多半是诱多，不追。开仓前看一眼近几分钟量价是否配合，不配合就等。
- **不在关键点之外追单（2026-07-13 借鉴 Livermore 关键点法则）**：与「做多合格入场只有两种」呼应——那条讲**在哪入场**（回踩支撑 / 突破回踩），这条讲**为何不追远离关键位的拉伸**：价格已远离关键支撑 / 阻力位（涨了一大段没回调 / 跌了一大段没反弹）时**不追**，因为此时 EV 变差——① 离止损位远 → 仓位被迫缩小或止损被迫放松；② 拉伸越大 → 均值回归概率越高 → 胜率下降。等价格回到关键位附近（回踩 / 反抽）再进。一句话：**只在关键位附近交易，远离关键位不追**。

- **半仓轮动：震荡市里替代移动止损的主动高抛低吸（2026-07-18 用户教，2026-07-18 用户纠正减半本质=降风险敞口、不止锁利）**：震荡市（价格在区间内来回反复）里，移动止损锁利不好用——价格会多次触及止损位，止损一旦上移到盈利区就被"正常的区间回调"扫掉、扫完价格又涨回去，等于卖飞在区间内的小回调上。此时改用「半仓轮动」主动降低风险敞口：**对已有持仓，在区间上沿（关键阻力位）减一半仓位、在区间下沿（关键支撑位）加回相同数量**——一来一回，最终持仓数量没变，但已经在区间上沿那一段落袋了一部分利润（震荡市持仓多为浮盈、减半表现为锁利；但减半的本质更广、与盈亏无关，见下「减半的本质」）。分方向（对称反向）：
  - **做多持仓**：价格涨到区间上沿阻力位 → 对某批次减仓一半（发 🟠 减仓信号、标针对批次、理由"区间上沿锁利"，减仓后该批次剩余仓位仍按原止损管理）；价格回落到区间下沿支撑位 → 加仓等量回来（发 🔵 加仓信号 = 新开一笔独立加仓批次，独立预算 B、独立止损，见「概念区分」）。
  - **做空持仓**：价格跌到区间下沿支撑位 → 减仓一半（🟠）；价格反弹到区间上沿阻力位 → 加仓等量回来（🔵）。
  - **为什么减"一半"而不是全平**：留一半底仓做后手——万一区间被突破转为单边趋势，底仓还能吃到顺势利润；全平则彻底卖飞。这是"半仓"轮动而非"全仓做 T"的关键，也呼应「做多合格入场只有两种」里"已发生事实"的原则：减半先锁定一半（盈则落袋利润、亏则止损一半）、降低一半后续敞口，留另一半应对判断错了的情况。
  - **减半的本质 = 降低一半风险敞口（与锁利 / 锁亏无关，看的是价格预期；2026-07-18 用户纠正）**：减半这一步的底层动机是**当价格预期不利（更糟）时、先降低一半后续风险**，**和当前是盈是亏无关**——盈利时减半 = 锁利、亏损时减半 = 锁亏，两者都只是减半降敞口后的副产物，**不是减半的目的、也不是分类开关**（纠正"减半 = 锁利"的联想）。即便当前是浮亏，只要预期价格会更糟，先减一半同样是降低一半后续风险（少亏那一半在后续下跌里的损失）——这跟锁利无关、跟价格预期有关。减完之后接不接回，看价格预期：① **预期短期能接回**（价格会回到对侧关键位）→ 打算做轮动，到对侧位加回等量、持仓数量还原；② **无法预期短期能否接回** → 先减半降风险（锁利锁亏都行、反正是降低了一半敞口），接不接回看后续演变。

## 盯盘节奏

**盯盘持续性（2026-07-13 用户铁律，2026-07-16 补充启动与停止边界，2026-07-19 修订美股停止边界）**：**AI 不自主启动盯盘，收到用户的盯盘指令才开始**；启动后**未叫停就持续盯，不中途停下等用户**。靠**后台分段采样脚本（`monitor_segment.py`，每段 40 秒）+ 段结束完成通知驱动**维持（机制详见下「采样频率」），任务不因单轮对话结束而终止——无信号时一行带过继续盯，不暂停问"要不要继续"。方向研判、找标的、盯信号、发信号、平仓全程连续推进，直到**用户喊停、或撞上强制终止盯盘边界**为止。港股两个强制边界（见「时点平仓与停止盯盘约束」）：港股 12:00 午休前（主动平仓 + 终止盯盘，13:00 午市不自动恢复、等用户指令）、港股 16:00 收盘前（主动平仓 + 终止盯盘）。美股不设固定终止时点——盯到**用户发出停止盯盘指令**（大概率北京晚上睡觉前）或**美东 16:00 收盘**（取先到者），停前主动平仓、不留单。

**📌 后台采样不间断规矩（2026-07-23 用户立，盯盘持续性的机制保障，最高优先级）**：盯盘启动后，**后台分段采样（`monitor_segment.py`）必须持续运行——每段结束立即重启下一段，形成不间断循环**。这是「未叫停就持续盯」**唯一的实现机制**：靠每段采样结束的 task-notification 自动唤醒 AI，AI 读完数据重启下一段，循环往复；**用户不需要每次呼叫，AI 自己靠通知醒**。**只有以下两种情况允许停止采样**：① **用户明确喊停**（发出「停止盯盘」指令）；② **休市 / 收盘**（港股 12:00 午休前已主动平仓后、港股 16:00 收盘后；美股美东 16:00 收盘后）。**除此之外的任何情况都不得停采样**——包括平仓后空仓、观望、无信号、横盘震荡、等下一个机会等，采样都必须照常运行（空仓观望时优先换标的密盯而非降频死盯，见「采样频率·标的不值得密盯时优先换标的」；早盘 09:30-12:00 不得放稀）。**为什么不能停**：停了采样 = 没有段结束通知 = 没有自动唤醒源 = AI 静默着不会自己醒来找信号，等于事实上暂停了盯盘，「未叫停就持续盯」名存实亡。**2026-07-23 教训（用户据此立此规矩）**：阿里平仓后 AI 停了采样、只说「空仓观望」，结果没有唤醒源，用户不呼叫 AI 就不醒——「未叫停就持续盯」成了空话。用户立规矩：**只要用户没喊停、且未休市/收盘，后台采样就不能停；AI 靠采样通知自动循环盯盘找信号，不依赖用户呼叫**。

**📌 采样链防中断（AI 自检 + 备份唤醒，2026-07-29 立，保 40 秒密采样的可靠性保障）**：上文规矩靠「每段 task-notification 唤醒 AI 重启」驱动，但**通知机制非 100% 可靠**——会话长时间运行 / 上下文压缩 / 状态切换时 task-notification 可能失效，一旦失效采样链即断（AI 不被唤醒、采样不重启）。**2026-07-28 中断事故**：盯盘 3.5 小时后最后一段结束通知没唤醒 AI（会话状态切换致失效）+ AI 刚平仓止损主观放松（没主动重启采样）→ 采样断 9.5 小时（空仓无持仓损失，但错过美股剩余 4 小时行情）。排查确认非系统睡眠（caffeinate 在跑）、非数据源掉线（OpenD 在监听）、非进程崩溃（分段正常 CallClose 退出），纯是通知没送达 + AI 没自检。

**核心原则：保 40 秒密采样是重中之重——靠「AI 自检 + 备份唤醒」防中断，绝不改持续模式**。⚠️ **不得改为长时段持续模式**（脚本一次跑 30-60 分钟不退出）：task-notification 只在「命令结束」时触发，脚本不退出就没有结束事件、AI 中间不会被唤醒；若改用 ScheduleWakeup 定时唤醒，其最小间隔 60 秒（> 40 秒），**违反「早盘 ≤ 40 秒密采样」规矩**。长时段持续模式与「每 40 秒唤醒 AI」互斥，只适合不需频繁介入的低频监控（午盘缩量、只盯关键位突破），**盘中密采样场景禁用**。**正解：保持分段 40 秒（task-notification 主驱动）+ AI 自检纪律 + 备份唤醒**。

**防中断三件套**：
1. **AI 自检纪律（最关键、确定有效）**：每次被唤醒（无论 task-notification 还是备份唤醒）**第一个动作 `ps aux | grep monitor_segment` 查采样进程在不在** → 不在则立即重启（不等、不假设通知会再来）。不依赖「通知一定来」，而是「每次醒都确认采样在跑」——即便 task-notification 偶发失效，只要 AI 被任何机制唤醒一次，就能发现并重启采样。
2. **大动作后强制复查采样链**：**平仓 / 止损 / 减仓后必须复查采样仍在跑**——2026-07-28 教训：平仓止损后 AI 心理放松（空仓 + 亏损情绪 + 以为告一段落）、没重启采样致断链。平仓/止损是「易放松点」，刻意复查采样（这是「后台采样不间断规矩」「空仓也不得停采样」的兜底执行）。
3. **备份唤醒（增强，消单点故障）**：盯盘启动时设 `ScheduleWakeup` 每 5-10 分钟定时自检（`delaySeconds` 300-600，`prompt` 带「采样链自检：ps 查 monitor_segment 在跑否、不在则重启」），task-notification 正常时它不抢戏、失效时它兜底唤醒 AI 重启采样；每次触发后重新设一个（滚动续保）到收盘/喊停。⚠️ ScheduleWakeup 原为 /loop 工具、普通盯盘适用性待实测；若不可用，回退到核心靠①②（AI 自检 + 大动作复查）——这两条已能堵住这次的漏洞（通知失效 + 主观放松），备份唤醒是锦上添花。

**盯盘启动清单显式列入三件套**（不靠记忆，2026-07-27「规定在 skill 里却没调用」同款教训）：启动时 ① 设 ScheduleWakeup 备份（尝试，若环境支持）；② 每次唤醒第一个动作 ps 自检采样；③ 大动作（平仓/止损/减仓）后复查采样链。

### 盯盘启动方向研判（盯盘第一步定当日基调，2026-07-13 借鉴 OhMyTradingTeam 多视角框架日内化）

盘中找标的（hot_list）是"看今天什么在动"，但缺一步先定"今天大方向偏多还是偏空"。本研判用**多维度独立打分后综合**，定当日方向倾向，缩小找标的范围（只做顺势方向）——避免见涨追涨、逆势开仓。

**时机**：盯盘启动的**第一步**，在 `preflight` 之后、`hot_list` 之前——**无论用户何时叫醒盯盘（盘前预热或已盘中）都先跑一次**，产出：一句话"今日港股/美股偏多 / 偏空 / 中性震荡"。盘前启动用隔夜外围 + 指数结构判基调；盘中启动数据更全（有实时资金流 / 量价），照样走这五维度。核心是"**先定方向再找标的**"，时点不限、不是只在盘前做。

**五个维度独立给倾向**（每维偏多 +1 / 中性 0 / 偏空 −1，最后求和定向）：

|---|---|---|
| **宏观基调** | **最近一根**美股日 K 收盘涨跌 / 美 10 年期国债收益率方向 / 美元指数 / VIX；今日有无央议息、CPI/非农、重大政策 | 富途 `get_market_snapshot` 查美股主指数 / ETF；外围消息看新闻。⚠️ **"最近一根"≠"昨夜"**：周一开盘时最近一根是**上周五**（周末美股休市），节假日后开盘同理跨假期——须跨周末/假期核对期间事件（地缘/政策/数据），不许说"昨夜"、不许忽略中间跨度（2026-07-13 用户纠正） |
| **技术趋势** | 目标市场指数近 5 日 K 线结构（上升 / 下降 / 横盘）、距关键支撑阻力远近 | `scripts/kline.py <指数代码> 5` |
| **量价** | 指数近几日涨跌是否带量（量价配合 = 趋势健康，背离 = 虚弱） | kline 量柱 |
| **资金流** | 目标板块 / 标的资金净流向（盘前数据有限，开盘后用 `capital` 复核） | 富途 `get_capital_flow`（盘中）|
| **事件催化** | 当日有无个股 / 板块级事件（财报、产品发布、政策落地）——事件日波动大、方向不定 | 财经日历 |

**综合定向**：
- 和 ≥ +2 → 今日偏多，找标的优先找顺势做多机会（hot_list 后叠"近 5 日上升趋势"过滤）。
- 和 ≤ −2 → 今日偏空，优先找顺势做空机会。
- 其余 → 中性震荡，按区间交易思路（支撑买 / 阻力卖，见「交易策略纪律」区间震荡条），降低开仓预期。

**⚠️ 位置评估：当前价在大趋势中的位置 = 盘中方向假设的关键**（2026-07-18 用户立，优先级高于五维度求和定向）。五维度求和给的是"大趋势方向"（偏多/偏空），但日内盘中走哪边还要看"**当前价在大趋势中的位置**"——同一支下跌趋势股，处在上沿（超买）和处在下沿（超跌）的盘中方向完全不同：

| 当前价位置 | 盘中倾向假设 | 即使大趋势 |
|---|---|---|
| **下沿（超跌区）**：接近最近 ≥4 个月日线低点连线 / 重要支撑 / 短期大幅超跌 | **超跌反弹做多假设**（等企稳做多、不空）| 即便大趋势空，下沿超跌最可能深 V 反弹 |
| **上沿（超买区）**：接近最近 ≥4 个月日线高点连线 / 重要阻力 / 短期大幅超买 | **回调做空假设**（等遇阻做空、不多）| 即便大趋势多，上沿超买最可能回调 |
| **中段** | **顺势大趋势方向** | 下跌中段续空、上涨中段续多 |

**怎么判断位置**：盯盘启动时 `python3 scripts/kline.py <标的> 120`（如 `US.MU 120`，约 4 个月交易日；**判断大趋势至少拉 4 个月日线**——短周期看不出真趋势通道，2026-07-18 用户立）画高点连线（上沿阻力）+ 低点连线（下沿支撑），开盘价/现价接近哪沿即位置判据；**大趋势方向 × 位置 = 今日盯盘方向假设**（例：大趋势空 + 下沿超跌 → 超跌反弹做多假设；大趋势空 + 中段 → 顺势做空假设）。

2026-07-17 反面教训：MU 开盘 804，从 7/9 高 1035 一个月跌 -22%、804 处在这段下跌**下沿**（接近一个月低点）= 超跌区。即便半导体大趋势下跌，开盘在下沿超跌最可能深 V 反弹——我却只看"大趋势偏空"就定做空、等"反弹遇阻做空"，完全错过 804→880 深 V（-22% 超跌后 +9.5% 反弹）。**正确：开盘前 `kline.py US.MU 30` 看位置（下沿超跌）→ 立超跌反弹做多假设 → 等企稳做多**，而非等"突破 2-3 道阻力"才被动转多（那已错过最佳段）。**位置预判是主动打头、盘中动态修正是被动兜底，两者叠加**（位置预判可能错，动态修正来纠偏）。

**重要边界**（避免误用）：
1. **本研判是"大方向参考 + 选标的过滤"，不是盘中信号**。方向偏多不代表立即追多，仍要等盘中合格入场点（回踩企稳 / 真突破站稳，见「做多合格入场只有两种」）。
2. **宏观基调维度较慢**，只影响"今日整体偏多偏空"的背景判断，不进实时盯盘链路（盯盘看秒级盘口，宏观是背景）。
3. **事件催化日**（CPI / 非农 / FOMC / 财报）方向不定但波动剧：优先上 WebSocket 密采样（见下「重要数据日优先 WebSocket」），开盘后等波动消化再入场、不抢第一波。
4. 中性震荡日**不是不开仓**，而是切区间交易（支撑买 / 阻力卖）、降单笔预期、止损更紧。
5. **⚠️ 盘中动态修正方向（2026-07-17 教训立，最高优先级）**：开盘方向研判是"起点"不是"全天锚定"——盘中必须随趋势演变动态校准，方向变了就切换策略，**绝不固守开盘方向执念**。反转触发条件（任一满足即重估方向）：① **连续突破 ≥2 道关键阻力**（创新高）= 趋势转多信号，不是"反弹遇阻"——放弃做空框架、转向做多/观望；② 连续跌破 ≥2 道关键支撑（创新低）= 转空，放弃做多；③ 标的站上/跌破 VWAP 并企稳 = 日内多空转换。④ **箱顶/箱底 ≥2 次假突破/假破位 = 震荡市确认**（既非趋势延续、也非反转，是区间反复）——立即切**区间交易**（箱顶卖/做空、箱底买/做多，打法见「交易策略纪律·区间震荡市」「半仓轮动」），**丢掉"等突破/破位"的趋势执念**（震荡市执念突破 = 把区间当趋势，必踏空）。⑤ **持续单向缓慢运动 ≥1 小时但未破关键位**（如持续阴跌后低位缓涨、或持续上涨后高位滞涨）= 动能可能在转向——重估「是否在构筑反弹/企稳」或「是否在构筑顶部」，**不能因「没破关键位」就继续守原方向**（2026-07-27 立，见下 MU 午盘教训）。判别时机：每隔 10 分钟重估时自问「箱顶/箱底今天第几次测试了？每次到顶/底是不是都回头？」——顶/底各被测试 ≥2 次都回头 = 震荡确认。**2026-07-22 中芯教训**：开盘判"上升三角形看涨"后当全天锚定，整上午箱顶 77.8 六次假突破（11:20/11:26/11:29 冲 77.25-77.5 都回落）+ 箱底 75.25 多次不破，**11:26 第二次假突破就该确认震荡、切区间交易**，却盯"突破做多"到 11:50（用户提醒才醒），错过箱顶做空（11:29 冲 77.5 赔率 2.5、11:42 赔率 1.55）与箱底做多（10:44 测 75.5 企稳）。根因：开盘预判当信仰 + 没按 10 分钟重估 + 确认偏误（只挑支持预判的"高点略上移"、忽略"箱顶反复不过 + 无量"的证伪信号）。**"反弹"vs"反转"判定**：连续突破多道阻力 = 反转/趋势性上涨（反弹只是短暂回升）；连破 2 道阻力即应重估方向。2026-07-17 教训：开盘偏空后 MU 连破 836/840/853/860 四道阻力（明确转多），却执念"等反弹遇阻做空"2 小时全踏空、靠用户提示才修正为做多（错过 804→880 整段）。**每隔 10 分钟、或标的突破关键位时，重跑一次方向研判**（看趋势/量价/资金流是否仍与开盘方向一致），不重估 = 把开盘研判当信仰。**2026-07-27 MU 午盘教训（渐进式回升盲区 + 规定遗忘）**：开盘判偏空后，午盘 MU 从 854 缓慢回升到 899（4 小时 +5.2%），但触发条件 ①–④ 都没明确满足（没破关键阻力、没站上 VWAP 927、不是箱体），我便守着偏空等反抽做空 4 小时、没重估，错过 ~9700 HKD 做多机会。根因三层：① **规定盲区**——触发条件只覆盖「明确反转信号」（破阻力 / 站上 VWAP）、对「渐进式单向回升」不灵敏（故本次补 ⑤）；② **执行不足**——没执行「每 10 分钟重估」；③ **最根本：压根没想起有这条规定**——盯盘时注意力全在盘面技术分析（价格 / 盘口 / 反抽阻力），「动态修正方向」这条根本没进入思考，规定写在 skill 里却没被调用 = 等于没用。**教训：不能靠「记住」执行规定，要靠流程 / 工具强制**——每段采样结束的处理流程里必须含一步「重估方向（过 5 个触发条件 + 自问方向是否仍与开盘一致）」，不靠记忆；盯盘启动时把「动态修正方向 5 触发」列进当日检查清单。即便没破关键位，持续单向运动 ≥1 小时也要主动重估（⑤），不能拿「触发条件没满足」当不重估的借口。

- **采样频率：后台分段采样脚本、每段 40 秒、10 秒间隔（2026-07-22 用户立，替代原 cron 每分钟机制）**：盘中（港股 09:30-12:00 / 13:00-16:00、美股美东 09:30-16:00）用 `monitor_segment.py` **后台连续密采样**——独立进程、不受会话状态影响，每段跑固定时长（标准 **40 秒**、10 秒间隔 = 4 次采样），段结束自动触发 harness 的 task-notification 通知 AI 读取分析 + 重启下一段。实际分析周期 = 40 秒采样 + 读数分析重启开销 ≈ 55-65 秒（略长于 40 秒）。盯盘启动后 AI 自主循环「启动后台段 → 等段结束通知 → 读数据 + 分析 + 汇报（汇报必含下次段结束时间）→ 重启下一段」，直到用户喊停或撞上强制终止边界。
  - **为什么不用 cron（2026-07-22 实测教训，重要）**：cron（无论 session-only 还是 durable 写盘）在此环境触发**不可靠**——它只在 REPL 特定 idle 态触发，会话卡顿（如富途 `capital_distribution` 接口卡死占用会话）、用户消息插队、Stop hook（如 `/goal`）都会挡住它，实测一上午多次中断（10:17、10:38、10:56 等，用户反复提醒才发现）。**后台任务完成通知（task-notification）是 harness 核心机制、远比 cron 可靠**，用它驱动盯盘循环不再无故中断。⚠️ task-notification 也**非 100% 可靠**（会话长时间运行 / 上下文压缩 / 状态切换时偶发失效，2026-07-28 实测过一次断链 9.5 小时），**靠「采样链防中断」三件套兜底**（AI 自检 + 大动作复查 + 备份唤醒，见上「📌 采样链防中断」段）。判别：看到 cron 注册还在（`CronList` 有）却不触发 = 此环境 cron 失效，转分段采样。
  - **突破即时响应（关键位提前通知，2026-07-22 参数化）**：每只标的的关键位（阻力 up / 支撑 dn）随命令行传入（targets 的 `SYM:up:dn`，见上「分段采样盯盘」用法），**不再写死在脚本里**——原版 `UP_BREAK`/`DN_BREAK` 是澜起 06809 的硬编码、换标的就失配。脚本检测到某只标的 high 创本段新高且 ≥ 它的 up、或 low 创新低且 ≤ 它的 dn，立即 `break` 退出、提前触发通知，突破响应延迟从段时长（≤40 秒）压到 ~10 秒（下一次采样）。**多只票任一破位都提前结束整段**（第一时间叫 AI 来看）。盯盘启动做方向研判时为每只候选标的定好关键位、随命令行传入。
  - **不因市况降频**——无论趋势 / 区间震荡、有无持仓、早盘 / 盘中 / 尾盘，一律每段 40 秒密采样（撤销原「震荡市 / 无持仓平稳时降频」规定，2026-07-20 用户立）。**密采样定义 + 早盘必密（2026-07-22 用户立）**：**分段采样段时长 ≤ 40 秒才叫「密采样」，> 40 秒（60-180 秒）算稀疏采样**；**早盘必须密采样**——**早盘 = 港股 09:30-12:00 HKT / 美股 09:30-12:00 ET**（整个上午交易时段），此时段段时长必须 ≤ 40 秒、不得放稀到 60-180 秒（早盘波动集中、机会与风险都在这，稀疏采样会漏掉冲高又回落的完整动作、分不清真突破与诱多）。开盘首小时（港股 09:30-10:30 / 美股 21:30-22:30）急涨急跌最剧烈，可更密到 30 秒。**段时长可调**：更密可改 30-40 秒、更稀可改 60-180 秒（`monitor_segment.py <targets> <duration> <interval>`，targets 格式见上「分段采样盯盘」），**但早盘（09:30-12:00）不得放稀**；默认 40 秒。
  - **标的不值得密盯时优先换标的、而非降频（2026-07-23 用户立，与「不因市况降频」协调）**：当觉得当前盯的标的「不值得密盯」（缩量横盘无信号、陷入僵持、赔率凑不足、反复测试关键位不破等）时，**第一优先级是切换到值得密盯的标的**（有波动、有信号潜力、有交易价值的活跃标的），**而不是降低盯盘频率**（放稀到 60-180 秒）死盯当前标的。原因：降频死盯一个无信号的标的 = 既错过别的标的的机会、又在该标的上也抓不到信号（无信号时放稀更抓不到），**双输**；换标的密盯 = 保持密采样捕捉新标的突破，才有机会。**2026-07-23 教训**：午市中芯/阿里持续缩量横盘（69.85 铁底、114.9 箱顶反复不破），AI 把段时长从 40 秒放稀到 120 秒死盯这两只、空耗整个午市，而非 `hot_list` 刷新换活跃标的——用户据此立此规矩。**执行**：发现当前标的不值得密盯 → 立即 `hot_list` 刷新找活跃标的（高振幅 + 高成交额 + 顺势）→ `snapshot`+`kline` 确认新标的位置与波动 → 切换 `monitor_segment` **密盯**新标的（保持 40-60 秒，不降频）。只有当**整个市场都缩量无活跃标的**（如全天单边后的垃圾时间、临近收盘无波动）时，才考虑降频。⚠️ 本条修正「后台采样不间断规矩」里「空仓观望时可放稀 60-180 秒」——空仓观望也应优先换标的密盯，而非降频死盯。
  - **采样输出只留关键字段**（price / bid / ask / 买卖比 / 量比 / high / low / 额 + 突破标记），不打印完整 JSON（连续几十段会撑爆上下文）；AI 每段**三层分析**：①先跑 `monitor_summary.py` 看全貌摘要判**行情性质**（震荡/多/空/中性，**每次重判、随时切换策略**——判断行情必须看开盘到当前全貌，最近 N 分钟看不出；**全貌必带 VWAP**，见上「VWAP 必看」条）；②读 log 最近 N 行（`tail -60 tmp/monitor_log_*.csv`）看即时突破/回踩定入场时机；③**每段过「做空入场 checklist」+ 每 10 分钟「方向重估」**（2026-07-28 立，落实 7-27「流程强制调用规定」）：a. **每段（约 1 分钟）必检做空信号**——反抽阻力乏力（多次不过 + 买卖比大负）？跌破支撑后反抽遇阻？**做空信号与做多信号同等优先、不能只盯企稳做多**；b. **每 10 分钟必重估方向**（`monitor_segment.py` 满 10 分钟打 ⏰ 提醒强制）——过「盘中动态修正方向」5 触发 + 自问方向/趋势/行情是否仍与开盘一致、不固守。2026-07-28 反面教训：兆易空头趋势日，AI 一根筋盯企稳做多、看到反抽 480 乏力 + 买卖比 −54 却仍想做多，错过 R 2.8 顺势做空——根因是每段流程没有「做空 checklist」这一步、365 行做空规则永远不被触发（与 7-27 MU「规定在 skill 里却没调用」同款）。三层结合精简汇报（盯盘汇报精简规则见下「盯盘对话输出要精简」，且**每次汇报必含下次段结束时间**）。
  - **被打断就跳过、直接看最新数据（2026-07-22 用户立）**：分段采样在跑期间若被用户消息、处理别的事、或漏掉段结束通知打断——**不纠结补读被打断的段、不重叠重启**，直接 `snapshot` 取当前最新数据（或重启一段新采样读当前）分析即可。避免「漏段 → 补读 → 重叠重启 → 多进程混乱」（2026-07-22 上午实战：漏读一段后试图补重启，结果两三个采样进程重叠、TaskStop 找不到 id，乱成一团）。一句话：**采样链断了就从当前时刻续上，不回头补**；用户消息优先处理，处理完用当下最新数据继续盯。
- **密采样工程参数（盘中任何时刻适用，2026-07-07 补、2026-07-20 修订撤销「仅早盘」限定）**：盘中任何时刻（尤其开盘首小时 港股 09:30-10:30 / 美股 21:30-22:30 流动性集中、急涨急跌最快）都用这套参数——10-30 秒内可能完成一次冲高又回落的完整动作，稀疏采样只看到结果、分不清「真突破」与「冲高诱多」，胜负往往在这几秒到几十秒内决定。工程实测结论（2026-07-03 盘后）：
  - **采样间隔统一取 10 秒**（用户 2026-07-07 取 config / 正文两处口径最小值；早期方案 A `sleep30×3`≈62 秒、方案 B `sleep20×5`≈84 秒均工程可行，已被更密的 10 秒取代）。配置读 `config.json` 的 `monitoring.early_session.sample_interval_sec`。
  - **API 限流不是瓶颈**：富途 / 老虎连续调 quote/depth/capital（无 sleep）实测约 1.6 次/秒、**零失败零限流**；10 秒间隔负载（0.1 次/秒）远低于压力测试速率，间隔小不会触发限流。
  - **物理下限约 15 秒/决策回合**：纯 CLI 调用约 0.6 秒/次，带「采样→读→决策」的回合约 15 秒；要秒级响应只能上 WebSocket 推送（见下条）。
  - **采样输出只留关键字段**（price / bid1 / ask1 / 3 档差 / 大单净流），**不打印完整 JSON**：单轮 quote+depth+capital 约 1KB，连续几十轮会撑爆上下文，须定期摘要而非全量输出。
  - **盯盘对话输出要精简（2026-07-14 用户二次修订，唯独盯盘要精简）**：实时盯盘盘面秒变，对话输出要精简、信息密度高——结论直接给、信号直接发、不展开「为什么」的长篇解释（长解释会让用户收到时情况已变、结论失配）。盯盘报告简短陈述关键事实（价格、变化、盘口关键值）+ 直接给判断；无信号一行带过（价 + 变化 + 判断）。⚠️ **精简靠用通用术语直接陈述，不靠自创缩写；语义清晰仍是底线**（不为短牺牲语义、不自造缩略说法）。响铃最先（`ring.sh`，拍板即响）、响铃后 snapshot 取价、最后 `log_signal.sh` 写信号文件复盘（对话不输出关键字段；时序见「信号格式 · 🔔 信号时序总则」）。**唯独盯盘要精简**——复盘、一般对话、写入文件（含 skill / rules / 文档）都不精简，用大白话把逻辑说清（见全局 CLAUDE.md「输出风格」、项目 `.claude/rules/output-and-writing-style.md`）。
  - **盘前启动只预热、开盘后才发信号（2026-07-16 立）**：用户如果在盘前发盯盘指令，AI 只做盘中盯盘准备（跑 `preflight`、做方向研判、`hot_list` 预先找标的），**盘前不发五类信号**；要等开盘（港股 09:30 / 美股美东 09:30）之后才发。美股盯盘窗口覆盖整个盘中（美东 09:30-16:00），盯到用户喊停或收盘（护栏 10）。
  - **重要数据日优先 WebSocket**：非农 / CPI / FOMC 等日子开盘波动极剧，10 秒间隔仍可能漏秒级信号，这类日子直接上老虎 WebSocket（方案 C）。
  - **开盘前 5 分钟验证富途 OpenD**：港股 09:25、美股 21:25 确认富途 OpenD 端口 11111 监听（`lsof -nP -iTCP:11111 -sTCP:LISTEN`），避免开盘才发现数据源掉线。
- **优先用老虎 WebSocket 推送替代轮询**（港股）：7/6 开盘后用 PushClient 订阅 quote/tick/depth，毫秒级实时，突破轮询瓶颈。代码骨架见 `tiger-websocket.md`。

## 用户执行反馈（2026-07-15 信号模式：假设执行，用户主动告知才据实调整）

AI 不下单，所有订单 / 成交均为用户在 App 操作。**信号模式下 AI 假设执行、不查 `positions`**（信号模式总则第 1 条），协作流程：

- **AI 发信号 → 假设用户已执行 → AI 按假设持仓继续盯盘**（不查 `positions`、不等反馈、不记账，复盘时再算）。
- **用户主动告知才据实调整**：用户若真实操作（执行了信号、或自行买卖）致持仓变化，会**临时主动告知** AI；只有这时 AI 据实调整假设持仓。用户没说就按假设持仓盯。
- **用户未按信号执行属正常**（用户有最终决定权）：AI 不告警、不催促，按假设持仓继续盯盘发信号。
- **持仓方向与数量以用户告知为准**：用户告知实际成交后，AI 据其调整；未告知则按开仓信号里的量作假设持仓。

## 停盯总结（盯盘结束即时小结，2026-07-23 立）

**停盯第一个动作——解除防睡眠（2026-07-25 立 → 2026-07-27 修订：盯盘预热已无条件启用 caffeinate -s，停盯须无条件解除）**：盯盘预热（preflight）已自动启用 `caffeinate -s` 防系统睡眠（无论开盖合盖、不询问），故停止盯盘时（用户喊停 / AI 仅在快休市或收盘时才自主停——其余时段持续盯、不收尾）AI **必须自己**跑 `bash .claude/skills/keep-awake/scripts/off.sh` 解除防睡眠。用户**不会**主动说「解除防睡眠」——AI 自主在停止盯盘时收尾，避免长期持 `PreventSystemSleep` assertion。

盯盘结束（用户喊停 / 撞上港股 12:00 午休或 16:00 收盘 / 美股用户喊停或 16:00 收盘）时，AI 主动给一份**当日小结**，区别于复盘分析（见 `references/review-and-evaluation.md`，由用户指令触发、更详细）。**停盯总结必含每笔的赔率三阶段（初始预期 / 修正预期 / 实际落地，定义见「交易策略纪律·赔率三阶段」）**，不只是盈亏金额：

- **三阶段赔率**（2026-07-23 用户立，总结必全列）：① **初始预期赔率**（开仓前、参考价算）② **修正预期赔率**（开仓后、响铃实测成交价算）③ **实际落地赔率**（平仓后、实际盈亏 ÷ 实际 max_loss，即 R-multiple，$R_i=P_i/M$；max_loss 用开仓时止损距离反推的风险额度 = 仓位 × 止损距离，移动止损不改开仓 max_loss 基准）。
- **盈亏与落地赔率用响铃实测价算**（开仓实测价、平仓实测价，不是参考价），最贴近真实成交。
- 每笔报：标的、方向、开仓参考价、开仓实测价、平仓实测价、实际盈亏金额、max_loss、**三阶段赔率（初始预期 R / 修正预期 R / 实际落地 R）**；多笔再给**整体实际落地赔率**（总盈亏 ÷ 总 max_loss）。三阶段并列表能直接看出「预估→实测→落地」的打折程度（如 2026-07-23 阿里 2.30→2.00→0.82R、中芯 3.21→2.20→0.48R）。
- **为什么必列三阶段**：盈亏金额看不出「承担了多少风险换来的」——同样赚 5000，max_loss 5000 是 1R、max_loss 10000 只算 0.5R；而单看落地赔率又看不出「预估乐观但落地打折」（初始 2.3R 落地只剩 0.82R）。三阶段并列表才能既看真实性价比、又看预期兑现度，暴露「赚了钱但赔率低」和「预估乐观但没让利润奔跑」两类问题。**所有数值用 Python 实算，不心算**（遵守「第一原则」）。

## 复盘分析（收到用户复盘指令时做，2026-07-16 立）

**数据源**：`signals/` 历史信号记录（港股 `signals/YYYY-MM-DD-HKT-signals.md`、美股 `signals/YYYY-MM-DD-ET-signals.md`，港美分开），按**建仓批次逐笔**算参数（入场价 / 止损 / 盈亏 / R-multiple）。

## 发信号前自查清单

发开仓信号前逐条过：

- [ ] 标的已富途快照查 name 确认？跑 `classify_hk_security.py` 判定为 etf / stock / reit（含杠杆 / 反向 ETF）且 confidence=high？港股优先 ETF（免印花税，仅港股；美股不适用）？
- [ ] 近 5 日趋势看过？顺势？
- [ ] **全貌 + VWAP + 位置 + 形态硬闸（2026-07-27 中芯教训立，开仓前必做、缺一不发）**：
  - **① 跑 `monitor_summary.py` 看全貌**：当日开/现/high/low/振幅、箱体顶/底各测试几次、买卖比与量比的前半→后半演变、**行情性质判别（震荡/多/空/中性）**——「判断震荡还是趋势必须看全貌、最近 N 分钟看不出」（2026-07-23 教训）。**没跑全貌 = 不知行情性质 = 不发**。
  - **② 看 VWAP**（snapshot 的 `avg_price` 字段）：价格在 VWAP 上方 = 多头占优、下方 = 空头占优；VWAP 震荡向上 = 多头趋势日、向下 = 空头趋势日；低开高走 + 站上 VWAP = 多头反弹日。**开仓前必须明确「价格相对 VWAP 位置 + VWAP 趋势」**——不看 VWAP = 可能把反弹日当震荡日、方向做反。
  - **③ 位置评估硬闸**（拉 4 个月日线 kline 判当前价在大趋势的位置，见「盯盘启动方向研判·位置评估」）：**下沿（超跌区）→ 做多假设（等企稳做多、不空）**；**上沿（超买区）→ 做空假设（等遇阻做空、不多）**；中段 → 顺势。**逆位置不开仓**（下沿做空 = 接飞刀、上沿做多 = 摸顶）。⚠️ **「下沿不空」精确边界（2026-07-28 立）**：「下沿不空」指不在**恐慌急跌点**空（接飞刀反面、易被 V 反弹扫损）；但若下沿出现**反抽阻力明确乏力**（反抽多次不过 + 买卖比大负 = 机构出货），则「反抽阻力位乏力遇阻」做空入场**仍成立**——这是顺势做空、不是接飞刀。一句话：下沿**恐慌急跌点**不空，下沿**反抽阻力乏力**可空。2026-07-28 反面教训：兆易 480 反抽两次不过 + 买卖比 −54（机构卖），AI 误把「下沿不空」当绝对禁令、却一直等企稳做多，错过 R 2.8 顺势做空（后实际跌到 466/456）。
  - **④ 做空必须等做空形态**（双顶 / 头肩顶 / 反抽阻力位乏力遇阻 / 跌破支撑后反抽该支撑遇阻），**不在潜在反弹底（双底 / 头肩底 / 暴跌低点）空**——那是做多位置；做多同理必须等做多形态（回踩企稳 / 突破回踩；**暴跌低点必须等双底/头肩底、禁企稳抄底**，见「做多合格入场」+ 2026-07-29 07709 教训），不在潜在顶部多。⚠️ 中芯 07-27 反面教训：暴跌低点 68.05 反抽未到阻力（70）就在 69.1 空 = 接飞刀 + 逆下沿位置 + 没做空形态，被 V 反弹扫止损 −1R；当时只看资金流出一维、漏了位置+形态+全貌+VWAP，误给 🟢 高置信——**资金流再强也不抵逆位置 + 无做空形态**。
