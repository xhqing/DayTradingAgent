# Trade

AI 用富途 OpenD / 老虎 SDK（盯盘行情数据主力，Level2 盘口 / 经纪队列 + 资金流 + WebSocket 毫秒级推送）做港股 / 美股日内交易的执行规范。本 skill 有**两种执行模式**——**信号（signal，默认）**与**自动交易（auto，用户特别说明时才用）**，详见下文「模式开关与触发首动作」。盯盘数据走富途 + 老虎（资金流富途更优：含 super 超大单 + 分钟序列 + 十大买卖经纪，数据源分工见 `references/account-tools.md`）。**事实错误和违规操作是 bug、不可接受**。

## 触发条件

当用户提出以下任一意图时激活本 skill：

- 盯盘 / 看盘 / 分析标的走势 / 找交易机会
- 开仓 / 平仓 / 移损（signal 模式 AI 发信号由用户手动执行；auto 模式用户特别说明时 AI 调脚本自动执行）
- 交易复盘 / 统计交易胜率 / 赔率 / EV
- 任何涉及富途 OpenD / 老虎 SDK / 长桥 OpenAPI 的盯盘数据或下单操作

## 模式开关与触发首动作（最高优先级）

本 skill 有两种执行模式，**唯一区别 = 是否使用证券账户**：auto 模式 AI 直接调券商 API 下单、碰账户；signal 模式 AI 只发信号、用户手动执行、不碰账户。**两种模式的交易策略（盯盘、找机会、算仓位止损、形态、时段、复盘）完全通用**，差异只在账户相关的执行环节（详见各自 reference）。

### 触发后第一件事 = 亮模式提醒

**用户指令激活本 skill 时（盯盘启动、开仓 / 平仓 / 移损 / 复盘指令），对话输出的第一段就是模式提醒**——先定模式、亮提醒，再进入任何盯盘 / 分析 / 执行。段间循环唤醒（`monitor_segment` 段结束通知）不算用户指令、不重复亮。模式在 session 内保持，用户喊切换时重新亮一次。

**先按下列逻辑判定当前模式**：

- 默认 **signal**。
- 用户指令含「只发信号 / 手动执行 / 不要 AI 下单 / 信号模式」→ 切 **signal**（本就是默认，用户说了也无害）。
- 用户指令含「自动下单 / 自动交易 / auto / AI 直接下单」→ 切 **auto**（需用户特别说明才用）。

**signal 模式提醒（默认）**：

```
🔴🔴🔴 **当前模式：信号（signal，默认）—— AI 只发信号、用户手动执行、不碰账户 / 资金 / 持仓、不下单** 🔴🔴🔴
```

**auto 模式提醒**（用户特别说明用自动交易时，含默认账户）：

```
🔴🔴🔴 **当前模式：自动交易（auto）—— AI 直接下单。默认账户：港股【老虎开放平台模拟 <HK_PAPER_ACCOUNT>】/ 美股【长桥模拟 ~/.longbridge/openapi/env-paper】（港股备选长桥模拟，仅用户特别说明时用）** 🔴🔴🔴
```

> 这条提醒是安全件：auto 模式下 AI 不问用户就下单，账户或模式弄错就是实盘事故。开场强制亮明模式 + 账户，等于逼 AI 和用户双方第一眼对齐——用户发现不对能立刻喊停（比如本想要信号、却显示 auto）。默认是 signal（不碰账户），只有用户特别说明才切 auto，切换的瞬间务必重新亮 auto 提醒。

### 模式路由

模式定下后，加载对应模式的专属规则（执行环节的差异都在里面）：

- **auto 模式** → 读 `references/auto-mode.md`（自动交易总则、3 类动作、交易动作脚本、动作记录格式、auto 专属硬护栏、下单 API 与订单机制、执行反馈、auto 专属自查）。
- **signal 模式** → 读 `references/signal-mode.md`（信号模式总则、信号时序、3 类信号格式、信号输出与持仓检查、被动平仓标记、用户执行反馈、signal 权益更新、signal 专属自查）。

**脚本调用按模式传 `--mode`**：调 `preflight.py` / `resume.py` / `open_position.py` 等涉及 equity 的脚本时，按当前模式传 `--mode`——signal 模式默认（不传即 signal）、auto 模式传 `--mode auto`。脚本据此选 equity 来源：auto 连长桥账户 API 取真实总资产、signal 读 `signals/equity-log.csv` 累加值（不连账户）。详见 `signal-mode.md`「signal 模式权益更新」。

> 三类动作 / 信号的语义两种模式一致：**开仓 🟢 / 平仓 🔴 / 移损 🟡，禁止加仓减仓**，最多持仓一个标的，一笔交易 = 一次开仓到一次平仓。详情（含平仓主动 vs 被动、止盈靠两类动作）在各自 mode reference。

## 第一原则：事实先验证，再说结论（最高优先级）

这是一切交易判断的地基，违反这条等于在沙地上盖楼。**凭推测当事实输出，比交易亏钱更不可接受**。具体执行：

1. **接触任何标的代码，第一件事用富途 `get_market_snapshot([code])` 查 `name` 字段确认真身**，再谈分析。港股代码本是 5 位数字（如 02800、00005、03688），无语义规律，凭记忆会认错（0823 是领展 REIT 不是汇丰、汇丰是 0005）。代码 + 中文名一起写进汇报。
2. **算术必须实算**，不许心算报数（如以为「400 不是 200 的倍数」，实际 400÷200=2）。
3. **交易日历用富途 `request_trading_days` 查**，不许凭记忆说哪天开盘。港股 7/3+7/5 周末休市、美股 7/3-7/4 独立日休市等都曾搞错过。
4. **API 字段先实跑一次看真实返回结构再用**，不许凭印象猜字段名（如富途 `get_market_snapshot` 返回 DataFrame、老虎 `get_stock_briefs` 也是 DataFrame，按对象属性直取会得 None）。
5. **手续费 / 利率 / 汇率等数字必须有据**，禁止估算报数，查不到标「待查」绝不编数字填进去。
6. **币种符号必须分明**：港币一律写 `HK$` 或 `HKD`，**禁止用裸 `$` 表港币**——`$` 在本 skill 默认指美元。报数时须据标的所在市场正确标注币种，美元写 `$` 或 `USD`、港币写 `HK$`/`HKD`，混用会让人误把港币当美元（或反之）。

## 6 要素（开仓前必须确定）

无论 auto（下单）还是 signal（发信号），开仓前都必须确定这 6 项：

1. **标的** — 代码 + 中文名（富途快照核验）
2. **方向** — 做多 / 做空
3. **参考价** — 初始预期赔率 ≥ 1.2 时的入场价（snapshot 实价）
4. **价格范围** — 在止损价和目标止盈价不变的前提下，修正预期赔率 ∈ [0.6, 10] 对应的入场价格区间（修正预期赔率 = 止盈距离 ÷ 止损距离，用实际成交价计算；成交价到止损价的价差 = 一个风险单位 R）。**计算公式与 [0.6, 10] 区间来源见 `references/risk-management.md`「价格范围计算」**。
5. **数量** — 按 B ÷ 止损距选最接近的离散仓位（止损距 = |参考价 − 止损价|，用参考价计算，因为下单前实际成交价未知）。**选仓位算法、lot_size 离散化、f_max 硬上限见 `references/risk-management.md`「选仓位」**。
6. **止损价** — 趋势反转位 / 逻辑失效点（**不是远技术位、不是百分比**，判定方法见 `references/risk-management.md`「止损位 = 趋势反转位」）。

## 硬性护栏（执行前逐条自检，违反不得执行）

> 下单（auto）或发信号（signal）前都要过的公共护栏。auto 模式另有下单专属护栏（止损单类型、AI 直接下单、脚本触发）见 `references/auto-mode.md`「auto 专属硬护栏」。

1. **单笔预算与 max_loss（固定比例动态下注）**：单笔预算 B = `risk_fraction`（2%）× 当前 equity，max_loss = 仓位 × 每股止损距（围绕 B 选最近、可略超或略低，但不可超 `equity × f_max` 硬上限，当前 10%）。止损位 = 趋势反转位 = 逻辑失效点（做多跌破 VWAP / 企稳支撑、做空站上 VWAP / 阻力），**不要用远技术位、不要用百分比机械算**——会让持仓逆势抗跌大亏。选仓位按 lot_size 离散候选里「实际 max_loss 最接近 B」的那档。**详细概念区分（B vs M）、选仓位算法、f_max 兜底、美股换算、权益更新、利润 = R × max_loss、杠杆对 R 的影响见 `references/risk-management.md`。**（auto 模式 equity 从券商账户 API 取真实总资产；signal 模式 equity 从 `signals/equity-log.csv` 累加假设盈亏——见 `references/signal-mode.md`「signal 模式权益更新」。）
2. **开仓前 `quote` 确认实价**作参考价。auto 模式脚本返回 order_id 即确认成交；signal 模式假设执行、不查 positions（用户是否真执行由用户自决）。
3. **不记账**：auto 模式交易动作记录到 `actions/`、signal 模式信号记录到 `signals/`，都不算实时盈亏；复盘时统一算当天盈亏。
4. **一次最多持仓一个标的（硬规矩）**：AI 自我约束——当前已有持仓时，不开新标的仓。持仓时只能平仓或移损（禁止加仓减仓）。auto 模式平仓后脚本自动撤销所有未触发止损单（`close_position.py` 内置，2026-07-06 教训：残留条件单下次开盘误触发）；signal 模式平仓信号发出后提示用户在 App 撤销未触发止损 / 挂单。
5. **标的范围：仅个股（含 ADR）+ ETF，禁止衍生品**（期权 / 窝轮 / CBBC / 期货）。港股偏好 ETF（免港式印花税，仅港股；美股无此优势）。杠杆 / 反向 ETF（含 2x/3x）允许；**所有 ETF 都可交易，没有黑名单/白名单限制**。**开仓初始止损按预判趋势反转点定；持仓中按「止损单的两种用法」（锁大利润 / 放趋势反转位）管理——锁大利润用法仅在浮盈 ≥ 2R（2 倍赔率）时考虑，< 2R 用放趋势反转位（2026-08-01 用户立）**——3x ETF 波动大，其反转位在价格上天然更远，但不套百分比。下单前必跑 `classify_hk_security.py` 判定类型（目的是排除衍生品，不是筛 ETF）。**标的判定的四层启发式、REIT 判定、代码格式、做空能力查询见 `references/account-tools.md`。**
6. **港股每手股数是硬约束**：下单量必须是整手倍数，否则报 602001。建仓前富途快照查 `lot_size`（中芯 500/手、小米 200/手、腾讯/美团/领展 100/手）。**tick size 等价位规则见 `references/risk-management.md`「港股价位 tick size」。**
7. **执行与盯盘时段——三类动作 / 信号只在盘中执行**：开仓 🟢、平仓 🔴、移损 🟡 只能在盘中执行或发出，盘前、盘后、夜盘一律不执行 / 不发，盯盘也只在盘中进行。**港股**盘中（北京 09:30-12:00 / 13:00-16:00，港股交易日），港股没有盘前 / 盘后 / 夜盘，午休 12:00-13:00 不可交易。**美股**盯盘窗口 = 美东 09:30-16:00（夏令时北京 21:30-次日 04:00 / 冬令时 22:30-次日 05:00）。**盯盘靠用户指令启动、AI 不自主启动**：盘前启动时只做准备（preflight、方向研判、hot_list），不执行交易动作 / 不发信号，等开盘后才执行。**不跨市场**：同一时刻只盯一个市场。**开盘观察期 = 条件触发、不机械卡时长**：开盘后**过完「开仓前自查清单」（全貌判行情性质 + VWAP 方向 + 位置评估硬闸 + 形态 + EV ≥ 1.2 + 置信度 🟢）即允许开仓**——开盘初期数据不稳 / VWAP 未成型 / 形态未构筑，自查清单自然过不了（等价于等数据稳定），条件满足即开仓，不卡死「开盘 N 分钟禁交易」的机械时点（原 09:30-10:30 一刀切禁令会错过开盘初期即确认的有效信号、且砍掉港股上午仅 2.5 小时的黄金时段）。**平仓 🔴、移损 🟡 任何时候都不被观察期挡**——二者是风控动作，即便开盘初期或前日漏平有持仓、价格急速反向，也必须能立即平 / 移损，不该被「观察期」卡死（裸奔 = 2026-07-31 类事故隐患）。暴跌标的「开盘 30 分钟内不开多、等双底 / 头肩底确认」是策略层接飞刀防护，见 `references/trading-strategy.md`，独立保留、不靠全市场禁交易覆盖。开盘一段时间后才启动盯盘的，先把已有数据（kline / monitor_summary / 资金流）过一遍、完成行情性质判断与开仓前自查再进正常流程。

## 时点平仓与停止盯盘约束

盯盘收到用户指令后持续盯，**没让停就不停**——美股盯到**用户发出停止盯盘指令**或**美东 16:00 收盘**（取先到者，用户大概率北京晚上睡觉前喊停），港股则撞上下面两个强制终止边界。**无论哪个时点停止盯盘，停前都必须主动平仓——不存在留单**（停盯前一律主动平仓离场；auto 调 `close_position.py`、signal 发平仓信号）。⚠️ **港股两个边界都是「终止盯盘」、不是暂停——终止后一律不自动恢复，即便午市 13:00 开盘也不自动续盯，须等用户再次下达盯盘指令才重新启动**。美股不设固定终止时点，由用户喊停决定（16:00 收盘兜底）。

📌 **持仓不过夜纪律**：所有持仓在当日停止盯盘前（港股 12:00 午休前 / 港股 16:00 收盘前 / 美股用户喊停或 16:00 收盘前）由 AI 主动平仓了结。这是 AI 主动平、不是账户强平。止盈决策在「当日了结、停盯前主动平」框架内：① 止盈位要在当日停止盯盘前可达，否则停盯前主动按市价平掉；② 不存在留单——停盯前一律主动平仓离场。「不过夜」按交易日判：持仓在该市场当日停止盯盘前了结、不跨到下一交易日。

| 边界 | 时点 | 必做动作 |
|---|---|---|
| **港股午休前** | 北京 12:00（早市收盘） | **平掉所有港股持仓 + 终止盯盘**。午休 12:00-13:00 无法交易 / 执行止损，持仓过午休等于裸奔（13:00 开盘可能跳空、午休期间止损单不触发）。**13:00 午市开盘不自动恢复盯盘**——午市要盯须等用户再次下达盯盘指令。 |
| **港股收盘前** | 北京 16:00（港股收盘） | **主动平掉所有港股持仓 + 终止盯盘**，当日港股彻底结束。临近 16:00 的策略分情况（见 `references/trading-strategy.md`「临近停止盯盘的分情况策略」）：有持仓——出现很好的主动平仓机会就主动平（剩余时间不多、不平则收益跌下去没时间再涨）；趋势仍健康可持有到收盘前再主动平。无持仓——临近收盘开仓要小心，剩余时间少意味着赔率可能受限。 |
| **美股停止盯盘前** | **用户发出停止盯盘指令的时刻**（大概率北京晚上睡觉前），或美东 16:00 收盘（取先到者） | **主动平掉所有美股持仓 + 终止盯盘**。⚠️ **不存在留单**——停盯前一律主动平仓离场。用户大概率在北京晚上睡觉前发停止盯盘指令（对应美东盘中某时刻，夏令时约美东 11:00-12:00 / 冬令时约 10:00-11:00），届时停前主动平；少数情况用户不喊停，则盯到美东 16:00 收盘、收盘前主动平。**停盯前必过 `references/trading-strategy.md`「临近停止盯盘的分情况策略」检查**：若**浮盈大 + 加速赶极端**（做多：加速赶顶 = 加速上涨 + 破前高 + 远离 VWAP 上方超买；做空：加速赶底 = 加速下跌 + 破前低 + 远离 VWAP 下方超卖 = 动能将竭）→ 立即主动平仓 🔴 锁利（2026-07-17 MU 教训：浮盈 +$3071、加速赶顶却误判「持续上涨」、最终回吐 ~$2000；盘中任何时候动能将竭就该主动平、不等停盯）。 |

⚠️ **跨境 / 杠杆 ETF 午休跳空风险尤其大**：跟踪**境外标的**的港股 ETF（如 07709 两倍做多海力士、07747 两倍做多三星电子——跟踪韩国股市），**韩国股市中午不休市**（韩国 09:00-15:30 连续交易），港股午休 12:00-13:00 期间境外标的仍在交易、价格持续变化，而港股 ETF 此刻既无法反应、也无法止损。一旦境外标的大跌，13:00 港股开盘 ETF 跳空下跌、止损单来不及触发。故这类跨境 ETF **尤其**必须在 12:00 前平仓，跳空风险比纯港股标的（自身也午休的）大得多。

盯盘临近停止盯盘时点（港股 12:00 午休前 / 港股 16:00 收盘前 / 美股用户喊停或 16:00 收盘前）都要**主动提前处理**仓位——停前一律主动平仓、不留单，别等到点被动；时点一到即停止盯盘，不拖。港股实际可交易窗口：早市 09:30-12:00（**12:00 午休前必须平**）、午市 13:00-16:00（**16:00 收盘前必须平**，所有港股持仓）。

## 盯盘工作流（高层骨架）

盯盘标准启动序列：**`preflight` → 方向研判 → `hot_list` 找标的 → `static` + `classify` 核实标的 → `snapshot` + `kline` 分析 → `monitor_segment` 密采样盯盘 → 段结束通知驱动循环 → 撞上终止边界或用户喊停 → 停盯总结**。

1. **preflight**（`scripts/preflight.py`）：时间 / 港股美股时段 / 富途 OpenD 端口 / 当日交易记录文件（auto 读 `actions/`、signal 读 `signals/`）+ equity / 自动启用 caffeinate 防系统睡眠。**先跑这个**。
2. **方向研判**（盯盘第一步定当日基调）：五维度（宏观基调 / 技术趋势 / 量价 / 资金流 / 事件催化）独立打分 + 位置评估（当前价在大趋势的上沿超买 / 下沿超跌 / 中段），产出「今日偏多 / 偏空 / 中性震荡」+ 盘中方向假设。
3. **hot_list**（`scripts/hot_list.py HK 15`）：热度榜 + 叠 snapshot 查成交额 / 振幅 / 换手，找标的铁律第一步——不许凭关注列表或 AI 记忆直接定标的。
4. **核实标的**：`snapshot` + `classify_hk_security.py` 查代码真身与类型（etf / stock / reit）。
5. **分析**：`snapshot`（现价 / OHLC / lot / 成交额 / 振幅 / 买卖比 / 量比）+ `kline`（近 N 日 K 线 + 斐波那契回撤）+ `monitor_summary`（全貌摘要 + VWAP + 行情性质判别）。
6. **监控循环**：`monitor_segment.py` 后台分段密采样（每段 40 秒、10 秒间隔），段结束 task-notification 唤醒 AI → 三层分析（**先看段结束输出自带的 📊 VWAP 检查（每标的现价 vs VWAP 位置，必看、方向框架地面真相）** + 全貌摘要判行情 + log 最近 N 行看即时 + 做空 checklist + 每 10 分钟方向重估）→ 重启下一段。AI 自主循环，不中途停下问用户。
7. **停盯**：撞上终止边界或用户喊停 → 主动平仓 + 停盯总结。

**所有采样机制（后台采样不间断规矩、采样链防中断三件套、时间断层哨兵）、方向研判详细打分表与位置评估表、脚本库完整用法与参数、采样频率工程参数（40 秒 / 10 秒、为什么不用 cron、突破即时响应、不因市况降频、标的不值得密盯时优先换标的、密采样定义 + 早盘必密）、VWAP 必看、被打断就跳过、盘前预热、重要数据日 WebSocket、开盘前验证 OpenD、盯盘对话输出精简规则见 `references/monitoring.md`。**

## 操作原则（公共）

> auto 专属操作原则（自动执行调脚本、记录到 actions/、持仓从脚本输出跟踪）见 `references/auto-mode.md`；signal 专属（假设执行不查 positions、响铃写文件）见 `references/signal-mode.md`。下面是两种模式共用的：

1. **质量优先**：开仓必须过两道闸（🟢 高置信 + 初始预期赔率 ≥ 1.2，见 `references/trading-strategy.md`「开仓基准」「置信度分级」），不达标就不开仓、宁可观望整场。
2. **自主循环、不打断用户**：AI 自主跑「盯盘→分析→执行 / 发信号→记录」循环，不中途停下问用户、不等确认。盯盘期间无人值守——AI 所有盯盘决策（换标的 / 方向 / 止损 / 平仓 / 移损 / 降频）自主完成，不 AskUserQuestion 中断。无机会时自主决策树：① 换标的（hot_list 刷新找活跃标的）；② 降频（整个市场无活跃机会时放宽采样间隔）；③ 持续盯到收盘 / 用户喊停。
3. **复盘由用户指令触发、盘中不复盘**：只有收到用户明确的复盘指令才做复盘。
4. **AI 职责边界**：分析、盯盘、算仓位 / 止损价、执行（auto 下单 / signal 发信号）、记录。**不记账、不实时算盈亏**（复盘时再算）。
5. **零额外延迟**：盘中盘面秒变，所有准备工作（汇率、标的分类、quote 实价）前置到盯盘启动时做好，盘中只做「拿最新数据 → 算 → 执行」，零额外查询。

## 停盯总结（盯盘结束即时小结）

**停盯第一个动作——解除防睡眠**：盯盘预热（preflight）已自动启用 `caffeinate -s` 防系统睡眠（无论开盖合盖、不询问），故停止盯盘时（用户喊停 / AI 仅在快休市或收盘时才自主停——其余时段持续盯、不收尾）AI **必须自己**跑 `bash .claude/skills/keep-awake/scripts/off.sh` 解除防睡眠。用户**不会**主动说「解除防睡眠」——AI 自主在停止盯盘时收尾，避免长期持 `PreventSystemSleep` assertion。

盯盘结束时，AI 主动给一份**当日小结**，区别于复盘分析（见 `references/review-and-evaluation.md`，由用户指令触发、更详细）。**停盯总结必含每笔的赔率三阶段（初始预期 / 修正预期 / 实际落地）**，不只是盈亏金额：

- **三阶段赔率**（总结必全列）：① **初始预期赔率**（开仓前、参考价算）② **修正预期赔率**（开仓后、实际成交价算）③ **实际落地赔率**（平仓后、实际盈亏 ÷ 实际 max_loss，即 R-multiple，$R_i=P_i/M$；max_loss 用开仓时止损距离反推的风险额度 = 仓位 × 止损距离，移动止损不改开仓 max_loss 基准）。**三阶段定义见 `references/trading-strategy.md`「赔率三阶段」。**
- **盈亏与实际落地赔率用实际成交价算**（auto = 脚本返回的真实成交价；signal = 响铃时刻价；开仓 / 平仓成交价都是真实 / 实测价，不是参考价）。
- 每笔报：标的、方向、开仓参考价、开仓成交价、平仓成交价、实际盈亏金额、max_loss、**三阶段赔率（初始预期 R / 修正预期 R / 实际落地 R）**；多笔再给**整体实际落地赔率**（总盈亏 ÷ 总 max_loss）。三阶段并列表能直接看出「预估→修正→落地」的打折程度（如 2026-07-23 阿里 2.30→2.00→0.82R、中芯 3.21→2.20→0.48R）。
- **为什么必列三阶段**：盈亏金额看不出「承担了多少风险换来的」——同样赚 5000，max_loss 5000 是 1R、max_loss 10000 只算 0.5R；而单看实际落地赔率又看不出「预估乐观但落地打折」（初始预期赔率 2.3R 实际落地赔率只剩 0.82R）。三阶段并列表才能既看真实性价比、又看预期兑现度，暴露「赚了钱但赔率低」和「预估乐观但没让利润奔跑」两类问题。**所有数值用 Python 实算，不心算**（遵守「第一原则」）。

## 复盘分析（收到用户复盘指令时做）

**触发**：只在收到用户明确的**复盘指令**时做。盯盘期间专注盯盘、**不自主复盘**（见「操作原则」第 3 条）。**所有数值用 Python 实算，不心算报数**（遵守「第一原则」）。

**数据源**：auto 模式读 `actions/` 历史交易动作记录（港股 `actions/YYYY-MM-DD-HKT-actions.md`、美股 `actions/YYYY-MM-DD-ET-actions.md`）；signal 模式读 `signals/` 历史信号记录（港股 `signals/YYYY-MM-DD-HKT-signals.md`、美股 `signals/YYYY-MM-DD-ET-signals.md`）。逐笔算参数（入场价 / 止损 / 盈亏 / R-multiple）。

**复盘工具**：`python3 scripts/review.py <trades.csv>` 一次性输出全套指标（样本明细、终局统计量、过程指标分盈亏单、贝叶斯 P(EV>0)、频率派 CI、样本量规划）；`python3 scripts/bayes_evolution.py` 输出 7 张序贯演化图。复盘产物放 `reviews/`（报告 `reviews/YYYY-MM-DD-review.md` + 同日 csv/png）。

**详细方法论见 `references/review-and-evaluation.md`**（收到复盘指令时读它）：统计量定义与推导（EV 分解合并恒等、MAE / MFE / 回吐 / 锁利效率 η）、7 张序贯演化图的必含规范、样本量规划、多层评估框架。盯盘时不必读、复盘时按此逐项统计。

**📊 读图纪律（省 token）**：复盘分析**以 `review.py` + `bayes_evolution.py` 的终端数值输出为依据**——两脚本在终端已 print 每笔序贯数值（胜率 / P(EV>0) / 累计均值 / EV 95% CI）与终局多 f 表，覆盖 7 张演化图的全部关键信息，看数值即可写「分阶段解读」与「终局表」。**演化图是复盘报告的必含产物**（写给用户看、嵌入报告），但 **Claude 默认不把 png Read 进上下文**——每张图按分辨率约 1500–2000 tokens、7 张上万，读图性价比远低于看终端数值。**只在终端数值看不出某个趋势拐点、确需肉眼确认时，才按需读单张 png**。

## 开仓前自查清单（公共项）

> auto 专属补充自查（从脚本输出取结果、价格范围校验、成交后 max_loss 复核、log_action 记录）见 `references/auto-mode.md`；signal 专属补充自查（发信号硬前置、假设执行、响铃时序、信号格式、提示用户挂止损）见 `references/signal-mode.md`。下面是两种模式共用的公共项，开仓前逐条过：

- [ ] **恢复协议 + 执行硬前置已过（最高优先级、首检项）**：距上次 `date` ≤ 2 分钟 且 距上次 `snapshot`（该标的）≤ 2 分钟？若任一 > 2 分钟，或本 session 经历过断网 / 暂停 / 工具故障 / 会话压缩 → **先跑 `python3 scripts/resume.py [标的]` 重建上下文 + 刷新现价**，再执行。参考价过时 = 执行基准错 = 实亏（2026-07-28 中芯事故教训），**禁止用过时数据执行**。
- [ ] 标的已富途快照查 name 确认？跑 `classify_hk_security.py` 判定为 etf / stock / reit（含杠杆 / 反向 ETF）且 confidence=high？港股优先 ETF（免印花税，仅港股；美股不适用）？
- [ ] 近 5 日趋势看过？顺势？
- [ ] **全貌 + VWAP + 位置 + 形态硬闸（开仓前必做、缺一不发）**：
  - **① 跑 `monitor_summary.py` 看全貌**：当日开 / 现 / high / low / 振幅、箱体顶 / 底各测试几次、买卖比与量比的前半→后半演变、**行情性质判别（震荡 / 多 / 空 / 中性）**——「判断震荡还是趋势必须看全貌、最近 N 分钟看不出」（2026-07-23 教训）。**没跑全貌 = 不知行情性质 = 不发**。
  - **② 看 VWAP**（snapshot 的 `avg_price` 字段）：价格在 VWAP 上方 = 多头占优、下方 = 空头占优；VWAP 震荡向上 = 多头趋势日、向下 = 空头趋势日；低开高走 + 站上 VWAP = 多头反弹日。**开仓前必须明确「价格相对 VWAP 位置 + VWAP 趋势」**——不看 VWAP = 可能把反弹日当震荡日、方向做反。
  - **③ 位置评估硬闸**（拉 4 个月日线 kline 判当前价在大趋势的位置，见 `references/monitoring.md`「位置评估」）：**下沿（超跌区）→ 做多假设（等企稳做多、不空）**；**上沿（超买区）→ 做空假设（等遇阻做空、不多）**；中段 → 顺势。**逆位置不开仓**（下沿做空 = 接飞刀、上沿做多 = 摸顶）。⚠️ **「下沿不空」精确边界**：「下沿不空」指不在**恐慌急跌点**空（接飞刀反面、易被 V 反弹扫损）；但若下沿出现**反抽阻力明确乏力**（反抽多次不过 + 买卖比大负 = 机构出货），则「反抽阻力位乏力遇阻」做空入场**仍成立**——这是顺势做空、不是接飞刀。一句话：下沿**恐慌急跌点**不空，下沿**反抽阻力乏力**可空。2026-07-28 反面教训：兆易 480 反抽两次不过 + 买卖比 −54（机构卖），AI 误把「下沿不空」当绝对禁令、却一直等企稳做多，错过 R 2.8 顺势做空（后实际跌到 466/456）。
  - **④ 做空必须等做空形态**（双顶 / 头肩顶 / 反抽阻力位乏力遇阻 / 跌破支撑后反抽该支撑遇阻），**不在潜在反弹底（双底 / 头肩底 / 暴跌低点）空**——那是做多位置；做多同理必须等做多形态（回踩企稳 / 突破回踩；**暴跌低点必须等双底 / 头肩底、禁企稳抄底**，见 `references/trading-strategy.md`「做多合格入场只有两种」+ 2026-07-29 07709 教训），不在潜在顶部多。⚠️ 中芯 07-27 反面教训：暴跌低点 68.05 反抽未到阻力（70）就在 69.1 空 = 接飞刀 + 逆下沿位置 + 没做空形态，被 V 反弹扫止损 −1R；当时只看资金流出一维、漏了位置 + 形态 + 全貌 + VWAP，误给 🟢 高置信——**资金流再强也不抵逆位置 + 无做空形态**。
- [ ] **EV 判据：胜率 > 50% 且 初始预期赔率 ≥ 1.2**（初始预期赔率 = 止盈距离 ÷ 止损距离 = |止盈−参考价| ÷ |参考价−止损|，止盈距离 ≥ 1.2 × 止损距离）？初始预期赔率 < 1.2 不开仓。止损按趋势反转位 = 逻辑失效点定（禁止百分比）。**详细见 `references/risk-management.md`「止损位 = 趋势反转位」+ `references/trading-strategy.md`「开仓基准」。**
- [ ] **置信度 = 🟢 高？**（开仓只在 🟢 高置信执行；🟡 中置信 / 🔴 低置信都不开仓、等升到高置信或局面明朗。判级见 `references/trading-strategy.md`「置信度分级」；**若有临近重大事件，按「事件风险三维度判别」评估（方向 / 程度 / 是否影响主导驱动）、不机械降级**。）
- [ ] **止损价已定**（趋势反转位 / 逻辑失效点、非远技术位）？每股止损距算出？单笔预算 B = risk_fraction × 当前 equity；开仓量 = 按 lot_size 离散候选里「实际 max_loss 最接近 B」的那档（不超 f_max 上限）？
- [ ] lot_size 整手倍数？价位合规？
- [ ] `quote` 实价已查作开仓参考价？

## 🔒 盯盘恢复协议（Resume Protocol，最高优先级）

盯盘要求**连续**（盘面秒变、决策时效以秒计），但执行环境会**断层**——断网、用户主动暂停再重启、工具故障 / 分类器不可用、会话压缩、长任务占用，任一都可能让 AI 失去时间感知 + 数据过时 + 上下文丢失。**最危险的是用过时数据做「看起来成立」的交易决策 / 信号**（参考价过时 = 执行基准错 = 实亏）。

**总则：AI 的内存（对话上下文）不可信，文件才是地面真相。任何时候重新获得执行权，第一动作是从文件重建状态、刷新数据，绝不用断层前的旧数据执行（auto 下单 / signal 发信号）。**

### 触发条件（任一即跑恢复协议，作为第一动作）

- 收到用户消息唤醒（尤其「继续盯盘 / 继续」类重启指令）
- 后台采样段结束通知唤醒、但距上次段结束明显偏久
- 工具故障 / 分类器不可用 / 断网恢复后
- 会话被压缩、长任务结束后回来
- 自己察觉距上次 `date` / `snapshot` 可能过了较久

**一句话：只要不是连续顺畅的段间循环（段结束 → 读数 → 重启下一段），就先跑恢复协议再继续。**

### 恢复协议五步（封装在 `scripts/resume.py`，跑一次即可）

`python3 scripts/resume.py [标的1,标的2,...]`（可选标的 = 额外 snapshot 刷新现价，如持仓标的）：

1. **`date` 核实真实时间 + 算「距上次活动的时间差」**——上次活动时间 = `tmp/monitor_log_*.csv` 最后采样时间；距现在 ≥ 5 分钟 → 输出 ⚠️ 断层警告。
2. **判市场状态决定能否执行**：港股盘中（北京 09:30-12:00 / 13:00-16:00）或美股盘中（美东 09:30-16:00）才允许执行（auto 下单 / signal 发信号）；盘前 / 盘外 / 收盘后停止盯盘，不执行。
3. **从文件重建上下文**（不靠内存）：读今日交易记录文件（auto 读 `actions/YYYY-MM-DD-<market>-actions.md` / signal 读 `signals/YYYY-MM-DD-<market>-signals.md`）确认当前持仓状态（开仓记录 + 入场价 + 止损 + 止盈）；读 equity 来源（auto 读券商账户 API / signal 读 `signals/equity-log.csv`）末行确认当前 equity（算单笔预算 B）。
4. **`snapshot` 刷新所有相关标的现价**——断层前的价一律作废。
5. **处理断层期间的持仓变化**：断层期间持仓可能被动触发止损（现价越过止损位）→ 标注「大概率被动触发、待盘后回查确认」，盘后用历史 K 线精确回查、更新 equity。

### 交易决策硬前置（针对过时数据做决策的补丁）

开仓前强制检查：

- 若**距上次 `date` > 2 分钟** → 重新 `date` 核实时间；
- 若**距上次 `snapshot`（该标的）> 2 分钟** → 重新 `snapshot` 取最新价当参考价；
- 不满足 → **禁止开仓**，先 `date` + `snapshot` 刷新再开。

这条与「第一原则·汇报当前时间 / 盘面时点前 date 实测」互补：参考价过时 = 执行基准错 = 实亏。时间断层哨兵等采样机制细节见 `references/monitoring.md`「时间断层哨兵」。

## 当前阶段

当前默认处于**信号模式（signal）**阶段：AI 只发信号、用户手动执行、不碰账户。用户**特别说明要自动交易**（说「自动下单 / 自动交易 / auto」等）时才切**自动交易模式（auto）**：港股默认用老虎开放平台模拟账户、美股默认用长桥模拟账户，AI 调脚本执行 3 类动作。两种模式交易策略通用，唯一区别 = 是否使用证券账户。auto 模式下如用户不使用默认账户会特别说明。进阶判据：胜率 / 赔率 / EV 稳定为正 + AI 持续进步。
