# Trade

AI 用富途 OpenD / 老虎 SDK（盯盘行情数据主力，Level2 盘口 / 经纪队列 + 资金流 + WebSocket 毫秒级推送）做港股 / 美股日内交易的执行规范。本 skill 有**两种执行模式**——**信号（signal，默认）**与**自动交易（auto，用户特别说明时才用）**，详见下文「模式开关与触发首动作」。盯盘数据走富途 + 老虎（资金流富途更优：含 super 超大单 + 分钟序列 + 十大买卖经纪，数据源分工见 `references/account-tools.md`）。**事实错误和违规操作是 bug、不可接受**。

## 触发条件

当用户提出以下任一意图时激活本 skill：

- 盯盘 / 看盘 / 分析标的走势 / 找交易机会
- 开仓 / 平仓 / 移损（signal 模式 AI 发信号由用户手动执行；auto 模式用户特别说明时 AI 调脚本自动执行）
- 交易复盘 / 统计交易胜率 / 赔率 / EV
- 任何涉及富途 OpenD / 老虎 SDK 的盯盘数据或下单操作

## 模式开关与触发首动作（最高优先级）

本 skill 有两种执行模式，**唯一区别 = 是否使用证券账户**：auto 模式 AI 直接调券商 API 下单、碰账户；signal 模式 AI 只发信号、用户手动执行、不碰账户。**两种模式的交易策略（盯盘、找机会、算仓位止损、形态、时段、复盘）完全通用**，差异只在账户相关的执行环节（详见各自 reference）。

### 触发后第一件事 = 亮模式提醒

**用户指令激活本 skill 时（盯盘启动、开仓 / 平仓 / 移损指令），对话输出的第一段就是模式提醒**——先定模式、亮提醒，再进入任何盯盘 / 分析 / 执行。段间循环唤醒（`monitor_segment` 段结束通知）不算用户指令、不重复亮。模式在 session 内保持，用户喊切换时重新亮一次。⚠️ **复盘指令不亮模式提醒（2026-08-04 用户立）**——复盘只读历史交易记录、不执行下单、不碰账户，没有「auto 模式误下单」的实盘事故风险，模式提醒的安全价值不成立、亮了反成啰嗦；模式提醒只在「会下单或可能下单」的盯盘 / 开仓 / 平仓 / 移损场景亮（它是安全件：防 auto 下 AI 不问就下单、账户或模式弄错就出实盘事故）。

**先按下列逻辑判定当前模式**：

- 默认 **signal**。
- 用户指令含「只发信号 / 手动执行 / 不要 AI 下单 / 信号模式」→ 切 **signal**（本就是默认，用户说了也无害）。
- 用户指令含「自动下单 / 自动交易 / auto / AI 直接下单」→ 切 **auto**（需用户特别说明才用）。

## 第一原则：事实先验证，再说结论（最高优先级）

这是一切交易判断的地基，违反这条等于在沙地上盖楼。**凭推测当事实输出，比交易亏钱更不可接受**。具体执行：

1. **接触任何标的代码，第一件事用富途 `get_market_snapshot([code])` 查 `name` 字段确认真身**，再谈分析。港股代码本是 5 位数字（如 02800、00005、03688），无语义规律，凭记忆会认错（0823 是领展 REIT 不是汇丰、汇丰是 0005）。代码 + 中文名一起写进汇报。
2. **算术必须实算**，不许心算报数（如以为「400 不是 200 的倍数」，实际 400÷200=2）。
3. **交易日历用富途 `request_trading_days` 查**，不许凭记忆说哪天开盘。港股 7/3+7/5 周末休市、美股 7/3-7/4 独立日休市等都曾搞错过。
4. **API 字段先实跑一次看真实返回结构再用**，不许凭印象猜字段名（如富途 `get_market_snapshot` 返回 DataFrame、老虎 `get_stock_briefs` 也是 DataFrame，按对象属性直取会得 None）。
5. **手续费 / 利率 / 汇率等数字必须有据**，禁止估算报数，查不到标「待查」绝不编数字填进去。
6. **币种符号必须分明**：港币一律写 `HK$` 或 `HKD`，**禁止用裸 `$` 表港币**——`$` 在本 skill 默认指美元。报数时须据标的所在市场正确标注币种，美元写 `$` 或 `USD`、港币写 `HK$`/`HKD`，混用会让人误把港币当美元（或反之）。

## 6 要素（开仓前必须确定）

无论 auto（下单）还是 signal（发信号），开仓前都必须确定这 6 项：

1. **标的** — 代码 + 中文名（富途快照核验）
2. **方向** — 做多 / 做空
3. **参考价** — snapshot 实价（开仓前 `quote` / 快照取的最新市价作基准；须满足净初始预期赔率 **≥ 1.2**（`config.json risk.min_net_odds`，2026-08-25 用户下调 1.8→1.2）才用它开仓——它是开仓筛选门槛、不是参考价的定义属性，门槛由来与沿革见 `references/trading-strategy.md`「预估赔率系统性打折」「门槛沿革」）
4. **价格范围** — 在止损价和目标止盈价不变的前提下，净修正预期赔率 ∈ [0.6, 10] 对应的入场价格区间（净口径，扣双边手续费；成交价到止损价的价差 = 一个风险单位 R）。**费率口径 = 老虎真实费率（2026-08-12 立、2026-08-17 平台费改固定模式 + 美股改按股，见 `references/risk-management.md`「费率与成本」）**：港股单边费 = 佣金 `max(15, 成交额×0.029%)` + 印花税（个股 0.1%、ETF 免）+ 各征费 + 固定平台费 15/笔；美股 = 佣金 0.0039/股 + 平台费 0.004/股（每笔最低 1、cap 0.5%×额）+ 代收近似 0.00396/股。**计算公式与 [0.6, 10] 区间来源见 `references/risk-management.md`「价格范围计算」**。
5. **数量** — 按 B ÷ 止损距选最接近的离散仓位（止损距 = |参考价 − 止损价|，用参考价计算，因为下单前实际成交价未知）。**选仓位算法、lot_size 离散化、f_max 硬上限、市值杠杆上限见 `references/risk-management.md`「选仓位」**。
6. **止损价** — 趋势反转位 / 逻辑失效点（**不是远技术位、不是百分比**，判定方法见 `references/risk-management.md`「止损位 = 趋势反转位」；**止损位须离开结构位与整数关口一点缓冲（0.25×5 分钟 ATR）防插针**，见 `references/risk-management.md`「止损位防插针缓冲」，2026-08-25 立）。

1. **单笔预算与 max_loss（固定比例动态下注）+ 开仓市值杠杆上限**：单笔预算 B = `risk_fraction`（2%）× 当前 equity，max_loss = 仓位 × 每股止损距 + 开仓边费 + 止损价平仓边费（**净口径，2026-08-28 立**——止损价精确成交时 R 恰 −1.000、最大亏损不深于 −1R；初始预期 / 修正两个变量见 `references/trading-strategy.md`「赔率三阶段」；围绕 B 选最近、可略超或略低，但不可超 `equity × f_max` 硬上限，当前 10%）。**开仓市值上限（2026-08-08 立）**：开仓市值 = 仓位 × 开仓价，**不得超过 `equity × max_leverage`（config 默认 10 倍）**——权益 10 万 → 最高开 100 万市值。f_max 与 max_leverage 是两套独立约束（f_max 限 max_loss 风险敞口、max_leverage 限开仓市值名义敞口），选仓位时**两者同时满足**：候选档先剔除净 max_loss > equity×f_max 与 市值 > equity×max_leverage 的档，再选最接近 B 的那档。止损位 = 趋势反转位 = 逻辑失效点（做多跌破 VWAP / 企稳支撑、做空站上 VWAP / 阻力），**不要用远技术位、不要用百分比机械算**——会让持仓逆势抗跌大亏。选仓位按 lot_size 离散候选里「实际净 max_loss 最接近 B」的那档。**详细概念区分（B vs M）、选仓位算法、f_max 兜底、市值杠杆上限、美股换算、权益更新、利润 = R × max_loss、杠杆对 R 的影响见 `references/risk-management.md`。**（auto 模式 equity 从券商账户 API 取真实总资产；signal 模式 equity 从 `signals/equity-log.csv` 累加假设盈亏——见 `references/signal-mode.md`「signal 模式权益更新」。）

8. **盯盘采样频率盘中固定 40 秒一段、每秒一个价格（2026-08-07 用户立）、禁止自主降频（含段间 sleep / 一条命令连跑多段）、标的僵局换标的不降频**：**港股每秒采样默认源 = 富途 `futu_ws_segment.py <targets> 40`（富途逐笔推送，2026-08-18 用户立）**——富途 OpenD 是本地网关、多客户端并存互不踢断，多会话并行盯盘天然无冲突；**老虎 `ws_segment.py <targets> 40`（老虎 WebSocket 每秒推送）降为备用源**——仅当富途 OpenD 不可用（连接失败 / 订阅报错 / 推送断流）时才切老虎顶上，用完切回；注意老虎 PushClient 单账户单连接、新连接踢旧连接（code 4001「kick out by a new connection」），多会话并行时必互踢，故并行场景一律富途（2026-08-07 立替代源规则、2026-08-18 反转主次：当日两会话并行互踢 + 00981 逐笔错收深市价两起事故后，用户定为默认富途）。**每秒密采样的由来**（2026-08-07 教训：00100 止损 330 触发前 10 秒快照只见 330.6、实际低点 329.4，10 秒间隔漏瞬时高低点；用户立规「密采样每秒一个价格」）；**美股无老虎行情权限，仍用富途 `monitor_segment.py <targets> 40 10`**（10 秒快照为兜底；2026-08-11 已实测富途可订阅美股 TICKER——每次美股盯盘启动做一次逐笔实测，若每秒稳定有点则升级为 `futu_ws_segment.py` 逐笔每秒采样，见 `references/monitoring.md`「每秒采样」）。AI 不得以任何理由自主修改采样频率——不放稀 DURATION（脚本 >40 已夹回）、不在段间加 `sleep` 等待拉长段间隔（DURATION 虽 40、段间 sleep = 等效降频）、不一条命令 `&&` 连跑多段（段间 AI 不分析 = 等效降频，2026-08-05 教训）、不换 cron / 直接调 snapshot 绕过采样脚本。标的僵局无机会时**换标的不降频**（市场几千只标的总有机会，`hot_list` 刷新找活跃标的密盯），**绝不存在「降频死等」的合法出口**。**详见 `references/monitoring.md`「每秒采样」+「不因市况降频」+「标的不值得密盯时优先换标的」**。

## 时点平仓与停止盯盘约束

盯盘收到用户指令后持续盯，**没让停就不停**——美股盯到**用户发出停止盯盘指令**或**美东 16:00 收盘**（取先到者，用户大概率北京晚上睡觉前喊停），港股则撞上下面两个强制终止边界。**无论哪个时点停止盯盘，停前都必须主动平仓——不存在留单**（停盯前一律主动平仓离场；auto 调对应平仓脚本（港股 `close_position_tiger.py` / 美股 `close_position_tiger_us.py`）、signal 发平仓信号）。⚠️ **港股两个边界都是「终止盯盘」、不是暂停——终止后一律不自动恢复，即便午市 13:00 开盘也不自动续盯，须等用户再次下达盯盘指令才重新启动**。美股不设固定终止时点，由用户喊停决定（16:00 收盘兜底）。

📌 **持仓不过夜纪律**：所有持仓在当日停止盯盘前（港股 12:00 午休前 / 港股 16:00 收盘前 / 美股用户喊停或 16:00 收盘前）由 AI 主动平仓了结。这是 AI 主动平、不是账户强平。止盈决策在「当日了结、停盯前主动平」框架内：① 止盈位要在当日停止盯盘前可达，否则停盯前主动按市价平掉；② 不存在留单——停盯前一律主动平仓离场。「不过夜」按交易日判：持仓在该市场当日停止盯盘前了结、不跨到下一交易日。

| 边界 | 时点 | 必做动作 |
|---|---|---|
| **港股午休前** | 北京 12:00（早市收盘） | **平掉所有港股持仓 + 终止盯盘**。午休 12:00-13:00 无法交易 / 执行止损，持仓过午休等于裸奔（13:00 开盘可能跳空、午休期间止损单不触发）。**13:00 午市开盘不自动恢复盯盘**——午市要盯须等用户再次下达盯盘指令。 |
| **港股收盘前** | 北京 16:00（港股收盘） | **主动平掉所有港股持仓 + 终止盯盘**，当日港股彻底结束。临近 16:00 的策略分情况（见 `references/trading-strategy.md`「临近停止盯盘的分情况策略」）：有持仓——出现很好的主动平仓机会就主动平（剩余时间不多、不平则收益跌下去没时间再涨）；趋势仍健康可持有到收盘前再主动平。无持仓——临近收盘开仓要小心，剩余时间少意味着赔率可能受限。 |
| **美股停止盯盘前** | **用户发出停止盯盘指令的时刻**（大概率北京晚上睡觉前），或美东 16:00 收盘（取先到者） | **主动平掉所有美股持仓 + 终止盯盘**。⚠️ **不存在留单**——停盯前一律主动平仓离场。用户大概率在北京晚上睡觉前发停止盯盘指令（对应美东盘中某时刻，夏令时约美东 11:00-12:00 / 冬令时约 10:00-11:00），届时停前主动平；少数情况用户不喊停，则盯到美东 16:00 收盘、收盘前主动平。**停盯前必过 `references/trading-strategy.md`「临近停止盯盘的分情况策略」检查**：若**浮盈大 + 加速赶极端**（做多：加速赶顶 = 加速上涨 + 破前高 + 远离 VWAP 上方超买；做空：加速赶底 = 加速下跌 + 破前低 + 远离 VWAP 下方超卖 = 动能将竭）→ 立即主动平仓 🔴 锁利（2026-07-17 MU 教训：浮盈 +$3071、加速赶顶却误判「持续上涨」、最终回吐 ~$2000；盘中任何时候动能将竭就该主动平、不等停盯）。⚠️ **美股停盯边界按 16:00 收盘算、不因盘前扩段改变**（2026-08-18 立规同日：可交易窗口向前扩到盘前 04:00，收盘边界不动——盘后 16:00-20:00 仍不可交易、不留仓过夜纪律不变）。 |

⚠️ **跨境 / 杠杆 ETF 午休跳空风险尤其大**：跟踪**境外标的**的港股 ETF（如 07709 两倍做多海力士、07747 两倍做多三星电子——跟踪韩国股市），**韩国股市中午不休市**（韩国 09:00-15:30 连续交易），港股午休 12:00-13:00 期间境外标的仍在交易、价格持续变化，而港股 ETF 此刻既无法反应、也无法止损。一旦境外标的大跌，13:00 港股开盘 ETF 跳空下跌、止损单来不及触发。故这类跨境 ETF **尤其**必须在 12:00 前平仓，跳空风险比纯港股标的（自身也午休的）大得多。

盯盘临近停止盯盘时点（港股 12:00 午休前 / 港股 16:00 收盘前 / 美股用户喊停或 16:00 收盘前）都要**主动提前处理**仓位——停前一律主动平仓、不留单，别等到点被动；时点一到即停止盯盘，不拖。港股实际可交易窗口：早市 09:30-12:00（**12:00 午休前必须平**）、午市 13:00-16:00（**16:00 收盘前必须平**，所有港股持仓）。

## 盯盘工作流（高层骨架）

盯盘标准启动序列：**`preflight` → 方向研判 → `hot_list` 找标的 → `static` + `classify` 核实标的 → `snapshot` + `kline` 分析 → `pool_claim.py claim <候选>` 认领标的池（2026-08-19 立自动划分；signal / auto 同规——认领表有活认领时不认领就被 hook 拦，见 monitoring.md「标的池自动划分」）→ `monitor_segment` 密采样盯盘 → 段结束通知驱动循环 → 撞上终止边界或用户喊停 → 停盯总结**。

1. **preflight**（`scripts/preflight.py`）：时间 / 港股美股时段 / 富途 OpenD 端口 / 当日交易记录文件（auto 读 `actions/`、signal 读 `signals/`）+ equity / 自动启用 caffeinate 防系统睡眠。**先跑这个**。
2. **方向研判**（盯盘第一步定当日基调）：五维度（宏观基调 / 技术趋势 / 量价 / 资金流 / 事件催化）独立打分 + 位置评估（当前价在大趋势的上沿超买 / 下沿超跌 / 中段），产出「今日偏多 / 偏空 / 中性震荡」+ 盘中方向假设。
3. **hot_list**（`scripts/hot_list.py HK 15`）：热度榜 + 叠 snapshot 查成交额 / 振幅 / 换手 + 类型列（**印花税闸已停用 2026-08-28：税闸列与预检列不再显示**），找标的铁律第一步——不许凭关注列表或 AI 记忆直接定标的。
4. **核实标的**：`snapshot` + `classify_hk_security.py` 查代码真身与类型（etf / stock / reit）。
5. **分析**：`snapshot`（现价 / OHLC / lot / 成交额 / 振幅 / 买卖比 / 量比）+ `kline`（近 N 日 K 线 + 斐波那契回撤）+ `monitor_summary`（全貌摘要 + VWAP + 行情性质判别）。
6. **监控循环**：`monitor_segment.py` 后台分段密采样（每段 40 秒、10 秒间隔），段结束 task-notification 唤醒 AI → 三层分析（**先看段结束输出自带的 📊 VWAP 检查（每标的现价 vs VWAP 位置，必看、方向框架地面真相）** + 全貌摘要判行情 + log 最近 N 行看即时 + 做空 checklist + 每 10 分钟方向重估）→ **每段产出一行式判断行 + 写分析心跳**（空转防护硬流程：先分析、写心跳，再重启下一段；见 `references/monitoring.md`「每段最小输出模板 + 分析心跳」）→ 重启下一段。AI 自主循环，不中途停下问用户。
7. **停盯**：撞上终止边界或用户喊停 → 主动平仓 + 停盯总结。

**所有采样机制（后台采样不间断规矩、采样链防中断三件套、时间断层哨兵）、方向研判详细打分表与位置评估表、脚本库完整用法与参数、采样频率工程参数（40 秒 / 10 秒、为什么不用 cron、突破即时响应、不因市况降频、标的不值得密盯时优先换标的、密采样定义 + 早盘必密）、VWAP 必看、被打断就跳过、盘前预热、重要数据日 WebSocket、开盘前验证 OpenD、**多会话并行盯盘（方案 A：单持仓互斥 + 各盯各池、互斥语义与标的池自动划分（认领制））**、盯盘对话输出精简规则见 `references/monitoring.md`。**

## 操作原则（公共）

> auto 专属操作原则（自动执行调脚本、记录到 actions/、持仓从脚本输出跟踪）见 `references/auto-mode.md`；signal 专属（假设执行不查 positions、响铃写文件）见 `references/signal-mode.md`。下面是两种模式共用的：

1. **质量优先**：开仓必须过两道闸（🟢 高置信 + **初始净预期赔率 ≥ 1.2 才开**（`config.json risk.min_net_odds`，2026-08-25 从 1.8 下调），单一门槛、直接比较一步判完；门槛由来与沿革见 `references/trading-strategy.md`「开仓基准」「预估赔率系统性打折·门槛沿革」「置信度分级」），不达标就不开仓、宁可观望整场。
2. **自主循环、不打断用户**：AI 自主跑「盯盘→分析→执行 / 发信号→记录」循环，不中途停下问用户、不等确认。盯盘期间无人值守——AI 所有盯盘决策（换标的 / 方向 / 止损 / 平仓 / 移损）自主完成，不 AskUserQuestion 中断。无机会时自主决策树：① 换标的（hot_list 刷新找活跃标的）；② 换标的不降频（觉得「整个市场无活跃机会」时也保持 40 秒密采样、持续刷 hot_list 找下一个活跃标的，绝无「降频死等」合法出口——见「硬性护栏」与 `references/monitoring.md`，降频出口已于 2026-08-04 撤销）；③ 持续盯到收盘 / 用户喊停。
3. **复盘由用户指令触发、盘中不复盘**：只有收到用户明确的复盘指令才做复盘。
4. **AI 职责边界**：分析、盯盘、算仓位 / 止损价、执行（auto 下单 / signal 发信号）、记录。**不记账、不实时算盈亏**（复盘时再算）。
5. **零额外延迟**：盘中盘面秒变，所有准备工作（汇率、标的分类、quote 实价）前置到盯盘启动时做好，盘中只做「拿最新数据 → 算 → 执行」，零额外查询。

## 停盯总结（盯盘结束即时小结）

**停盯第一个动作——解除防睡眠 + 注销盯盘会话**：盯盘预热（preflight）已自动启用 `caffeinate -s` 防系统睡眠（无论开盖合盖、不询问），故停止盯盘时（用户喊停 / AI 仅在快休市或收盘时才自主停——其余时段持续盯、不收尾）AI **必须自己**跑 `bash .claude/skills/keep-awake/scripts/off.sh` 解除防睡眠，并跑 `bash .claude/skills/trade/scripts/monitor_unregister.sh` 注销盯盘会话（从 `tmp/monitor_sessions.txt` 注册表移除本会话——preflight 已自动注册**仅港股盯盘**，注册表供 caffeinate 引用计数（多会话并行时最后停盯的才解除防睡眠）与 preflight 在场会话数打印使用；watcher 的中断警报 2026-08-20 已删、空转警报 2026-08-21 已删，watcher 不再依赖注册表，但停盯仍必须注销，否则注册表残留会让 caffeinate 引用计数误判「还有人在盯」而不关灯；注销脚本同时联动释放本会话的标的池认领，2026-08-19 立）。用户**不会**主动说「解除防睡眠」——AI 自主在停止盯盘时收尾，避免长期持 `PreventSystemSleep` assertion。

盯盘结束时，AI 主动给一份**当日小结**，区别于复盘分析（见 `references/review-and-evaluation.md`，由用户指令触发、更详细）。**⚠️ 总结范围 = 只总结本会话自己（2026-08-29 用户立，多会话并行场景）**：停盯总结**只能总结本会话自身的盯盘任务执行过程和结果**——本会话认领的标的池、本会话开 / 平的交易、本会话的影子仓、本会话的采样与分析执行情况；**禁止把其它并行会话的交易、其它标的池的盈亏、或账户全口径数字混进来**（多会话共用同一账户时，「账户今日订单」是全池混合口径、不等于本会话战绩——2026-08-28 实录：美股会话停盯总结误把其它会话的 NVDA/CRM/PLTR 交易与历史订单当成当日总结对象、且总结范围跑到港股，被用户两次纠正）。**用户要全局或跨会话汇总时明确说，才做全口径汇总并标明数据来源与归属**。**停盯总结必含每笔的赔率三阶段（初始预期 / 修正预期 / 实际落地）**，不只是盈亏金额：

- **三阶段赔率**（总结必全列，**三阶段统一净口径**——扣双边手续费，分子扣费、**分母（max_loss）也含费**（2026-08-28 起：止损距 + 开仓边费 + 止损价平仓边费，止损价精确成交时 R 恰 −1.000）；费率 = 老虎真实费率，见 `references/risk-management.md`「费率与成本」）：① **初始预期赔率**（开仓前、参考价 + 预期仓位算，分母初始预期 max_loss）② **修正预期赔率**（开仓后、实际成交价 + 实际仓位算，止盈价可修正，分母修正 max_loss）③ **实际落地赔率**（平仓后、净盈亏 ÷ 修正 max_loss，即 R-multiple，$R_i=P_i^{net}/M_修正$；M_修正 = 仓位 × 止损距 + 开仓费 + 止损价平仓费，开仓时点算死、移动止损不改基准）。**三阶段定义见 `references/trading-strategy.md`「赔率三阶段」。**
- **盈亏与实际落地赔率用实际成交价算、扣双边费**（auto = 脚本返回的真实成交价；signal = 响铃时刻价；开仓 / 平仓成交价都是真实 / 实测价，不是参考价；净盈亏 = 毛盈亏 − 单边费率 ×（开仓额 + 平仓额））。
- 每笔报：标的、方向、开仓参考价、开仓成交价、平仓成交价、实际盈亏金额、max_loss、**三阶段赔率（初始预期 R / 修正预期 R / 实际落地 R）**；多笔再给**整体实际落地赔率**（总盈亏 ÷ 总 max_loss）。三阶段并列表能直接看出「预估→修正→落地」的打折程度（如 2026-07-23 阿里 2.30→2.00→0.82R、中芯 3.21→2.20→0.48R）。
- **为什么必列三阶段**：盈亏金额看不出「承担了多少风险换来的」——同样赚 5000，max_loss 5000 是 1R、max_loss 10000 只算 0.5R；而单看实际落地赔率又看不出「预估乐观但落地打折」（初始预期赔率 2.3R 实际落地赔率只剩 0.82R）。三阶段并列表才能既看真实性价比、又看预期兑现度，暴露「赚了钱但赔率低」和「预估乐观但没让利润奔跑」两类问题。**所有数值用 Python 实算，不心算**（遵守「第一原则」）。

**触发**：只在收到用户明确的**复盘指令**时做。盯盘期间专注盯盘、**不自主复盘**（见「操作原则」第 3 条）。**所有数值用 Python 实算，不心算报数**（遵守「第一原则」）。

## 🔒 盯盘恢复协议（Resume Protocol，最高优先级）

盯盘要求**连续**（盘面秒变、决策时效以秒计），但执行环境会**断层**——断网、用户主动暂停再重启、工具故障 / 分类器不可用、会话压缩、长任务占用，任一都可能让 AI 失去时间感知 + 数据过时 + 上下文丢失。**最危险的是用过时数据做「看起来成立」的交易决策 / 信号**（参考价过时 = 执行基准错 = 实亏）。

**总则：AI 的内存（对话上下文）不可信，文件才是地面真相。任何时候重新获得执行权，第一动作是从文件重建状态、刷新数据，绝不用断层前的旧数据执行（auto 下单 / signal 发信号）。**

### 触发条件（任一即跑恢复协议，作为第一动作）

- 收到用户消息唤醒（尤其「继续盯盘 / 继续」类重启指令）
- 后台采样段结束通知唤醒、但距上次段结束明显偏久
- 工具故障 / 分类器不可用 / 断网恢复后
- 会话被压缩、长任务结束后回来
- 自己察觉距上次 `date` / `snapshot` 可能过了较久

**一句话：只要不是连续顺畅的段间循环（段结束 → 读数 → 重启下一段），就先跑恢复协议再继续。**

### 恢复协议五步（封装在 `scripts/resume.py`，跑一次即可）

`python3 scripts/resume.py [标的1,标的2,...]`（可选标的 = 额外 snapshot 刷新现价，如持仓标的）：

1. **`date` 核实真实时间 + 算「距上次活动的时间差」**——上次活动时间 = `tmp/monitor_log_*.csv` 最后采样时间；距现在 ≥ 5 分钟 → 输出 ⚠️ 断层警告。
2. **判市场状态决定能否执行**：港股盘中（北京 09:30-12:00 / 13:00-16:00）或美股可交易时段（美东 04:00-16:00，盘前 + 盘中，2026-08-18 立规）才允许执行（auto 下单 / signal 发信号）；港股盘前 / 美股盘前 04:00 之前 / 盘外 / 收盘后停止盯盘，不执行。
3. **从文件重建上下文**（不靠内存）：读今日交易记录文件（auto 读 `actions/YYYY-MM-DD-<market>-actions.md` / signal 读 `signals/YYYY-MM-DD-<market>-signals.md`）确认当前持仓状态（开仓记录 + 入场价 + 止损 + 止盈）；读 equity 来源（auto 读券商账户 API / signal 读 `signals/equity-log.csv`）末行确认当前 equity（算单笔预算 B）。
4. **`snapshot` 刷新所有相关标的现价**——断层前的价一律作废。
5. **处理断层期间的持仓变化**：断层期间持仓可能被动触发止损（现价越过止损位）→ 标注「大概率被动触发、待盘后回查确认」，盘后用历史 K 线精确回查、更新 equity。

### 交易决策硬前置（针对过时数据做决策的补丁）

开仓前强制检查：

- 若**距上次 `date` > 2 分钟** → 重新 `date` 核实时间；
- 若**距上次 `snapshot`（该标的）> 2 分钟** → 重新 `snapshot` 取最新价当参考价；
- 不满足 → **禁止开仓**，先 `date` + `snapshot` 刷新再开。

这条与「第一原则·汇报当前时间 / 盘面时点前 date 实测」互补：参考价过时 = 执行基准错 = 实亏。时间断层哨兵等采样机制细节见 `references/monitoring.md`「时间断层哨兵」。
