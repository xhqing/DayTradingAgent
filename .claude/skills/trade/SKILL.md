# Trade

AI 用富途 OpenD / 老虎 SDK（盯盘行情数据主力，Level2 盘口 / 经纪队列 + 资金流 + WebSocket 毫秒级推送）做港股 / 美股日内交易的执行规范。**港股默认用老虎开放平台模拟账户、美股默认用长桥模拟账户自动下单，3 类动作（开仓 / 平仓 / 移损），AI 直接调用脚本执行。如用户不使用默认账户会特别说明**。盯盘数据走富途 + 老虎（资金流富途更优：含 super 超大单 + 分钟序列 + 十大买卖经纪，数据源分工见 `references/account-tools.md`）。**事实错误和违规操作是 bug、不可接受**。

## 触发条件

当用户提出以下任一意图时激活本 skill：

- 盯盘 / 看盘 / 分析标的走势 / 找交易机会
- 开仓 / 平仓 / 移损（AI 调脚本自动执行）
- 交易复盘 / 统计交易胜率 / 赔率 / EV
- 任何涉及富途 OpenD / 老虎 SDK / 长桥 OpenAPI 的盯盘数据或下单操作

## 第一原则：事实先验证，再说结论（最高优先级）

这是一切交易判断的地基，违反这条等于在沙地上盖楼。**凭推测当事实输出，比交易亏钱更不可接受**。具体执行：

1. **接触任何标的代码，第一件事用富途 `get_market_snapshot([code])` 查 `name` 字段确认真身**，再谈分析。港股代码本是 5 位数字（如 02800、00005、03688），无语义规律，凭记忆会认错（0823 是领展 REIT 不是汇丰、汇丰是 0005）。代码 + 中文名一起写进汇报。
2. **算术必须实算**，不许心算报数（如以为「400 不是 200 的倍数」，实际 400÷200=2）。
3. **交易日历用富途 `request_trading_days` 查**，不许凭记忆说哪天开盘。港股 7/3+7/5 周末休市、美股 7/3-7/4 独立日休市等都曾搞错过。
4. **API 字段先实跑一次看真实返回结构再用**，不许凭印象猜字段名（如富途 `get_market_snapshot` 返回 DataFrame、老虎 `get_stock_briefs` 也是 DataFrame，按对象属性直取会得 None）。
5. **手续费 / 利率 / 汇率等数字必须有据**，禁止估算报数，查不到标「待查」绝不编数字填进去。
6. **币种符号必须分明**：港币一律写 `HK$` 或 `HKD`，**禁止用裸 `$` 表港币**——`$` 在本 skill 默认指美元。报数时须据标的所在市场正确标注币种，美元写 `$` 或 `USD`、港币写 `HK$`/`HKD`，混用会让人误把港币当美元（或反之）。

## 自动交易模式总则（最高优先级）

本 skill 是 **自动交易模式**。港股默认用老虎开放平台模拟账户（`21728459786026713`）、美股默认用长桥模拟账户（`~/.longbridge/openapi/env-paper`），AI 决定拍板后**直接调用券商 API 下单 + 设止损条件单**，全流程自动化。如用户不使用默认账户会特别说明。

### 3 类动作（开仓 / 平仓 / 移损，禁止加仓减仓）

空仓时只能做**开仓**，持仓时只能做**平仓**和**移损**。禁止加仓和减仓。最多持仓一个标的。

- **开仓 🟢** — 空仓时建仓（做多 / 做空），开仓 = 一笔交易开始，包含挂初始止损条件单。必含 ① 标的 ② 方向 ③ 开仓量 ④ 参考价 ⑤ 止损价（脚本先挂止损单、再下开仓单，确保无裸奔空窗）⑥ 止盈目标价（预期值，不设止盈条件单）⑦ 单笔预算 + 预估 max_loss ⑧ 初始预期赔率（≥1.2）⑨ 置信度 ⑩ 依据。
- **平仓 🔴** — 持仓时主动清仓，或止损条件单被动触发；平仓后自动撤销所有未触发条件单；平仓 = 一笔交易结束。
- **移损 🟡** — 持仓时移动止损（只朝有利方向移，不删旧止损单，直接新增止损条件单）。

**一笔交易（a trade）= 一次开仓到一次平仓**。同一标的同一时刻只有一笔持仓。开仓 = 一笔交易开始，平仓 = 一笔交易结束。复盘时逐笔算 R-multiple、胜率、EV。

### 平仓行为：主动 vs 被动

| 行为 | 触发方 | 盈利 | 亏损 |
|---|---|---|---|
| 主动开仓 | AI 开仓 → 脚本自动执行 | — | — |
| 主动平仓 | AI 平仓 → 脚本自动执行 | **主动锁利** | **主动锁亏** |
| 被动平仓 | 止损条件单触发 | **被动锁利** | **被动锁亏** |

- **主动平仓 🔴**：AI 判断动能减弱 / 情况不对 / 到硬平仓时点等，调 `close_position.py` 执行平仓，记录到 `actions/`。
- **被动平仓（止损条件单触发）**：只标记记录（「XX 止损 $Y 触发、成交 ~$Z、亏/盈 $M」），更新 equity。不存在止盈条件单——锁利靠平仓 / 移损两个主动动作。
- **止盈靠两类动作**：① 主动平仓 🔴（AI 判断到目标 / 情况不对）② 移动止损锁利 🟡（浮盈中上移止损到盈利区，被动触发锁利）。不设移动止盈动作，不设止盈条件单。

### 交易动作脚本（`.claude/skills/trade/scripts/`）

- `open_position.py` — 开仓（6 要素：标的 / 方向 / 参考价 / 价格范围 / 数量 / 止损价；自动算价格范围 + **先挂止损条件单、再下开仓单**（确保无裸奔空窗）+ 智能下单）
- `close_position.py` — 平仓（智能下单，同开仓策略；成功后自动撤销所有未触发条件单）
- `move_stop.py` — 移动止损（不删旧止损单，直接新增止损条件单）
- `trade_utils.py` — 共用工具库（长桥 API 封装、价格范围计算、仓位计算）
- `log_action.sh` — 把完整交易动作写入 `actions/` 目录

### 6 要素（开仓前必须确定）

1. **标的** — 代码 + 中文名（富途快照核验）
2. **方向** — 做多 / 做空
3. **参考价** — 初始预期赔率 ≥ 1.2 时的入场价（snapshot 实价）
4. **价格范围** — 在止损价和目标止盈价不变的前提下，修正预期赔率 ∈ [0.6, 10] 对应的入场价格区间（修正预期赔率 = 止盈距离 ÷ 止损距离，用实际成交价计算；成交价到止损价的价差 = 一个风险单位 R）。**计算公式与 [0.6, 10] 区间来源见 `references/risk-management.md`「价格范围计算」**。
5. **数量** — 按 B ÷ 止损距选最接近的离散仓位（止损距 = |参考价 − 止损价|，用参考价计算，因为下单前实际成交价未知）。**选仓位算法、lot_size 离散化、f_max 硬上限见 `references/risk-management.md`「选仓位」**。
6. **止损价** — 趋势反转位 / 逻辑失效点（**不是远技术位、不是百分比**，判定方法见 `references/risk-management.md`「止损位 = 趋势反转位」）。

### 操作原则

1. **自动执行**：AI 拍板后立即调用 `open_position.py`（开仓）/ `close_position.py`（平仓）/ `move_stop.py`（移损），脚本先挂止损单、再下开仓单（确保无裸奔空窗）+ 智能下单（目标最优成交价）。下单结果（order_id、成交价）由脚本 JSON 输出，AI 据此记录交易动作到 `actions/` 目录（`log_action.sh`）。
2. **自主循环、不打断用户**：AI 自主跑「盯盘→分析→执行→记录」循环，不中途停下问用户、不等确认。盯盘由用户指令启动、AI 不自主启动。盯盘期间无人值守——AI 所有盯盘决策（换标的 / 方向 / 止损 / 平仓 / 移损 / 降频）自主完成，不 AskUserQuestion 中断。无机会时自主决策树：① 换标的（hot_list 刷新找活跃标的）；② 降频（整个市场无活跃机会时放宽采样间隔）；③ 持续盯到收盘 / 用户喊停。
3. **质量优先**：开仓必须过两道闸（🟢 高置信 + 初始预期赔率 ≥ 1.2，见 `references/trading-strategy.md`「开仓基准」「置信度分级」），不达标就不开仓、宁可观望整场。
4. **记录到 `actions/` 目录（复盘基准）**：下单成功后 `log_action.sh` 写交易动作到 `actions/YYYY-MM-DD-<market>-actions.md`（港股 HKT / 美股 ET）。记录必含：时间（精确到秒）、标的、动作类型（开仓 🟢 / 平仓 🔴 / 移损 🟡）、方向、量、参考价、止损价、止盈目标价（预期值，不设止盈条件单）、单笔预算、预估 max_loss、置信度、依据、下单结果（order_id、成交价）。
5. **复盘由用户指令触发、盘中不复盘**：只有收到用户明确的复盘指令才做复盘。
6. **AI 职责边界**：分析、盯盘、算仓位 / 止损价、下单执行、记录动作。**不记账、不实时算盈亏**（复盘时再算）。
7. **持仓状态从脚本输出跟踪**：AI 调用开仓 / 平仓脚本后，从脚本 JSON 输出获取 order_id 和成交价据此确定持仓状态——不需要假设、不查 positions。
8. **零额外延迟**：盘中盘面秒变，所有准备工作（汇率、标的分类、quote 实价）前置到盯盘启动时做好，盘中只做「拿最新数据 → 算 → 执行」，零额外查询。

## 硬性护栏（下单前逐条自检，违反不得下单）

1. **单笔预算与 max_loss（固定比例动态下注）**：单笔预算 B = `risk_fraction`（2%）× 当前 equity，max_loss = 仓位 × 每股止损距（围绕 B 选最近、可略超或略低，但不可超 `equity × f_max` 硬上限 2.5%）。止损位 = 趋势反转位 = 逻辑失效点（做多跌破 VWAP / 企稳支撑、做空站上 VWAP / 阻力），**不要用远技术位、不要用百分比机械算**——会让持仓逆势抗跌大亏。选仓位按 lot_size 离散候选里「实际 max_loss 最接近 B」的那档。**详细概念区分（B vs M）、选仓位算法、f_max 兜底、美股换算、权益更新、利润 = R × max_loss、杠杆对 R 的影响见 `references/risk-management.md`。**
2. **止损用附加止损单，一律市价（主单 + 附加 STOP_LOSS，主单成交才激活——2026-07-31 用户新规）**。下单必须分清两类订单：**主订单**是开仓单（做多 Buy / 做空 Sell，建立仓位）；**附加订单**是主单的附属、不能单独发起、只能跟随主单一起提交——主单「已提交未成交」时附加订单处于「未提交」状态，主单成交后附加订单才转为「监控」状态（监控价到触发价即自动市价下单）。**止损单默认就和主单反向（券商设定），不存在「反向止损单」这种说法**；长桥里止损单属于附加订单范畴（App 可见），老虎里直接叫「止损单」、语义等同附加订单（详见 `references/account-tools.md`「主订单 vs 附加订单」）。
   - **开仓**：REST 一次提交主单（LO）+ `attached_params`（`attached_order_type=STOP_LOSS` + `stop_loss_price` + `activate_order_type=MIT`）。附加止损随主单提交、主单成交才激活，开仓失败止损不残留；STOP_LOSS 语义自动定向、无需 `trigger_direction`（SDK MIT 默认触发方向不能直接做止损，详见 `references/account-tools.md`）。SDK `submit_order` 不支持 `attached_params` 故走 REST。
   - **禁止限价止损**（LO / STP_LMIT / SLO）：止损单一律市价（MIT / STOP_LOSS 触发后市价成交）。本 skill 提到「止损单」默认指市价止损单；`move_stop` 移损新增的止损单也一律用市价止损单。
   - **禁止用一笔反向的主订单去给另一笔已成交的主订单做止损**：止损只能用止损单（附加止损单），不能用反向的主订单——主订单是开仓单、会开新仓，不是了结仓位。
   - **触发价 = 目标止损价**（允许小范围偏差）；用户也会在 App 手动新增止损单，故最新止损价不能凭记忆，`monitor_segment.py` 每轮采样查账户当日订单获取最新止损价。
   - ⚠️ **代码现状（待办）**：`open_position.py` 目前仍是「先挂止损单 → 再下开仓单」两步实现（确保无裸奔空窗、开仓失败撤止损），尚未迁移到 `trade_utils.submit_order_with_stop`（主单 + 附加一次提交）。护栏规则以附加订单为准，代码迁移属待办——迁移前实跑 `open_position.py` 走的是两步。
3. **AI 直接下单**：港股默认用老虎开放平台模拟账户、美股默认用长桥模拟账户，AI 拍板后调用对应脚本直接下单（限价单 + 止损条件单）。如用户不使用默认账户会特别说明。
4. **开仓前 `quote` 确认实价**作参考价。脚本返回 order_id 即确认成交。
5. **不记账**：交易动作记录到 `actions/` 目录，不算实时盈亏；复盘时统一算当天盈亏。
6. **一次最多持仓一个标的（硬规矩）**：AI 自我约束——当前已有持仓时，不开新标的仓。持仓时只能平仓或移损（禁止加仓减仓）。**平仓后，脚本自动撤销所有未触发止损单**（`close_position.py` 内置，2026-07-06 教训：残留条件单下次开盘误触发）。
7. **标的范围：仅个股（含 ADR）+ ETF，禁止衍生品**（期权 / 窝轮 / CBBC / 期货）。港股偏好 ETF（免港式印花税，仅港股；美股无此优势）。杠杆 / 反向 ETF（含 2x/3x）允许；**所有 ETF 都可交易，没有黑名单/白名单限制**。**开仓初始止损按预判趋势反转点定；持仓中按「止损单的两种用法」（锁利 / 放趋势反转位）管理**——3x ETF 波动大，其反转位在价格上天然更远，但不套百分比。下单前必跑 `classify_hk_security.py` 判定类型（目的是排除衍生品，不是筛 ETF）。**标的判定的四层启发式、REIT 判定、代码格式、做空能力查询见 `references/account-tools.md`。**
8. **港股每手股数是硬约束**：下单量必须是整手倍数，否则报 602001。建仓前富途快照查 `lot_size`（中芯 500/手、小米 200/手、腾讯/美团/领展 100/手）。**tick size 等价位规则见 `references/risk-management.md`「港股价位 tick size」。**
9. **交易动作与盯盘时段——三类动作只在盘中执行**：开仓 🟢、平仓 🔴、移损 🟡 只能在盘中执行，盘前、盘后、夜盘一律不执行，盯盘也只在盘中进行。**港股**盘中（北京 09:30-12:00 / 13:00-16:00，港股交易日），港股没有盘前 / 盘后 / 夜盘，午休 12:00-13:00 不可交易。**美股**盯盘窗口 = 美东 09:30-16:00（夏令时北京 21:30-次日 04:00 / 冬令时 22:30-次日 05:00）。**盯盘靠用户指令启动、AI 不自主启动**：盘前启动时只做准备（preflight、方向研判、hot_list），不执行交易动作，等开盘后才执行。**不跨市场**：同一时刻只盯一个市场。**早盘开盘首小时只观察不交易**：港股 09:30-10:30 HKT / 美股 09:30-10:30 ET，不发任何交易动作（不开仓、不平仓、不移损），只观察和判断当日行情性质（震荡日还是趋势日？多头还是空头？），用这一个小时的数据（价格走势、量价配合、资金流、VWAP 方向）定当日基调，10:30 之后才允许开仓交易。如果用户在 10:30 之后才让开始盯盘，则先把前一个小时的数据（kline / monitor_summary / 资金流）分析一遍，完成行情性质判断后再进入正常盯盘交易流程。
10. **开仓 / 平仓触发**：① 开仓必带止损条件单（脚本自动设置，止损单用市价单）；② 平仓在动能减弱 / 做空时回踩前低不破（下跌动能衰竭）/ 做多时回踩前高遇阻（上涨遇阻）/ 做空时资金流转正（买盘涌入）/ 做多时资金流转负（卖盘涌出）/ 到硬平仓时点时由 AI 调脚本执行；③ AI 最高频盯盘，触发条件一到立即执行，出手要快。

## 时点平仓与停止盯盘约束

盯盘收到用户指令后持续盯，**没让停就不停**——美股盯到**用户发出停止盯盘指令**或**美东 16:00 收盘**（取先到者，用户大概率北京晚上睡觉前喊停），港股则撞上下面两个强制终止边界。**无论哪个时点停止盯盘，停前都必须主动平仓——不存在留单**（停盯前一律主动平仓离场）。⚠️ **港股两个边界都是「终止盯盘」、不是暂停——终止后一律不自动恢复，即便午市 13:00 开盘也不自动续盯，须等用户再次下达盯盘指令才重新启动**。美股不设固定终止时点，由用户喊停决定（16:00 收盘兜底）。

📌 **持仓不过夜纪律**：所有持仓在当日停止盯盘前（港股 12:00 午休前 / 港股 16:00 收盘前 / 美股用户喊停或 16:00 收盘前）由 AI 主动平仓了结。这是 AI 主动平、不是账户强平。止盈决策在「当日了结、停盯前主动平」框架内：① 止盈位要在当日停止盯盘前可达，否则停盯前主动按市价平掉；② 不存在留单——停盯前一律主动平仓离场。「不过夜」按交易日判：持仓在该市场当日停止盯盘前了结、不跨到下一交易日。

| 边界 | 时点 | 必做动作 |
|---|---|---|
| **港股午休前** | 北京 12:00（早市收盘） | **平掉所有港股持仓 + 终止盯盘**。午休 12:00-13:00 无法交易 / 执行止损，持仓过午休等于裸奔（13:00 开盘可能跳空、午休期间止损单不触发）。**13:00 午市开盘不自动恢复盯盘**——午市要盯须等用户再次下达盯盘指令。 |
| **港股收盘前** | 北京 16:00（港股收盘） | **主动平掉所有港股持仓 + 终止盯盘**，当日港股彻底结束。临近 16:00 的策略分情况（见 `references/trading-strategy.md`「临近停止盯盘的分情况策略」）：有持仓——出现很好的主动平仓机会就主动平（剩余时间不多、不平则收益跌下去没时间再涨）；趋势仍健康可持有到收盘前再主动平。无持仓——临近收盘开仓要小心，剩余时间少意味着赔率可能受限。 |
| **美股停止盯盘前** | **用户发出停止盯盘指令的时刻**（大概率北京晚上睡觉前），或美东 16:00 收盘（取先到者） | **主动平掉所有美股持仓 + 终止盯盘**。⚠️ **不存在留单**——停盯前一律主动平仓离场。用户大概率在北京晚上睡觉前发停止盯盘指令（对应美东盘中某时刻，夏令时约美东 11:00-12:00 / 冬令时约 10:00-11:00），届时停前主动平；少数情况用户不喊停，则盯到美东 16:00 收盘、收盘前主动平。**停盯前必过 `references/trading-strategy.md`「临近停止盯盘的分情况策略」检查**：若**浮盈大 + 加速赶极端**（做多：加速赶顶 = 加速上涨 + 破前高 + 远离 VWAP 上方超买；做空：加速赶底 = 加速下跌 + 破前低 + 远离 VWAP 下方超卖 = 动能将竭）→ 立即主动平仓 🔴 锁利（2026-07-17 MU 教训：浮盈 +$3071、加速赶顶却误判「持续上涨」、最终回吐 ~$2000；盘中任何时候动能将竭就该主动平、不等停盯）。 |

⚠️ **跨境 / 杠杆 ETF 午休跳空风险尤其大**：跟踪**境外标的**的港股 ETF（如 07709 两倍做多海力士、07747 两倍做多三星电子——跟踪韩国股市），**韩国股市中午不休市**（韩国 09:00-15:30 连续交易），港股午休 12:00-13:00 期间境外标的仍在交易、价格持续变化，而港股 ETF 此刻既无法反应、也无法止损。一旦境外标的大跌，13:00 港股开盘 ETF 跳空下跌、止损单来不及触发。故这类跨境 ETF **尤其**必须在 12:00 前平仓，跳空风险比纯港股标的（自身也午休的）大得多。

盯盘临近停止盯盘时点（港股 12:00 午休前 / 港股 16:00 收盘前 / 美股用户喊停或 16:00 收盘前）都要**主动提前处理**仓位——停前一律主动平仓、不留单，别等到点被动；时点一到即停止盯盘，不拖。港股实际可交易窗口：早市 09:30-12:00（**12:00 午休前必须平**）、午市 13:00-16:00（**16:00 收盘前必须平**，所有港股持仓）。

## 盯盘工作流（高层骨架）

盯盘标准启动序列：**`preflight` → 方向研判 → `hot_list` 找标的 → `static` + `classify` 核实标的 → `snapshot` + `kline` 分析 → `monitor_segment` 密采样盯盘 → 段结束通知驱动循环 → 撞上终止边界或用户喊停 → 停盯总结**。

1. **preflight**（`scripts/preflight.py`）：时间 / 港股美股时段 / 富途 OpenD 端口 / 当日交易动作文件（`actions/`）+ equity / 自动启用 caffeinate 防系统睡眠。**先跑这个**。
2. **方向研判**（盯盘第一步定当日基调）：五维度（宏观基调 / 技术趋势 / 量价 / 资金流 / 事件催化）独立打分 + 位置评估（当前价在大趋势的上沿超买 / 下沿超跌 / 中段），产出「今日偏多 / 偏空 / 中性震荡」+ 盘中方向假设。
3. **hot_list**（`scripts/hot_list.py HK 15`）：热度榜 + 叠 snapshot 查成交额 / 振幅 / 换手，找标的铁律第一步——不许凭关注列表或 AI 记忆直接定标的。
4. **核实标的**：`snapshot` + `classify_hk_security.py` 查代码真身与类型（etf / stock / reit）。
5. **分析**：`snapshot`（现价 / OHLC / lot / 成交额 / 振幅 / 买卖比 / 量比）+ `kline`（近 N 日 K 线 + 斐波那契回撤）+ `monitor_summary`（全貌摘要 + VWAP + 行情性质判别）。
6. **监控循环**：`monitor_segment.py` 后台分段密采样（每段 40 秒、10 秒间隔），段结束 task-notification 唤醒 AI → 三层分析（全貌摘要判行情 + log 最近 N 行看即时 + 做空 checklist + 每 10 分钟方向重估）→ 重启下一段。AI 自主循环，不中途停下问用户。
7. **停盯**：撞上终止边界或用户喊停 → 主动平仓 + 停盯总结。

**所有采样机制（后台采样不间断规矩、采样链防中断三件套、时间断层哨兵）、方向研判详细打分表与位置评估表、脚本库完整用法与参数、采样频率工程参数（40 秒 / 10 秒、为什么不用 cron、突破即时响应、不因市况降频、标的不值得密盯时优先换标的、密采样定义 + 早盘必密）、VWAP 必看、被打断就跳过、盘前预热、重要数据日 WebSocket、开盘前验证 OpenD、盯盘对话输出精简规则见 `references/monitoring.md`。**

AI 调用脚本下单后，脚本 JSON 输出 order_id 和成交价，AI 据此记录动作文件并按成交价继续盯盘。若脚本报错（价格不在范围内 / API 错误），AI 据错误信息调整策略。持仓状态从脚本输出跟踪，不需要假设。

## 停盯总结（盯盘结束即时小结）

**停盯第一个动作——解除防睡眠**：盯盘预热（preflight）已自动启用 `caffeinate -s` 防系统睡眠（无论开盖合盖、不询问），故停止盯盘时（用户喊停 / AI 仅在快休市或收盘时才自主停——其余时段持续盯、不收尾）AI **必须自己**跑 `bash .claude/skills/keep-awake/scripts/off.sh` 解除防睡眠。用户**不会**主动说「解除防睡眠」——AI 自主在停止盯盘时收尾，避免长期持 `PreventSystemSleep` assertion。

盯盘结束时，AI 主动给一份**当日小结**，区别于复盘分析（见 `references/review-and-evaluation.md`，由用户指令触发、更详细）。**停盯总结必含每笔的赔率三阶段（初始预期 / 修正预期 / 实际落地）**，不只是盈亏金额：

- **三阶段赔率**（总结必全列）：① **初始预期赔率**（开仓前、参考价算）② **修正预期赔率**（开仓后、实际成交价算）③ **实际落地赔率**（平仓后、实际盈亏 ÷ 实际 max_loss，即 R-multiple，$R_i=P_i/M$；max_loss 用开仓时止损距离反推的风险额度 = 仓位 × 止损距离，移动止损不改开仓 max_loss 基准）。**三阶段定义见 `references/trading-strategy.md`「赔率三阶段」。**
- **盈亏与实际落地赔率用实际成交价算**（开仓成交价、平仓成交价都是脚本返回的真实成交价，不是参考价）。
- 每笔报：标的、方向、开仓参考价、开仓成交价、平仓成交价、实际盈亏金额、max_loss、**三阶段赔率（初始预期 R / 修正预期 R / 实际落地 R）**；多笔再给**整体实际落地赔率**（总盈亏 ÷ 总 max_loss）。三阶段并列表能直接看出「预估→修正→落地」的打折程度（如 2026-07-23 阿里 2.30→2.00→0.82R、中芯 3.21→2.20→0.48R）。
- **为什么必列三阶段**：盈亏金额看不出「承担了多少风险换来的」——同样赚 5000，max_loss 5000 是 1R、max_loss 10000 只算 0.5R；而单看实际落地赔率又看不出「预估乐观但落地打折」（初始预期赔率 2.3R 实际落地赔率只剩 0.82R）。三阶段并列表才能既看真实性价比、又看预期兑现度，暴露「赚了钱但赔率低」和「预估乐观但没让利润奔跑」两类问题。**所有数值用 Python 实算，不心算**（遵守「第一原则」）。

## 复盘分析（收到用户复盘指令时做）

**触发**：只在收到用户明确的**复盘指令**时做。盯盘期间专注盯盘、**不自主复盘**（见「自动交易模式总则」操作原则第 5 条）。**所有数值用 Python 实算，不心算报数**（遵守「第一原则」）。

**数据源**：`actions/` 历史交易动作记录（港股 `actions/YYYY-MM-DD-HKT-actions.md`、美股 `actions/YYYY-MM-DD-ET-actions.md`），逐笔算参数（入场价 / 止损 / 盈亏 / R-multiple）。

**复盘工具**：`python3 scripts/review.py <trades.csv>` 一次性输出全套指标（样本明细、终局统计量、过程指标分盈亏单、贝叶斯 P(EV>0)、频率派 CI、样本量规划）；`python3 scripts/bayes_evolution.py` 输出 7 张序贯演化图。复盘产物放 `reviews/`（报告 `reviews/YYYY-MM-DD-review.md` + 同日 csv/png）。

**详细方法论见 `references/review-and-evaluation.md`**（收到复盘指令时读它）：统计量定义与推导（EV 分解合并恒等、MAE / MFE / 回吐 / 锁利效率 η）、7 张序贯演化图的必含规范、样本量规划、多层评估框架。盯盘时不必读、复盘时按此逐项统计。

**📊 读图纪律（省 token）**：复盘分析**以 `review.py` + `bayes_evolution.py` 的终端数值输出为依据**——两脚本在终端已 print 每笔序贯数值（胜率 / P(EV>0) / 累计均值 / EV 95% CI）与终局多 f 表，覆盖 7 张演化图的全部关键信息，看数值即可写「分阶段解读」与「终局表」。**演化图是复盘报告的必含产物**（写给用户看、嵌入报告），但 **Claude 默认不把 png Read 进上下文**——每张图按分辨率约 1500–2000 tokens、7 张上万，读图性价比远低于看终端数值。**只在终端数值看不出某个趋势拐点、确需肉眼确认时，才按需读单张 png**。

## 开仓前自查清单

开仓前逐条过：

- [ ] **恢复协议 + 下单硬前置已过（最高优先级、首检项）**：距上次 `date` ≤ 2 分钟 且 距上次 `snapshot`（该标的）≤ 2 分钟？若任一 > 2 分钟，或本 session 经历过断网 / 暂停 / 工具故障 / 会话压缩 → **先跑 `python3 scripts/resume.py [标的]` 重建上下文 + 刷新现价**，再下单。参考价过时 = 下单基准错 = 实亏（2026-07-28 中芯事故教训），**禁止用过时数据下单**。
- [ ] 标的已富途快照查 name 确认？跑 `classify_hk_security.py` 判定为 etf / stock / reit（含杠杆 / 反向 ETF）且 confidence=high？港股优先 ETF（免印花税，仅港股；美股不适用）？
- [ ] 近 5 日趋势看过？顺势？
- [ ] **全貌 + VWAP + 位置 + 形态硬闸（开仓前必做、缺一不发）**：
  - **① 跑 `monitor_summary.py` 看全貌**：当日开 / 现 / high / low / 振幅、箱体顶 / 底各测试几次、买卖比与量比的前半→后半演变、**行情性质判别（震荡 / 多 / 空 / 中性）**——「判断震荡还是趋势必须看全貌、最近 N 分钟看不出」（2026-07-23 教训）。**没跑全貌 = 不知行情性质 = 不发**。
  - **② 看 VWAP**（snapshot 的 `avg_price` 字段）：价格在 VWAP 上方 = 多头占优、下方 = 空头占优；VWAP 震荡向上 = 多头趋势日、向下 = 空头趋势日；低开高走 + 站上 VWAP = 多头反弹日。**开仓前必须明确「价格相对 VWAP 位置 + VWAP 趋势」**——不看 VWAP = 可能把反弹日当震荡日、方向做反。
  - **③ 位置评估硬闸**（拉 4 个月日线 kline 判当前价在大趋势的位置，见 `references/monitoring.md`「位置评估」）：**下沿（超跌区）→ 做多假设（等企稳做多、不空）**；**上沿（超买区）→ 做空假设（等遇阻做空、不多）**；中段 → 顺势。**逆位置不开仓**（下沿做空 = 接飞刀、上沿做多 = 摸顶）。⚠️ **「下沿不空」精确边界**：「下沿不空」指不在**恐慌急跌点**空（接飞刀反面、易被 V 反弹扫损）；但若下沿出现**反抽阻力明确乏力**（反抽多次不过 + 买卖比大负 = 机构出货），则「反抽阻力位乏力遇阻」做空入场**仍成立**——这是顺势做空、不是接飞刀。一句话：下沿**恐慌急跌点**不空，下沿**反抽阻力乏力**可空。2026-07-28 反面教训：兆易 480 反抽两次不过 + 买卖比 −54（机构卖），AI 误把「下沿不空」当绝对禁令、却一直等企稳做多，错过 R 2.8 顺势做空（后实际跌到 466/456）。
  - **④ 做空必须等做空形态**（双顶 / 头肩顶 / 反抽阻力位乏力遇阻 / 跌破支撑后反抽该支撑遇阻），**不在潜在反弹底（双底 / 头肩底 / 暴跌低点）空**——那是做多位置；做多同理必须等做多形态（回踩企稳 / 突破回踩；**暴跌低点必须等双底 / 头肩底、禁企稳抄底**，见 `references/trading-strategy.md`「做多合格入场只有两种」+ 2026-07-29 07709 教训），不在潜在顶部多。⚠️ 中芯 07-27 反面教训：暴跌低点 68.05 反抽未到阻力（70）就在 69.1 空 = 接飞刀 + 逆下沿位置 + 没做空形态，被 V 反弹扫止损 −1R；当时只看资金流出一维、漏了位置 + 形态 + 全貌 + VWAP，误给 🟢 高置信——**资金流再强也不抵逆位置 + 无做空形态**。
- [ ] **EV 判据：胜率 > 50% 且 初始预期赔率 ≥ 1.2**（初始预期赔率 = 止盈距离 ÷ 止损距离 = |止盈−参考价| ÷ |参考价−止损|，止盈距离 ≥ 1.2 × 止损距离）？初始预期赔率 < 1.2 不开仓。止损按趋势反转位 = 逻辑失效点定（禁止百分比）。**详细见 `references/risk-management.md`「止损位 = 趋势反转位」+ `references/trading-strategy.md`「开仓基准」。**

## 🔒 盯盘恢复协议（Resume Protocol，最高优先级）

盯盘要求**连续**（盘面秒变、决策时效以秒计），但执行环境会**断层**——断网、用户主动暂停再重启、工具故障 / 分类器不可用、会话压缩、长任务占用，任一都可能让 AI 失去时间感知 + 数据过时 + 上下文丢失。**最危险的是用过时数据做「看起来成立」的交易决策**（参考价过时 = 下单基准错 = 实亏）。

**总则：AI 的内存（对话上下文）不可信，文件才是地面真相。任何时候重新获得执行权，第一动作是从文件重建状态、刷新数据，绝不用断层前的旧数据下单。**

### 触发条件（任一即跑恢复协议，作为第一动作）

- 收到用户消息唤醒（尤其「继续盯盘 / 继续」类重启指令）
- 后台采样段结束通知唤醒、但距上次段结束明显偏久
- 工具故障 / 分类器不可用 / 断网恢复后
- 会话被压缩、长任务结束后回来
- 自己察觉距上次 `date` / `snapshot` 可能过了较久

**一句话：只要不是连续顺畅的段间循环（段结束 → 读数 → 重启下一段），就先跑恢复协议再继续。**

### 恢复协议五步（封装在 `scripts/resume.py`，跑一次即可）

`python3 scripts/resume.py [标的1,标的2,...]`（可选标的 = 额外 snapshot 刷新现价，如持仓标的）：

1. **`date` 核实真实时间 + 算「距上次活动的时间差」**——上次活动时间 = `tmp/monitor_log_*.csv` 最后采样时间；距现在 ≥ 5 分钟 → 输出 ⚠️ 断层警告。
2. **判市场状态决定能否下单**：港股盘中（北京 09:30-12:00 / 13:00-16:00）或美股盘中（美东 09:30-16:00）才允许下单；盘前 / 盘外 / 收盘后停止盯盘，不下单。
3. **从文件重建上下文**（不靠内存）：读今日 actions 文件（`actions/YYYY-MM-DD-<market>-actions.md`）确认当前持仓状态（开仓记录 + 入场价 + 止损 + 止盈）；读 `actions/equity-log.csv` 末行确认当前 equity（算单笔预算 B）。
4. **`snapshot` 刷新所有相关标的现价**——断层前的价一律作废。
5. **处理断层期间的持仓变化**：断层期间持仓可能被动触发止损（现价越过止损位）→ 标注「大概率被动触发、待盘后回查确认」，盘后用历史 K 线精确回查、更新 equity。

### 交易决策硬前置（针对过时数据做决策的补丁）

开仓前强制检查：

- 若**距上次 `date` > 2 分钟** → 重新 `date` 核实时间；
- 若**距上次 `snapshot`（该标的）> 2 分钟** → 重新 `snapshot` 取最新价当参考价；
- 不满足 → **禁止开仓**，先 `date` + `snapshot` 刷新再开。

这条与「第一原则·汇报当前时间 / 盘面时点前 date 实测」互补：参考价过时 = 下单基准错 = 实亏。时间断层哨兵等采样机制细节见 `references/monitoring.md`「时间断层哨兵」。
