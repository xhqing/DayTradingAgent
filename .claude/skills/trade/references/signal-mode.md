# 信号模式（signal-mode，详细参考）

> 本文件是 trade skill **信号模式（signal）** 的专属规则。trade skill 默认 auto；当用户明确说「只发信号 / 手动执行 / 不要 AI 下单」时切 signal 模式（见 `SKILL.md`「模式开关与触发首动作」），加载本文件。本文件只在 signal 模式下加载，auto 模式不加载。

## signal 与 auto 的唯一区别 = 是否需要证券账户

signal 和 auto 两种模式**唯一**的区别，就是**是否需要证券账户**相关的规则和动作。除这一类区别外，两种模式的所有规则完全一致：

- **完全一致（共用，不另搞一套）**：三类动作 / 信号的语义（开仓 🟢 / 平仓 🔴 / 移损 🟡，禁止加仓减仓）、一笔交易定义、最多持仓一个标的、平仓行为（主动 vs 被动）、止盈靠两类动作、交易策略与教训（`trading-strategy.md`）、风控与止损位判定（`risk-management.md`）、盯盘机制与采样（`monitoring.md`）、行情数据源（`account-tools.md`，行情部分公共）、复盘方法论（`review-and-evaluation.md`）、时点平仓与停止盯盘约束、做空权限、第一原则（事实验证）、盯盘恢复协议、开仓前自查清单的公共项。
- **唯一的区别（本文件只讲这些）**——都是「要不要碰证券账户」派生的：
  1. **执行**：auto 是 AI 调脚本直接下单 + 挂止损条件单；signal 是 AI 只发信号（响铃 + 写文件），用户拿信号在自家 App 手动执行，AI 不下单、不挂任何条件单。
  2. **持仓跟踪**：auto 从脚本输出的 order_id / 成交价确定持仓；signal 假设执行、不查 `positions`、用户主动告知才据实调整。
  3. **成交价来源**：auto 用脚本返回的真实成交价；signal 用响铃时刻价（响铃后立即 snapshot 取 `last_price`）。
  4. **equity 来源**：auto 从券商账户 API 取真实总资产；signal 因不连真实账户，用 `signals/equity-log.csv` 累加假设盈亏（见下文「signal 模式权益更新」）。
  5. **记录载体**：auto 写 `actions/`（含 order_id、真实成交价）；signal 写 `signals/`（含响铃时刻价、假设持仓）。
  6. **止损单**：auto 由脚本挂附加 / 独立 MIT 止损单；signal 只在信号里算出止损价、提示用户在 App 自行挂，AI 不碰任何条件单。

> 一句话：**signal 模式 = auto 模式去掉「碰账户」的部分，换成「发信号给用户手动执行」**。读本文件前，auto 模式的所有公共规则你都已掌握（来自 `SKILL.md` + 公共 references），本文件只覆盖上面 6 点差异。

## 信号模式总则（最高优先级）

本 skill 处于 **信号模式**：**AI 只发买卖信号、用户手动执行，AI 不管账户、不下单、不核实资金 / 持仓**。AI 不再直接碰任何订单。三类信号（开仓 🟢 / 平仓 🔴 / 移损 🟡，禁止加仓减仓）的语义、止损位判定、策略、风控、时段、复盘全部与 auto 模式一致（见 `SKILL.md` 与公共 references），区别只在「AI 发信号、用户手动执行」。

- **假设执行、不查 positions**：AI 发出任何信号（开仓 / 平仓 / 移损）后，**直接假设用户已按信号执行**（即假设已持仓 / 已平仓），**不查 positions、不等用户反馈**。用户是否真执行是用户自己的事（用户可能不下单，但 AI 当成已成交继续盯）。用户若真实操作致持仓变化，会**临时主动告知**——只有这时 AI 据实调整；用户没说就按假设持仓盯。
- **AI 职责边界**：AI **只负责 ① 发信号 ② 记录 ③ 事后复盘统计（胜率 / 赔率 / EV）**，**不管账户、不下单、不核实资金 / 持仓**。仓位按「单笔预算 B = `risk_fraction` × 当前 equity」选最接近的离散仓位作风控建议（不查实时账户；equity 来源见下文「signal 模式权益更新」）。
- **禁止自动下单**：AI 不得调用任何券商的下单 / 撤单命令（order buy/sell/cancel 等）。所有买卖由用户拿信号后在自家 App 手动执行。
- **禁止设置条件单**：AI 不得挂任何条件单 / 止损单 / 止盈单（MIT / MO / LIT / LO 一律不挂）。止损价只在开仓信号里**计算并告知**，由用户在 App 自行挂止损。
- **信号记录到 `signals/` 目录**（复盘基准）：港股 `signals/YYYY-MM-DD-HKT-signals.md`、美股 `signals/YYYY-MM-DD-ET-signals.md`（港美分开记、文件名带 HKT/ET 时区标识，便于分别复盘）。

## 信号时序总则（写文件 → 响铃 → 取响铃时刻价，三步连贯，最高优先级）

用户**时刻盯会话输出（含 AI 思考过程）**，能预判 AI 即将发信号、预判标的 + 方向 + 参考价，**时刻准备下单**。AI 拍板决定发信号后，按下面三步**连贯执行、中间不插入任何其它动作**（不输出对话关键字段、不算参数、不跑其它查询），几秒内一气呵成——响铃与取价之间零间隔，取到的响铃实测价才能近似用户实际成交价（用户听到铃即下单，取价时刻 ≈ 用户下单时刻）。三步时序：**写信号文件（拍板即写）→ 响铃（用户听到即下单）→ snapshot 取响铃时刻价（成交价）**：

1. **第一个动作：写信号文件**——拍板决定发信号那一刻，立即把完整信号内容（标题 + 表格 + 依据 + 风险提示）经 stdin 传给 `log_signal.sh`，写入对应市场文件（港股 `signals/YYYY-MM-DD-HKT-signals.md` / 美股 `signals/YYYY-MM-DD-ET-signals.md`），标题框线内（标题行后、第二条框线前）自动带发信号时间戳（= 写文件当下时刻，≈ AI 拍板时刻）。**文件先落盘**：响铃时文件已就绪，用户听到铃即可从文件读到完整字段（参考价 / 止损）下单。**用户 App 挂止损 / 止盈、复盘查字段都看信号文件**。
2. **第二个动作：立马响铃**——写完文件立即调 `ring.sh`（只响一声对应类型提示音 + 记响铃时刻到 `signals/ring-log.csv`，时间精确到秒）。用户听到铃 = 认定 AI 拍板了（标的 + 方向从思考过程已知），立即开始下单。
3. **第三个动作：立马 snapshot 取响铃时刻价**——响铃后立即用 `get_market_snapshot` 的 `last_price` 取当前价，作为响铃实测价（成交价近似），并把实测价以一行注释 append 到该条信号末尾（形如 `> 响铃后成交价：$P（HH:MM:SS 取价时刻）`）。取价紧跟响铃之后（T0+几秒内）。

**三步连贯铁律（2026-08-02 用户立）**：写文件 → 响铃 → 取价之间**不得插入任何其它动作**——不输出对话关键字段、不算参数、不跑 monitor_summary / 其它查询，一步接一步连续执行。若中间插入其它动作，响铃与取价之间产生间隔，取到的价就不是「响铃时刻价」、与用户实际成交价偏差变大，复盘盈亏失真。某步工具调用失败 → 立即修正重做后继续下一步，同样不插入其它动作。

**为什么写文件最先、且与响铃 / 取价分离**：原 `alert.sh`「写文件 + 响铃」二合一，写文件（构造完整 markdown）有延迟、会让响铃滞后几秒～十几秒；拆分后写文件（`log_signal.sh`）、响铃（`ring.sh`）、取价（snapshot）三步各自独立、连贯执行——写文件先落盘（信号内容有据可查、响铃时文件已就绪），响铃让用户听到即动，取价紧跟响铃拿成交价近似，三步紧凑无间隔（2026-08-02 用户立，取代 2026-07-29 的「响铃最先 → 取价 → 写文件」时序）。

**`log_signal.sh` 调用方式**（第一个动作，信号内容经 stdin 传入，写文件 + 时间戳）：

```bash
cat <<'SIGNAL' | bash .claude/skills/trade/scripts/log_signal.sh <market>
## 🟢🟢🟢 开仓 · <标的代码> <中文名> · 做多/做空 🟢🟢🟢
（完整信号内容：标题 + 表格 + 依据 + 风险，复盘用、也是用户挂止损/查字段的来源——对话不再单独输出关键字段；「成交价」栏写「响铃后取价」占位，响铃取价后 append 实测价到该条末尾）
SIGNAL
# market=HKT/ET（决定写到哪个信号文件，必填）
```

**`ring.sh` 调用方式**（第二个动作，响铃 + ring-log）：

```bash
bash .claude/skills/trade/scripts/ring.sh <type> [symbol] [note]
# type=open/close/ts（决定音色）；symbol/note 可选，写入 ring-log 备查
```

⚠️ **脚本校验**：`ring.sh` 缺 `type` 时报错退出；`log_signal.sh` 信号内容为空 / 缺 `market` / `market` 非 HKT/ET 时报错退出、不写文件——发信号时看退出码与 stderr 报错确认。

⚠️ **`alert.sh` 已弃用**：原「写文件 + 响铃」二合一脚本 `alert.sh` 已弃用（调用即报错提示用 `ring.sh` + `log_signal.sh`）；本 skill 内所有引用 `alert.sh` 的旧描述以本段新时序为准。

### 响铃时刻价直接当成交价（取消价格范围与成交判据）

响铃是用户开始 App 操作的时刻，响铃时刻的市价 ≈ 用户实际成交价。**响铃实测价是确定成交价、算实际 max_loss / 修正赔率、决定后续盯盘逻辑（持仓盯止损 vs 空仓找机会）的唯一依据——不取 = 信号悬空、不知成交价、持仓状态无法确定**。故响铃后**必须立即用 snapshot（`get_market_snapshot` 的 `last_price`）取实测价**——取价紧跟响铃之后（T0+几秒内，时序第 3 步；三步连贯、中间不插任何动作，保证取到的是响铃时刻价）。取到后把实测价以一行注释 append 到该条信号末尾（形如 `> 响铃后成交价：$P（HH:MM:SS 取价时刻）`——标注取价时刻、非严格响铃时刻）。**写文件（第 1 步）时响铃实测价还没取到，表格「成交价」栏先写「响铃后取价（见该条末尾注释）」占位**，取价后立即 append 实测价到该条末尾——复盘 / 挂止损查成交价看该注释。

- **成交价 = 响铃时刻价，不算价格范围、不判开仓失败**：用户听到铃立马下单（市价或近市价限价），实战下单来不及核对「成交价是否落在某个理论区间」。故响铃时刻价（实测价）直接作为该笔的成交价，用它算实际 max_loss（= 仓位 × 按实测价的每股止损距）、修正赔率（按实测价重算止盈距 ÷ 止损距）、浮盈盯盘。**不再有「开仓失败」判定**：只要用户按信号下了单、响铃时刻价取到了，就假设按该价成交；若用户实际没下单或没成交，用户会主动告知，AI 据实调整——默认假设按响铃时刻价成交。
- **取实测价的操作禁忌**：响铃后取实测价**只用 snapshot（`get_market_snapshot` 的 `last_price`）**，**绝不调 `request_history_kline`（历史 K 线接口）**——该接口对美股 1 分钟 K 偶发卡死（与 `capital_distribution` 同类坑），调用会占用会话 120 秒+。响铃后必须立即用 snapshot 取；若响铃当时漏取，事后复盘时再回查历史 K，不在盘中调。

## 三类信号格式（与 auto 三类动作对齐，禁止加仓减仓）

signal 模式只发**三类信号**：开仓 🟢 / 平仓 🔴 / 移损 🟡。**禁止加仓 / 减仓**（与 auto 模式一致，不复活旧信号模式的加仓 🔵 / 减仓 🟠）。一个标的最多一笔持仓（禁止加仓 → 不存在批次概念），平仓即清空。

**信号 emoji**：开仓 🟢 / 平仓 🔴 / 移损 🟡（与 auto 动作 emoji 完全一致）。

**表格格式规范**（与 auto 动作记录一致）：表格内不放装饰性 emoji，字段名用纯文字；圆形彩色 emoji（🟢🔴🟡）可在表格内用于信号类型标记；只有开仓信号的参考价和止损价加粗显示。每条信号**表格前**加「框线 + 3 个圆形同色 emoji + 标题 + 3 个同色 emoji + 框线」醒目装饰，再接表格。

**字段与 auto 开仓动作完全一致**，唯一区别是「成交价」来源：auto = 脚本返回的真实成交价，signal = 响铃时刻价（响铃后 snapshot 取 `last_price`）。

**开仓信号 🟢**：

```
════════════════════════════════════
🟢🟢🟢 开仓 · <标的代码> <中文名> · 做多/做空 🟢🟢🟢
════════════════════════════════════
```

| 项 | 值 |
|---|---|
| 方向 | 做多/做空 |
| 量 | N 股 |
| 参考价 | **$X**（App 限价，**加粗**）|
| **成交价** | **$P**（**响铃时刻价**：写文件时先写「响铃后取价」占位，响铃（第 2 步）后立即 snapshot 取 `last_price`（第 3 步）并 append 到该条信号末尾，非参考价；用它算实际 max_loss / 修正赔率 / 浮盈盯盘）|
| 止损 | **$Y**（App 挂止损，**加粗**）|
| 止盈 | $Z（止盈目标价，开仓时必须定，预期值不设条件单）|
| **初始预期赔率** | **R 倍**（≥1.2 才发；响铃后按实测成交价重算修正预期赔率）|
| 单笔预算 | $B（= risk_fraction × 当前 equity）|
| 预估 max_loss | $M（= 仓位 × 每股止损距，按参考价；响铃后按实测价修正）|
| 置信度 | 🟢高（开仓只发高置信，🟡中 / 🔴低不发，见 `trading-strategy.md`「置信度分级」）|
| 依据 | 顺势 + 资金流 + EV 一句话 |

**平仓信号 🔴**：

```
════════════════════════════════════
🔴🔴🔴 平仓 · <标的代码> <中文名> · 平多/平空 🔴🔴🔴
════════════════════════════════════
```

| 项 | 值 |
|---|---|
| 标的 | 代码 中文名 |
| 方向 | 平多 / 平空 |
| 参考价 | $X |
| 理由 | 动能减弱 / 做空时回踩前低不破（下跌动能衰竭）/ 做多时回踩前高遇阻（上涨遇阻）/ 做空时资金流转正（买盘涌入）/ 做多时资金流转负（卖盘涌出）/ 到硬平仓时点（止损 / 止盈被动触发不发此信号、只标记）|

**移动止损信号 🟡**（浮盈中上移锁利，提示用户在 App 调整止损）：

```
════════════════════════════════════
🟡🟡🟡 移动止损 · <标的代码> · 新止损 $Y 🟡🟡🟡
════════════════════════════════════
```

| 项 | 值 |
|---|---|
| 标的 | 代码 中文名 |
| 新止损 | $Y（提示用户在 App 改挂：撤旧止损单、挂新止损单）|
| 浮盈 | +$M |
| 理由 | 锁利 / 保本（动态权衡锁利大小与赔率，见 `trading-strategy.md`）|

> 移损信号只给新止损价 + 提示用户在 App 调整。auto 模式的「先新增后撤旧」是脚本的 API 操作，signal 模式不涉及（撤旧挂新由用户在 App 完成）。

## 信号输出与持仓检查

**发信号三步连贯执行：第一个动作 = 写信号文件（`log_signal.sh`），第二个 = 响铃（`ring.sh`），第三个 = snapshot 取响铃时刻价**：三步之间不插入任何其它动作（不输出对话关键字段、不算参数），几秒内一气呵成——取价紧跟响铃、零间隔，取到的实测价才近似用户实际成交价。用户下单靠「听到铃」（秒级，标的 + 方向从思考过程预判，听铃时信号文件已就绪、可从文件查参考价 / 止损），信号文件用于复盘 + 用户挂止损参考。对话**不输出关键字段**（完整字段在信号文件）。

**持仓检查（positions）：signal 模式下假设执行、不查**——按「信号模式总则」，AI 发信号后**假设用户已执行、不查 positions、不等反馈**（用户若真实操作致持仓变化会主动告知，那时才据实调整）。

- **不记账、不算实时盈亏**（不写 `ai_trade_ledger.csv`；复盘时统一算）。
- **三类信号都支持**：开仓 🟢、平仓 🔴、移损 🟡（均按三步连贯时序：第一个动作 `log_signal.sh` 写文件、第二个 `ring.sh` 响铃、第三个 snapshot 取响铃时刻价并 append 到该条信号末尾；三步间不插入其它动作；对话不输出关键字段）。

### 主动平仓 vs 被动平仓的信号边界

- **主动平仓 → 发 🔴 平仓信号 + 响铃**（AI 判断动能减弱 / 情况不对 / 到硬平仓时点等，需提示用户现在手动平仓）：三步连贯执行——第一个动作 `log_signal.sh` 写信号文件、第二个立马调 `ring.sh close` 响铃、第三个 snapshot 取响铃时刻价并 append 到该条信号末尾（三步间不插入其它动作）。
- **被动平仓（止损 / 止盈条件单触发）→ 不发 🔴、不响铃**，只 ① 对话简短标记一句（「XX 止损 / 止盈 $Y 触发、成交 ~$Z、亏 / 盈 $M」）② signals 记录写明「触发价 / 盈亏 / 被动平仓」③ **更新 equity 并在信号文件该笔记录末尾 append 当前总资产**（被动平仓也是交易了结、走「signal 模式权益更新」流程）。原因：止损 / 止盈是用户在 App 挂的条件单，触发时 App 自动执行 + 通知用户，AI 发信号发出来时已触发、没有「提示用户去手动执行」的意义。
- **判别**：AI 发出的是「让用户动手平」= 主动 🔴；「用户 App 条件单自己触发了」= 被动 → 只标记。

## 用户执行反馈（假设执行，用户主动告知才据实调整）

AI 不下单，所有订单 / 成交均为用户在 App 操作。**signal 模式下 AI 假设执行、不查 `positions`**（信号模式总则），协作流程：

- **AI 发信号 → 假设用户已执行 → AI 按假设持仓继续盯盘**（不查 `positions`、不等反馈、不记账，复盘时再算）。
- **用户主动告知才据实调整**：用户若真实操作（执行了信号、或自行买卖）致持仓变化，会**临时主动告知** AI；只有这时 AI 据实调整假设持仓。用户没说就按假设持仓盯。
- **用户未按信号执行属正常**（用户有最终决定权）：AI 不告警、不催促，按假设持仓继续盯盘发信号。
- **持仓方向与数量以用户告知为准**：用户告知实际成交后，AI 据其调整；未告知则按开仓信号里的量作假设持仓。

## signal 模式权益更新（equity-log 累加，区别于 auto 的账户 API）

> auto 模式的 equity 从券商账户 API 取真实总资产（见 `references/risk-management.md`「权益更新」）。signal 模式因不连真实账户、无法取真实总资产，改用 `signals/equity-log.csv` 累加假设盈亏——这是 signal 与 auto 在「账户相关」上的固有差异。

**每笔交易了结后**（主动平仓 🔴 清仓、被动平仓止损 / 止盈触发——凡是兑现盈亏的了结动作都算），当前 equity += 本笔盈亏（港股直接 HKD、美股按当日 USD/HKD 汇率换算 HKD），并**同时写两处**：

1. **append 一行到 `signals/equity-log.csv`**（字段 `date, symbol, P_HKD, equity_after, note`，结构化、preflight 读它算 B）；
2. **在该笔了结对应的当天信号文件记录末尾 append 一行当前总资产**（港股 `signals/YYYY-MM-DD-HKT-signals.md` / 美股 `signals/YYYY-MM-DD-ET-signals.md`，形如 `> 当前总资产：HK$98,900（本笔后 equity）`，便于人眼回看每笔了结后的账户总值）。

**当前 equity = `equity-log.csv` 最新行 `equity_after`**（无记录则 = `config.risk.initial_equity`）。权益缩水 → B 自动缩小（复利减速）、权益增长 → B 自动放大（复利加速）。

⚠️ **注意**：signal 模式的 equity 是「假设执行」累加值（用户未必真按信号下单），与 auto 模式的真实账户总资产性质不同——这是 signal 不碰账户的固有代价。复盘时以用户告知的真实成交为准据实修正。

## signal 专属自查条目（开仓前自查清单的 signal 补充）

> 公共自查项（恢复协议前置、标的核实、趋势 / 位置 / VWAP / 形态 / EV / 置信度 / 止损价 / 仓位 / lot_size / 时段）见 `SKILL.md`「开仓前自查清单」。下面是 signal 模式专属的补充条目。

- [ ] **发信号硬前置已过（首检项）**：距上次 `date` ≤ 2 分钟 且 距上次 `snapshot`（该标的）≤ 2 分钟？若任一 > 2 分钟，或本 session 经历过断网 / 暂停 / 工具故障 / 会话压缩 → **先跑 `python3 scripts/resume.py [标的]` 重建上下文 + 刷新现价**，再发信号。参考价过时 = 用户下单基准错 = 实亏，**禁止用过时数据发信号**。
- [ ] **假设执行、不查 positions**（信号模式总则）：开仓信号发出即假设已成交，不查 positions、不等反馈？（用户若真实操作致持仓变化会主动告知）
- [ ] **三步连贯时序 + 成交价**：发信号第一个动作 = `log_signal.sh` 写信号文件、第二个 = `ring.sh` 响铃 + 写 `signals/ring-log.csv`（时间精确到秒）、第三个 = snapshot 取响铃时刻价当成交价 + append 到该条信号末尾；**三步之间不插入任何其它动作**（对话不输出关键字段）？（时序见上文「信号时序总则」）响铃后按实测价重算实际 max_loss、修正赔率；**不算价格范围、不判开仓失败**？
- [ ] **止损价在信号里给出 + 提示用户 App 挂止损**：信号末尾提示「开仓后请在 App 挂止损 @ $Y」？（AI 不挂任何条件单）
- [ ] **信号按三类格式呈现**（🟢 开仓 / 🔴 平仓 / 🟡 移损 + 表格，禁止加仓减仓）？写入对应市场文件（港股 `HKT-signals.md` / 美股 `ET-signals.md`）？
- [ ] **港股两个硬平仓时点（12:00 午休前 + 16:00 收盘前）——届时主动发平仓信号？**
- [ ] **持仓不过夜（AI 主动纪律）？** 港股 12:00 午休前 / 16:00 HKT 收盘前、美股用户喊停或 16:00 ET 收盘前——主动平掉所有持仓；不存在留单。
- [ ] **发信号时段合规？** 三类信号只在盘中发、盘前 / 盘后 / 夜盘不发：港股限盘中 09:30-12:00 / 13:00-16:00（午休 12:00-13:00 不可交易）；美股限盘中美东 09:30-16:00。
