# 自动交易模式（auto-mode，详细参考）

> 本文件是 trade skill **自动交易模式（auto）** 的专属规则。trade skill 默认 signal；当用户**特别说明要自动交易**（说「自动下单 / 自动交易 / auto」等）时才切 auto 模式（见 `SKILL.md`「模式开关与触发首动作」），加载本文件。本文件只在 auto 模式下加载，signal 模式不加载（默认加载 `references/signal-mode.md`）。
>
> auto 与 signal 的区别**只在最后一步「怎么执行」**：auto 是 AI 拍板后直接调券商 API 下单 + 设止损条件单，全流程自动化；signal 是 AI 只发信号、用户拿信号在自家 App 手动执行、AI 不碰账户。前面「盯盘 → 找机会 → 算仓位止损 → 复盘」完全一样，共用 `SKILL.md` 主文件 + 公共 references（`trading-strategy.md` / `risk-management.md` / `monitoring.md` / `account-tools.md` / `review-and-evaluation.md`）。
>
> 触发本模式加载时，先按 `SKILL.md`「模式开关与触发首动作」亮明模式提醒，再读本文件。

## 自动交易模式总则（最高优先级）

本 skill 处于 **自动交易模式**。港股、美股默认都用老虎开放平台模拟账户（`<HK_PAPER_ACCOUNT>`，港股 HKD / 美股 USD 同账户），AI 决定拍板后**直接调用券商 API 下单 + 设止损条件单**，全流程自动化。如用户不使用默认账户会特别说明。

**⚠️ 凭证与账户号防泄漏（2026-08-17 立）**：实盘与模拟共用同一套 API 凭证（tiger_id + RSA 私钥 + license，在 `~/.tigeropen/` 与项目 `accounts.json`，均非 git 跟踪），**完整账户号与私钥不得进入 AI 对话上下文**（上下文会进入模型请求）。已在配置层拦截：permissions.deny 挡 Read 工具、`.claude/hooks/secret_guard.py` 挡 Bash 命令行读取（cat / grep / python open 等碰凭证文件即阻断）。AI 需要展示账户时一律用打码口径——`python3 .claude/skills/trade/scripts/trade_utils_tiger.py --masked-live-account` 输出 `67****91` 形式的打码号（用户自己知道完整号、足够确认）。脚本内部读凭证属正常业务链路、不受拦截影响。

**⚠️ 实盘误开防护：默认态实盘物理不可达（2026-08-21 立，工具强制）**：模拟盘是默认账户；实盘（`--account live`）**默认态被两道物理拦截**——① 6 个下单脚本前置闸：解析到 `--account live` 且解锁文件无效 → 直接输出 `{ok:false, blocked_by:"live_locked"}` 拒单（不往下走）；② `apply_proxy` 实盘解锁闸：实盘无有效解锁 → 不挂代理、本地直连 → 被老虎 IP 白名单在**连接层**拒（access forbidden）。**实盘授权流程**（用户明确要切实盘时）：按 SKILL.md「auto 模式的账户选择」发 AskUserQuestion（问题含打码号 `67****91` / 「--account live」+「实盘」+ 授权范围）→ 用户点「确认授权」（hook `live_auth_witness.py` 自动写 10 分钟短时凭证）→ AI 跑 `python3 scripts/live_unlock.py verify-auth` 写解锁（24h 有效、绑定本会话）→ 此后 `--account live` 脚本放行 + apply_proxy 给实盘挂代理。收到 `blocked_by:"live_locked"` = 未解锁（误传参数去掉 `--account live` 即回模拟盘；确需实盘走授权流程）。撤销：`python3 scripts/live_unlock.py revoke`。详见 `accounts.md`「实盘误开防护」节。

## 4 类动作（开仓 / 平仓 / 移损 / 移盈，禁止加仓减仓；2026-08-23 从 3 类扩为 4 类——新增移盈）

空仓时只能做**开仓**，持仓时只能做**平仓**、**移损**和**移盈**。**禁止加仓和减仓**（不复活旧信号模式的加仓 / 减仓动作）。最多持仓一个标的。

- **开仓 🟢** — 空仓时建仓（做多 / 做空），开仓 = 一笔交易开始，包含**双腿附加单**（止损 + 止盈，主单 + 两附加一次提交）。必含 ① 标的 ② 方向 ③ 开仓量 ④ 参考价 ⑤ 止损价（LOSS 腿触发价）⑥ 止盈目标价（**PROFIT 腿触发价，2026-08-23 用户立：开仓主订单的附加单里除止损单还必须有止盈单**）⑦ 单笔预算 + 预估 max_loss ⑧ 初始预期赔率（净赔率 ≥1.2（config.risk.min_net_odds 权威，2026-08-25 从 1.8 下调），单一门槛直接比）⑨ 置信度 ⑩ 依据。**主单一律限价单（LMT，2026-08-23 用户立「下单必须用限价单」）**：限价 = 盘口对价（做多挂 ask 主动买；**做空挂 max(bid, ask) 即挂 ask，2026-08-25 修 T122**——港股提价规则要求持续交易时段卖空价 ≥ 当时最好沽盘价（ask），挂 bid 恒违规、实盘生产网关必拒（07709 空单 3 连拒实录），挂 ask = 与最低卖单同价排队卖，是提价规则下做空唯一合法挂法），取整 tick，`--order-type mkt` 已禁用（脚本直接拒单）。**双腿机制（2026-08-23 查证 SDK 源码 + 官方文档）**：LOSS+PROFIT 齐发 = `attach_type='BRACKETS'` 括号订单——主单成交后系统自动监控，止损/止盈**任一边触发成交、另一边自动作废**；主单撤则两腿同步取消；附加订单仅限价主单支持（市价主单已禁用，正好吻合）。腿方向由券商按主单方向自动定。沿革：2026-08-07 曾因高波动标的限价 + 8 秒超时撤单易错过成交改市价单默认，2026-08-23 按用户新规改回限价唯一——限价未成交场景按「挂起超时撤单退出、AI 决策」处理，不靠市价单兜底。
- **平仓 🔴** — 持仓时主动清仓，**「止损/止盈触发价交替逼近现价」循环**（2026-08-23 用户立）：① 先把**止损单**触发价改为现价 → 检查是否触发平仓成功（**通常第一次改止损价就能触发**）；② 没触发（小概率）→ 把**止盈单**触发价也设为现价、让价格触发止盈单平仓 → 再检查；③ 还没触发（更小概率）→ 再改止损单触发价 → **不断循环，止损价与止盈价不断接近来逼迫平仓**；④ **止损单失效**（瞬时插针触发但平仓失败 → 处于无止损单状态）→ **必须立刻重新设置止损单并把触发价设为现价**来触发平仓。每轮先复查持仓（条件单已实际成交而轮询滞后时按已平收尾，防超卖反向开仓）；循环上限 8 轮，耗尽未平如实上报、不撤条件单（保护必须在场）。平仓成交后撤全部残留止损单 + 止盈单（BRACKETS 理论一边成交另一边作废，复查兜底——残留条件单日后零持仓触发会反向开仓）。**无止损单的情况（开仓未带 / 插针触发后失效）→ 立刻再设置一个止损单、止损价 = 现价**（循环第④步内置——触发价=现价等于立刻触发市价平仓，这是「没有止损单」场景的唯一处理方式；平仓全程不下普通订单）。止损/止盈条件单触发后的成交方式是条件单语义、市价触发——**条件单不在「下单必须用限价单」禁用范围**（见下方「禁止限价止损」）。平仓 = 一笔交易结束。
- **移损 🟡** — 持仓时移动止损（**只朝有利方向移、永远单向**：做多只上移、做空只下移——移动止损的目的 = 不断往上锁赔率，从负赔率锁到正赔率、赔率越大越好）。**把随开仓附带的止损单触发价 modify 为新止损价**（单步、无撤单 race——2026-08-05 实测开仓附加止损腿 OrderLeg('LOSS') 落成的独立 STP 可直接 `modify_order(aux_price=新价)`），保留单个活动止损——防空仓反向开仓：完全空仓时止损单触发会被接受、反向开仓，故不能累积。仓位无活动止损才补下新 STP、modify 失败才 fallback「先下新止损单、再撤旧止损单」。⚠️ 2026-08-23 起 move_stop 的止损单判定排除止盈单（PROFIT 腿落成单不会被当止损误改误撤）。
- **止损单铁律（2026-08-23 用户立，兜底）**：**只要持仓在，止损单就必须存在**。持仓期间实时监测止损单状态（采样段持仓状态行每 40 秒自带——工具强制，不凭记忆）；瞬时插针触发止损但平仓失败、价格反弹后**若不想立马平仓，必须立刻恢复之前失效的止损单**（失效前止损价 = 当日 actions 开仓「止损」/ 移损「新止损」行解析值，告警文案直接给出；恢复 = `move_stop` 传失效前止损价、走「无活动止损单 → 下新 STP」分支），恢复后继续盯盘；**若确认要平仓**则走 `close_position`（交替逼近循环第④步补设止损单触发价=现价、市价触发离场）。二者必居其一、当段执行——不许「裸奔继续盯盘」。
- **移盈 🔵（2026-08-23 用户立，第 4 类动作：移动止盈）** — 持仓时移动止盈单触发价（`move_target_tiger.py` / `move_target_tiger_us.py`）。**理念与移动止损一致：放在趋势反转位；但具体操作不同——止盈位可双向移动、止损位永远单向**。以做多为例，趋势是否在的观察有两条：① 低点更高 ② 高点也更高。**止损的逻辑** = 放在结构性低点（下一个低点没有更高就触发止损）；**止盈的逻辑** = 放在结构性高点——**高点没有更高，则止盈放在当前结构性高点**（此时很可能就是双顶或头肩顶形态）；**接近止盈价但趋势还在，则适当远移止盈位**（让利润继续跑）。止盈是锦上添花、防快速回撤抓不到浮盈峰值；抓得准不准需要精准的预见性判断。方向硬校验同 move_stop：新止盈必须未穿越现价（穿越 = 主动平仓语义，归 close 脚本管）。

### 下单失败处置（2026-08-11 立，MINIMAX 58,400 教训）

开仓脚本（港股 `open_position_tiger.py` / 美股 `open_position_tiger_us.py`）已内置**失败自动降档重试**：目标量下单被券商拒绝（回查 Invalid / 提交抛异常）时，脚本自动按降档序列（逐次减半、向下取整手）重试到可下上限，每次失败输出**失败档位 + reason**；降档成交时输出 `downscaled: true` + `target_quantity` + `failed_attempts` + warning（仓位缩水提示），AI 按实际成交量记录动作、不必再手动试探可下量。

**执行顺序（2026-08-28 用户立「先算仓位再校验」）**：开仓脚本的内部顺序是 **取现价 → 算仓位（quantity=0 自动定档，净口径 max_loss）→ 价格范围检查 + 净赔率硬校验（真实股数 × 真实费率 × 净分母，vs config.min_net_odds）→ 下单**。净赔率与净 max_loss 的公式都依赖股数（费按成交额×股数算、按笔固定费摊每股随股数变），先定股数再校验才能拦住「小仓位固定费占比高、真实净赔率不达标」的单（实测例：200 股真实净赔率 0.97 应拦，旧近似口径 1.98 会放行）；拒单报错自带股数与净 max_loss。两条路径（显式传量 / 自动算仓位）同一口径，旧「quantity=0 时退百分比估费」路径已废止。代价：拒单场景多查一次 equity（只读 API、秒级）。

**为什么做**：2026-08-06 MINIMAX-W 计划仓位 58,400 股（预算 B ÷ 止损距 2.8 算）无法一次下达，当时脚本只输出「Invalid」、没有原因，AI 手动试 5,000 / 500 / 200 / 120 多次失败才摸到 10,000 可下（且未二分穷尽上限，最终仓位只有计划的 17%，收益被仓位拖累）。失败原因没暴露、可下量靠盲试——两个问题本次一并解决：回查函数输出 reason（`check_order_filled_tiger` 返回 4 元组，被拒订单的具体原因不再丢失）+ 脚本自动降档。

**两种失败不降档（脚本行为，AI 按提示处置）**：
- **cross-trading**（reason 含 `cross-trading with your pending sell order`）——账户已有同标的**未成交委托单**（之前下单尝试残留的挂单），新单会与它交叉成交，券商自成交防护拒绝再挂一单（2026-08-06 实测 120 股那笔的明确 reason；8-06 当时 AI 归因「已有止损挂单」未严格验证，2026-08-11 用户纠正：开仓 = 空仓建仓、与已有止损单无关）。这与量无关、降档无意义，须**改单（modify 已有委托单）或撤销现有未成交委托单后，再重新挂单**（不要直接再挂一单，仍会被拒）。
- **挂起超时未成交**（非 Invalid）——可能是限价 / 盘口问题而非被拒，脚本撤单退出，由 AI 重新决策。

**购买力上限：下单前主动降档（2026-08-16 立，与 cross-trading 并列的第三类拒单根因）**：开仓脚本算出目标量后会按**单标的保证金率**预算可买上限——可买股数 = `buying_power × long_initial_margin ÷ 参考价`（`get_buying_power_tiger`，实测字段：`get_assets().summary.buying_power`、`get_contract().long_initial_margin`，00100 保证金率 0.75）。目标量超上限时脚本**先主动降档再下单**（输出 `capped_by_buying_power: true` + 上限值），2026-08-06 00100 大单被拒的根因即此约束（8-12 实测：buying_power 817.5 万 × 0.75 = 可开 1,090 万市值 = 37,484 股，远小于预算 B 算出的 58,400 股）——被动降档重试保留兜底，但正常路径不再烧降档轮次。

**不设分批建仓路径（2026-08-11 用户纠正移除）**：降档后实际成交量低于计划仓位时**接受缩水、不补足**——分批补足 = 同一标的先后两笔同向开仓，本质上就是加仓，违反「禁止加仓减仓」护栏；一次性开仓设止损即可，一次下不了的计划仓位就缩水接受（降档重试已自动摸到可下上限）。

**一笔交易（a trade）= 一次开仓到一次平仓**。同一标的同一时刻只有一笔持仓。开仓 = 一笔交易开始，平仓 = 一笔交易结束。复盘时逐笔算 R-multiple、胜率、EV。

### 平仓行为：主动 vs 被动

| 行为 | 触发方 | 盈利 | 亏损 |
|---|---|---|---|
| 主动开仓 | AI 开仓 → 脚本自动执行 | — | — |
| 主动平仓 | AI 平仓 → 脚本自动执行 | **主动锁利** | **主动锁亏** |
| 被动平仓 | 止损 / 止盈条件单触发（2026-08-23 起含 PROFIT 腿） | **被动锁利** | **被动锁亏** |

- **主动平仓 🔴**：AI 判断动能减弱 / 情况不对 / 到硬平仓时点等，调对应老虎平仓脚本（港股 `close_position_tiger.py` / 美股 `close_position_tiger_us.py`）执行平仓——脚本走「止损/止盈触发价交替逼近现价」循环（见上方「平仓 🔴」定义），记录到 `actions/`。
- **被动平仓（止损 / 止盈条件单触发）**：只标记记录（「XX 止损/止盈 $Y 触发、成交 ~$Z、亏/盈 $M」），更新 equity。2026-08-23 起开仓带止盈条件单（PROFIT 腿），止盈触发也是被动平仓的一种。
- **止盈靠三条路（2026-08-23 修订）**：① 止盈条件单被动触发 🔵（开仓双腿自带的 PROFIT 腿，涨/跌到止盈触发价自动平仓）② 主动平仓 🔴（AI 判断到目标 / 情况不对，走交替逼近循环）③ 移动止损锁利 🟡（浮盈中上移止损到盈利区）+ 移动止盈 🔵（止盈位随结构双向调整——见「移盈」动作）。

## 操作原则（auto 专属）

1. **自动执行**：AI 拍板后立即调用对应老虎脚本（港股 `open_position_tiger.py`（开仓）/ `close_position_tiger.py`（平仓）/ `move_stop_tiger.py`（移损）/ `move_target_tiger.py`（移盈，2026-08-23 新增）、美股 `*_tiger_us.py` 同名对应），脚本主单 + 附加止损/止盈双腿一次提交（无裸奔空窗）+ 成交回查（目标最优成交价）。下单结果（order_id、成交价）由脚本 JSON 输出，AI 据此记录交易动作到 `actions/` 目录（`log_action.sh`）。
2. **自主循环、不打断用户**：AI 自主跑「盯盘→分析→执行→记录」循环，不中途停下问用户、不等确认。盯盘由用户指令启动、AI 不自主启动。盯盘期间无人值守——AI 所有盯盘决策（换标的 / 方向 / 止损 / 平仓 / 移损）自主完成，不 AskUserQuestion 中断。无机会时自主决策树：① 换标的（hot_list 刷新找活跃标的）；② 换标的不降频（觉得「整个市场无活跃机会」时也保持 40 秒密采样、持续刷 hot_list 找下一个活跃标的，绝无「降频死等」合法出口——见 SKILL.md 硬性护栏与 `references/monitoring.md`，降频出口已于 2026-08-04 撤销）；③ 持续盯到收盘 / 用户喊停。
3. **持仓状态从脚本输出跟踪**：AI 调用开仓 / 平仓脚本后，从脚本 JSON 输出获取 order_id 和成交价据此确定持仓状态——不需要假设、不查 positions。
4. **记录到 `actions/` 目录（复盘基准）**：下单成功后 `log_action.sh` 写交易动作到 `actions/YYYY-MM-DD-<market>-actions.md`（港股 HKT / 美股 ET）。记录必含：时间（精确到秒）、标的、动作类型（开仓 🟢 / 平仓 🔴 / 移损 🟡 / 移盈 🔵）、方向、量、参考价、止损价、止盈目标价（PROFIT 腿触发价）、单笔预算、预估 max_loss、置信度、依据、下单结果（order_id、成交价）。B、max_loss、盈亏、赔率、equity / 净值照常写（2026-08-29 用户裁定：实盘净值不属敏感财务信息、照常可写——2026-08-20 立的「实盘交易日 equity 本体数值不写」旧规已废止，沿革见项目 CLAUDE.md「实盘净值不属敏感信息、照常可写」节）。
5. **盘中排查用开仓单测试后必须立即平仓（2026-08-10 用户立）**：auto 模式盘中为排查问题（开仓失败 / EXPIRED / 下单机制验证等）而用开仓单做测试时，测试单一旦成交**必须立即平仓**（调用对应平仓脚本），排查完不留测试仓位过任何时段——测试仓位暴露在价格波动下有资金损失风险（2026-08-10 实测：00100 大单 EXPIRED 后用 100 股小单排查机制，成交 @330.6 后立即平掉 @329.4，亏约 -239 HKD 测试成本；若忘了平仓，价格波动会放大损失）。排查用单只用于验证机制、不构成正式交易，记录时标注「作废测试单」。**实盘账户排查铁律（2026-08-10 用户立）**：若账户切换为实盘（非模拟），盘中遇到需要开仓单测试才能排查的问题时，**一律先用模拟账户排查**——先用模拟账户复现 / 验证机制，排查清楚后再在实盘按正常流程操作；**模拟账户也排查不出问题时，暂停盯盘、请求用户许可，经用户明确同意后才允许在实盘排查**（实盘测试单有真实资金损失风险，未经许可不得自行在实盘用测试单排查，模拟排查不出 ≠ 可以默认在实盘试）。

> 质量优先（开仓过两道闸 🟢 高置信 + 初始净预期赔率 ≥ 1.2（config 权威））、复盘由用户指令触发盘中不复盘、不记账、零额外延迟——这些是公共操作原则，见 `SKILL.md`。

|---|---|

> **平仓必填实际落地赔率（2026-08-03 用户立；2026-08-04 改净口径；2026-08-12 改真实费率；2026-08-17 平台费改固定模式 + 美股按股；2026-08-28 分母改净 max_loss）**：平仓动作表格必须含「实际落地赔率 = **净**盈亏 ÷ 修正 max_loss」（修正 max_loss = 实际仓位 × |开仓成交价 − 止损价| + 开仓边费 + **止损价**平仓边费，开仓时点算死、移动止损不改这个基准；净盈亏 = 毛盈亏 − [开仓边费 + 平仓边费]，开仓 / 平仓各按各自成交额/股数算单边费——auto 平仓额用脚本返回的真实成交价 / 止损触发价；费率 = 老虎真实费率见 `risk-management.md`「费率与成本」，含佣金最低 / 印花税 / 固定平台费）。**分母含费的意义**：止损价精确成交时净亏损恰好等于修正 max_loss → R 恰好 −1.000，最大亏损不深于 −1R（仅剩滑点）。**盈亏金额看不出「承担了多少风险换来的」**——同样赚 $5000，max_loss $5000 是 1R、max_loss $10000 只算 0.5R；实际落地赔率才反映真实性价比，与开仓记录的初始预期 / 修正预期赔率对照，能直接看出「预估→修正→落地」的打折程度（如 2026-08-03 MU 空：初始 2.86R → 修正 2.06R → 实际 −0.92R，预估乐观但被板块 V 反打破止损——历史 R 为旧毛分母口径、与新政不可直接比大小）。被动平仓（止损触发）也照填。**开仓条目在平仓后回填实际落地赔率**，让该笔三阶段赔率（初始预期 / 修正预期 / 实际落地，均净口径含费分母）齐全于一处。

> **费用与成交价的唯一权威口径（2026-08-16 立，消除双口径并存；2026-08-19 修订：盈亏净额以 App 实测为权威；2026-08-28 max_loss 净口径）**：同一笔交易的**成交价、max_loss 两个数字，唯一权威 = 脚本 JSON 输出 + `fee_schedule.py` 复算**——动作记录（actions/）转录时**直接抄脚本输出的字段值**（`fill_price` / `avg_fill_price` / `stop_loss` / 脚本返回的止损触发价），**禁止手算 / 心算后再写一个略不同的数**。**盈亏净额（含费净利润）唯一权威 = 券商 App 实测**（2026-08-19 用户立：当日小米平仓 AI 手算净利 506、App 实测 473.93，差 32——AI 拆算费率再细也会漏费项 / 漏印花取整 / 口径差，直接抄 App 数字才不会错）。**取数方式**：① 老虎 SDK `get_filled_orders` 的 `commission` 字段（= 该笔实收总费用）与 App 成本价口径；② 用户在 App 看到的已实现盈亏。**落地为工具强制**：平仓脚本（close_position_tiger / _us）成交后自动查成交单 `commission` 字段、按「毛盈亏 − 双边实收费」输出 `net_pnl_app` 字段，AI 转录动作记录时直接抄该字段（不查到时才用 fee_schedule 复算并在备注注明「复算口径、待账单核对」）。背景：2026-08-10 药明、08-12 旭创等约 8 笔交易在源记录与 review.py 复算间存在两套费用 / 两套 R（最大差 13,914 HKD）；2026-08-19 又现手算 vs App 双口径（AI 当场手算漏了交收费 / 征费 / 财汇局 / 印花取整四项）。裁定：**复盘统计的费率口径仍以 review.py / fee_schedule 为准**（保证全样本一致性）；**单笔动作记录的盈亏净额以 App 实测为准**，两者不一致时在复盘时校正并注明。max_loss 同理（2026-08-28 起净口径）——「实际 / 修正」字样的 max_loss 必须用成交价口径（仓位 × |成交价 − 止损价| + 开仓费 + 止损价平仓费），参考价口径的只能标「初始预期 max_loss」（开仓脚本 `max_loss_basis` 字段已标注口径；2026-08-13 MINIMAX 开仓条目曾按旧毛口径修正过）。

**开仓脚本成交确认后自动响一声 `open` 音色提醒用户已开仓**（`open_position_tiger.py` / `open_position_tiger_us.py` 内置调 `ring_after_fill`，部分成交同样响、note 注明）——auto 模式 AI 直接下单，用户若不盯屏幕感知不到已开仓，响铃把注意力拉回来。**这是脚本内置的工具强制行为，AI 无需（也不必）再手动调 `ring.sh`**。响铃记录写 `signals/ring-log-auto.csv`（与 signal 模式的 `ring-log.csv` 隔离——后者末行被 `log_action.sh`（signal 拍板时刻）与 `resume.py`（signal 断层检测）消费，auto 写入会污染）。响铃失败静默降级（提醒件非交易链路、不影响下单结果输出）。

## 影子交易（shadow，2026-08-27 立——auto 模式的分支交易路径）

**定义（用户 2026-08-27 定案）**：auto 模式下开仓拍板后碰到**单持仓互斥闸拦截**（`blocked_by=open_exposure_today` / `active_open_order`，即「别的会话已持仓或已占坑」）时，本会话不真下单，改为把这笔机会按**信号式记录**落成一笔模拟交易并打**【影子】标签**——影子交易是**实盘自动模式下的分支交易**，不切模式、不换会话，会话仍是 auto（采样 log、equity 来源、互斥语义全部不动）。

**三者必须区分（不可混称）**：

| 概念 | 是否下单 | 触发方式 | 记录载体 |
|---|---|---|---|
| signal 模式 | 否（用户手动执行） | 用户启动的整会话模式 | `signals/`（响铃时刻价） |
| auto 模式（模拟 / 实盘账户） | 是（真实订单进账户） | 用户说 auto 启动 | `actions/`（order_id、真实成交价） |
| **影子交易（shadow）** | **否（纯纸面）** | **auto 会话内被互斥闸拦下时自动转** | `signals/`（【影子】标、决策时刻价） |

**为什么做**：多会话并行盯盘走方案 A（全局至多一笔在场），后到机会全被闸门拦下删失——被拦样本永远无法验证、复盘只看到「第一名机会」，单持仓互斥与样本搜集在并行场景结构性冲突（2026-08-27 用户立）。影子交易把被拦机会变成可统计样本：假设成交、按决策时刻价近似、走完开仓→（移损）→平仓完整生命周期，进复盘统计（单独一组）。

**落地动作（AI 收到 blocked JSON 后）**：

1. 开仓脚本 blocked 输出自带 `shadow_hint` 字段（在场打印，工具强制）——被拦口径是「别人在场」时 AI 按 hint 给的命令行落影子仓：
   `python3 scripts/shadow_trade.py open HKT <symbol> <direction> <entry_ref> <stop> <target> <qty> --blocked-by <blocked_by>`
   （价格与量用**本会话这次拍板的计划值**——正是被拦下的那笔机会；`decision_price` 取脚本输出的 `current_price` 作假设成交价近似）；
2. 影子仓期间照常盯盘，按真实仓同款逻辑判断移损 / 平仓时机——但**只走 `shadow_trade.py move / close`**（纸面记录，不下单、不响铃、不调 close_position 脚本）；
3. 平仓时 `shadow_trade.py close <market> <symbol> <决策时刻价> <理由>`，脚本自动结算净盈亏 / R（fee_schedule 同源费率、max_loss 毛口径分母，与真实仓同口径）并追加【影子】平仓条目到当日信号文件。

**四条硬边界（2026-08-27 用户定案的决策点，脚本已内置强制）**：

1. **真实仓优先**：影子仓在场时本池又出真实开仓机会 → 真实仓优先、正常走 open_position 下单（影子仓被动并行盯，纸面不紧急）；**不放走真实机会、也不提前终止影子仓**（提前终止产生截断偏差，除非该笔已触发止损价 / 止盈价——价格穿越本身就是完整退出事件、照常 close 结算，不算截断）；
2. **每会话同时至多一笔影子仓**（脚本强制：同会话已有未平影子仓时 open 拒记）；真实「全局至多一笔」硬规矩不变、互斥闸照常对真实开仓生效；
3. **只落「别人在场」口径**：`open_exposure_today` / `active_open_order` 才落影子仓；`pending_intent`（可能崩溃残留）**不落**——那种场景连真实状态都不确定，先按 JSON 提示人工排查；其它拒单口径（time_gate / stamp_tax_gate / live_locked / 净赔率不达标等）是**本会话自己不过闸**、不是别人占坑，也不落影子仓（那种情况是放弃机会、不是被互斥拦下）；
4. **复盘单独统计**：影子样本进 trades.csv 时 `type` 列前缀不参与、**单独一列 `shadow` 标 `1`**（或 CSV 文件名加 `-shadow`），统计时与真实样本**分开算胜率 / EV**（影子成交价是决策时刻价近似、无真实滑点、且是「被拦下的机会」——与真实样本不同质）；样本攒够后可合并看「先到 vs 被拦」两组表现对照。**禁止把影子样本混进真实胜率 / EV / equity 曲线。**

**与互斥机制的隔离（设计约束，shadow_trade.py 不碰的东西）**：不碰 `trade_mutex` 的 intent 日志（不下真单、无需 WAL）；不拿 flock 锁（影子开仓与真实开仓无竞态——真实闸门查的是订单流，影子仓不在订单流上）；不碰 `signals/equity-log.csv`（影子盈亏只记单笔 R / 净盈亏，不进 equity 累加链——影子是样本、不是资金曲线）。状态文件 `tmp/shadow_positions.json`（本机运行时数据，随 tmp/ 不入库）。

**工具强制落点（按项目「文档规定必须尽可能配工具强制」规矩）**：① `shadow_hint` 在场打印——开仓脚本 blocked JSON 直接带影子路径命令行，AI 读 JSON 必然看到（决策时刻在场）；② `shadow_trade.py open` 前置校验——blocked_by 口径不符直接拒记（决策点 3）、同会话已有未平影子仓直接拒记（决策点 2）；③ 影子条目自动打【影子】标——AI 无法漏标（记录由脚本生成、不经 AI 手写）。

## auto 专属硬护栏（下单前逐条自检，违反不得下单）

> 公共硬护栏（标的范围 / 衍生品禁令 / 单持仓 / 盯盘时段 / lot_size / 单笔预算与 max_loss 概念）见 `SKILL.md`「硬性护栏」。下面是 auto 模式专属的下单护栏。

1. **开仓止损用附加止损腿（OrderLeg('LOSS')，主单成交才激活），一律市价触发（2026-07-31 用户新规）**。「主订单 / 附加订单」**不是订单的固有分类**——订单本质按类型分（`LMT`/`MKT`/`STP` 等），「主/附加」只是开仓把主单 + 止损腿打包一次提交时的相对称呼（主单 = 开仓限价单 LMT（2026-08-23 用户立「下单必须用限价单」，默认且唯一）、附加 = 跟随提交的止损腿），**只在开仓场景才有**。开仓场景的操作要点：
   - **开仓**：一次提交主单（LMT 限价单 = 盘口对价，2026-08-23 用户立「下单必须用限价单」；`--order-type mkt` 已禁用拒单）+ 附加止损腿 `OrderLeg('LOSS', 止损价)`（`trade_utils_tiger.submit_order_with_stop_tiger`）。附加止损随主单提交、主单成交才激活，开仓失败止损不残留；附加腿的方向与触发符号由券商后端按主单方向自动定（与主单相反）、无需传 side。
   - **禁止限价止损**（独立止损用 `STP_LMT` 限价触发单）：止损单一律市价触发（`STP` 触发后市价成交）。限价止损委托价不合理时有无法及时成交的风险（老虎官方：止损限价单「若委托价格设置不合理，有无法及时止盈或止损的风险」），故本 skill 提到「止损单」默认指市价止损单；`move_stop` 移损 fallback（无活动止损 / modify 失败）下新止损单时也一律用市价止损单。**止盈单同理市价触发**（2026-08-23 双腿开仓立）：PROFIT 止盈腿与 LOSS 止损腿同语义——触发后尽快成交、不因限价挂不住错过，快速回撤时锁不住峰值就失去止盈单的意义。
   - **止损只能用条件单（`STP` 或附加腿 `LOSS`），不能用反向的普通订单（`LMT`/`MKT`）冒充**：`LMT`/`MKT` 没有「价格到触发价才成交」的语义，要么挂单要么立即成交，起不到条件止损作用（2026-07-31 MU 事故的真因之一正是误用市价单当止损——提交即按市价成交、瞬间平仓亏 $119，见 CHANGELOG 2026-07-31）。这才是「禁止反向订单止损」的正确含义——不是说止损单不能反向（止损单本就和开仓反向），而是说**不能用一笔反向的普通订单冒充条件止损单**。
   - **触发价 = 目标止损价**（允许小范围偏差）；用户也会在 App 手动新增止损单，故最新止损价不能凭记忆，`monitor_segment.py` 每轮采样查账户当日订单获取最新止损价。
   - **持仓状态工具强制 + 空仓不查（2026-08-18 立，用户两起实盘事故后）**：① **自己开仓后，持仓状态与最新止损价由采样段输出自动带出，不靠 AI 记得去查**——`futu_ws_segment.py`（主力源）每段结束打印「📌 持仓状态」行（账户实持量 + 活动止损单最新触发价 + 状态比对：账户已无持仓但 AI 未记录平仓 → 🚨 告警、数量不一致 → ⚠️ 提示），实现见 `scripts/account_status.py`（读当日 actions 判定持仓、有持仓才查账户）；② **空仓时不必查持仓状态**——别人开的仓不用管（2026-08-18 用户纠正：AI 曾空仓也频繁查账户、且把并行会话的持仓当自己的盯），actions 无未平仓记录时 `account_status` 直接返回 None、零 API 调用；③ AI 收到 🚨 告警后立即核对账户（get_positions + get_orders）并按实际情况记录平仓 / 核对最新止损价，不许继续按记忆盯盘。**背景**：2026-08-18 实盘 00700——用户在 App 移损 440→442.6、止损 14:04:19 即触发成交，AI 未知悉移损、也未察觉持仓已平、空盯 29 分钟，两起违规同根因：只信开仓脚本输出与行情采样、从不向账户核对（SKILL.md 虽明文规定「每轮查账户订单」，但散文规定靠 AI 记忆执行会衰减，故改为工具强制）。
2. **AI 直接下单**：港美股默认都用老虎开放平台模拟账户，AI 拍板后调用对应脚本直接下单（港股 `*_tiger.py` / 美股 `*_tiger_us.py`，**普通订单一律限价单**（2026-08-23 用户立，市价单已脚本级禁用）+ 止损条件单）。如用户不使用默认账户会特别说明。
3. **开仓 / 平仓触发**：① 开仓必带止损条件单（脚本自动设置，止损单市价触发）；② 平仓在动能减弱 / 做空时回踩前低不破（下跌动能衰竭）/ 做多时回踩前高遇阻（上涨遇阻）/ 做空时资金流转正（买盘涌入）/ 做多时资金流转负（卖盘涌出）/ 到硬平仓时点时由 AI 调脚本执行；③ AI 最高频盯盘，触发条件一到立即执行，出手要快。

## 执行反馈

AI 调用脚本下单后，脚本 JSON 输出 order_id 和成交价，AI 据此记录动作文件并按成交价继续盯盘。若脚本报错（价格不在范围内 / API 错误），AI 据错误信息调整策略。持仓状态从脚本输出跟踪，不需要假设。
