# 自动交易模式（auto-mode，详细参考）

> 本文件是 trade skill **自动交易模式（auto）** 的专属规则。trade skill 默认 signal；当用户**特别说明要自动交易**（说「自动下单 / 自动交易 / auto」等）时才切 auto 模式（见 `SKILL.md`「模式开关与触发首动作」），加载本文件。本文件只在 auto 模式下加载，signal 模式不加载（默认加载 `references/signal-mode.md`）。
>
> auto 与 signal 的区别**只在最后一步「怎么执行」**：auto 是 AI 拍板后直接调券商 API 下单 + 设止损条件单，全流程自动化；signal 是 AI 只发信号、用户拿信号在自家 App 手动执行、AI 不碰账户。前面「盯盘 → 找机会 → 算仓位止损 → 复盘」完全一样，共用 `SKILL.md` 主文件 + 公共 references（`trading-strategy.md` / `risk-management.md` / `monitoring.md` / `account-tools.md` / `review-and-evaluation.md`）。
>
> 触发本模式加载时，先按 `SKILL.md`「模式开关与触发首动作」亮明模式提醒，再读本文件。

## 自动交易模式总则（最高优先级）

本 skill 处于 **自动交易模式**。港股、美股默认都用老虎开放平台模拟账户（`<HK_PAPER_ACCOUNT>`，港股 HKD / 美股 USD 同账户），AI 决定拍板后**直接调用券商 API 下单 + 设止损条件单**，全流程自动化。如用户不使用默认账户会特别说明。

**⚠️ 凭证与账户号防泄漏（2026-08-17 立）**：实盘与模拟共用同一套 API 凭证（tiger_id + RSA 私钥 + license，在 `~/.tigeropen/` 与项目 `accounts.json`，均非 git 跟踪），**完整账户号与私钥不得进入 AI 对话上下文**（上下文会进入模型请求）。已在配置层拦截：permissions.deny 挡 Read 工具、`.claude/hooks/secret_guard.py` 挡 Bash 命令行读取（cat / grep / python open 等碰凭证文件即阻断）。AI 需要展示账户时一律用打码口径——`python3 .claude/skills/trade/scripts/trade_utils_tiger.py --masked-live-account` 输出 `67****91` 形式的打码号（用户自己知道完整号、足够确认）。脚本内部读凭证属正常业务链路、不受拦截影响。

## 3 类动作（开仓 / 平仓 / 移损，禁止加仓减仓）

空仓时只能做**开仓**，持仓时只能做**平仓**和**移损**。**禁止加仓和减仓**（不复活旧信号模式的加仓 / 减仓动作）。最多持仓一个标的。

- **开仓 🟢** — 空仓时建仓（做多 / 做空），开仓 = 一笔交易开始，包含附加止损单（主单 + 附加止损一次提交）。必含 ① 标的 ② 方向 ③ 开仓量 ④ 参考价 ⑤ 止损价（附加止损触发价，主单 + 附加一次提交、主单成交才激活，无裸奔空窗）⑥ 止盈目标价（预期值，不设止盈条件单）⑦ 单笔预算 + 预估 max_loss ⑧ 初始预期赔率（净赔率 ≥2.4，单一门槛直接比）⑨ 置信度 ⑩ 依据。**主单默认市价单（MKT，2026-08-07 改）**：高波动标的限价单 + 8 秒超时撤单极易错过成交（MINIMAX 当日 5 次 LMT 开仓全 Invalid），市价单立即成交、附加止损腿同一次提交无裸奔空窗；`--order-type lmt` 可切回限价单（慢波动标的控价用）。
- **平仓 🔴** — 持仓时主动清仓：**把持仓的止损单（开仓附加腿落成的 STP）触发价 modify 为想平仓的价格（主动平仓 = 现价、取整 tick），止损单立即触发、按市价成交平仓**（主路径，只改一个触发价、无「撤止损 + 市价单」两步、无 race，方向不看好时要确定性、允许不利偏移）；无活动止损单时直接市价单，modify 失败 / 未触发才 fallback「撤止损 + 市价单」（保证平仓）。⚠️ **fallback 必须先复查持仓再下 MO（2026-08-07 事故修复）**：modify 触发价=现价后止损单可能已实际触发成交（价格瞬时穿越触发价、轮询状态滞后误判「未触发」），持仓已被平——再按原量撤止损 + MO 会**超卖反向开仓**（实测复现：MINIMAX 平多 20 股 → 反向开空 20 股，2026-08-03「撤止损+MO 反向开空 -36500」同根 race 残留路径）；修复后 fallback 先查持仓：已空 → 只撤残留止损单、不下 MO；持仓剩余 < 原量 → MO 只平剩余量。或止损单被动触发。平仓后不残留未触发止损单（防反向开仓，属平仓动作的一部分）；平仓 = 一笔交易结束。
- **移损 🟡** — 持仓时移动止损（只朝有利方向移；**把随开仓附带的止损单触发价 modify 为新止损价**（单步、无撤单 race——2026-08-05 实测开仓附加止损腿 OrderLeg('LOSS') 落成的独立 STP 可直接 `modify_order(aux_price=新价)`），保留单个活动止损——防空仓反向开仓：完全空仓时止损单触发会被接受、反向开仓，故不能累积）。仓位无活动止损才补下新 STP、modify 失败才 fallback「先下新止损单、再撤旧止损单」。

### 下单失败处置（2026-08-11 立，MINIMAX 58,400 教训）

开仓脚本（港股 `open_position_tiger.py` / 美股 `open_position_tiger_us.py`）已内置**失败自动降档重试**：目标量下单被券商拒绝（回查 Invalid / 提交抛异常）时，脚本自动按降档序列（逐次减半、向下取整手）重试到可下上限，每次失败输出**失败档位 + reason**；降档成交时输出 `downscaled: true` + `target_quantity` + `failed_attempts` + warning（仓位缩水提示），AI 按实际成交量记录动作、不必再手动试探可下量。

**为什么做**：2026-08-06 MINIMAX-W 计划仓位 58,400 股（预算 B ÷ 止损距 2.8 算）无法一次下达，当时脚本只输出「Invalid」、没有原因，AI 手动试 5,000 / 500 / 200 / 120 多次失败才摸到 10,000 可下（且未二分穷尽上限，最终仓位只有计划的 17%，收益被仓位拖累）。失败原因没暴露、可下量靠盲试——两个问题本次一并解决：回查函数输出 reason（`check_order_filled_tiger` 返回 4 元组，被拒订单的具体原因不再丢失）+ 脚本自动降档。

**两种失败不降档（脚本行为，AI 按提示处置）**：
- **cross-trading**（reason 含 `cross-trading with your pending sell order`）——账户已有同标的**未成交委托单**（之前下单尝试残留的挂单），新单会与它交叉成交，券商自成交防护拒绝再挂一单（2026-08-06 实测 120 股那笔的明确 reason；8-06 当时 AI 归因「已有止损挂单」未严格验证，2026-08-11 用户纠正：开仓 = 空仓建仓、与已有止损单无关）。这与量无关、降档无意义，须**改单（modify 已有委托单）或撤销现有未成交委托单后，再重新挂单**（不要直接再挂一单，仍会被拒）。
- **挂起超时未成交**（非 Invalid）——可能是限价 / 盘口问题而非被拒，脚本撤单退出，由 AI 重新决策。

**购买力上限：下单前主动降档（2026-08-16 立，与 cross-trading 并列的第三类拒单根因）**：开仓脚本算出目标量后会按**单标的保证金率**预算可买上限——可买股数 = `buying_power × long_initial_margin ÷ 参考价`（`get_buying_power_tiger`，实测字段：`get_assets().summary.buying_power`、`get_contract().long_initial_margin`，00100 保证金率 0.75）。目标量超上限时脚本**先主动降档再下单**（输出 `capped_by_buying_power: true` + 上限值），2026-08-06 00100 大单被拒的根因即此约束（8-12 实测：buying_power 817.5 万 × 0.75 = 可开 1,090 万市值 = 37,484 股，远小于预算 B 算出的 58,400 股）——被动降档重试保留兜底，但正常路径不再烧降档轮次。

**不设分批建仓路径（2026-08-11 用户纠正移除）**：降档后实际成交量低于计划仓位时**接受缩水、不补足**——分批补足 = 同一标的先后两笔同向开仓，本质上就是加仓，违反「禁止加仓减仓」护栏；一次性开仓设止损即可，一次下不了的计划仓位就缩水接受（降档重试已自动摸到可下上限）。

**一笔交易（a trade）= 一次开仓到一次平仓**。同一标的同一时刻只有一笔持仓。开仓 = 一笔交易开始，平仓 = 一笔交易结束。复盘时逐笔算 R-multiple、胜率、EV。

### 平仓行为：主动 vs 被动

| 行为 | 触发方 | 盈利 | 亏损 |
|---|---|---|---|
| 主动开仓 | AI 开仓 → 脚本自动执行 | — | — |
| 主动平仓 | AI 平仓 → 脚本自动执行 | **主动锁利** | **主动锁亏** |
| 被动平仓 | 止损条件单触发 | **被动锁利** | **被动锁亏** |

- **主动平仓 🔴**：AI 判断动能减弱 / 情况不对 / 到硬平仓时点等，调对应老虎平仓脚本（港股 `close_position_tiger.py` / 美股 `close_position_tiger_us.py`）执行平仓——脚本把持仓止损单触发价 modify 为现价、止损单立即触发市价平仓（见上方「平仓 🔴」定义），记录到 `actions/`。
- **被动平仓（止损条件单触发）**：只标记记录（「XX 止损 $Y 触发、成交 ~$Z、亏/盈 $M」），更新 equity。不存在止盈条件单——锁利靠平仓 / 移损两个主动动作。
- **止盈靠两类动作**：① 主动平仓 🔴（AI 判断到目标 / 情况不对）② 移动止损锁利 🟡（浮盈中上移止损到盈利区，被动触发锁利）。不设移动止盈动作，不设止盈条件单。

## 操作原则（auto 专属）

1. **自动执行**：AI 拍板后立即调用对应老虎脚本（港股 `open_position_tiger.py`（开仓）/ `close_position_tiger.py`（平仓）/ `move_stop_tiger.py`（移损）、美股 `*_tiger_us.py`），脚本主单 + 附加止损一次提交（无裸奔空窗）+ 成交回查（目标最优成交价）。下单结果（order_id、成交价）由脚本 JSON 输出，AI 据此记录交易动作到 `actions/` 目录（`log_action.sh`）。
2. **自主循环、不打断用户**：AI 自主跑「盯盘→分析→执行→记录」循环，不中途停下问用户、不等确认。盯盘由用户指令启动、AI 不自主启动。盯盘期间无人值守——AI 所有盯盘决策（换标的 / 方向 / 止损 / 平仓 / 移损）自主完成，不 AskUserQuestion 中断。无机会时自主决策树：① 换标的（hot_list 刷新找活跃标的）；② 换标的不降频（觉得「整个市场无活跃机会」时也保持 40 秒密采样、持续刷 hot_list 找下一个活跃标的，绝无「降频死等」合法出口——见 SKILL.md 硬性护栏与 `references/monitoring.md`，降频出口已于 2026-08-04 撤销）；③ 持续盯到收盘 / 用户喊停。
3. **持仓状态从脚本输出跟踪**：AI 调用开仓 / 平仓脚本后，从脚本 JSON 输出获取 order_id 和成交价据此确定持仓状态——不需要假设、不查 positions。
4. **记录到 `actions/` 目录（复盘基准）**：下单成功后 `log_action.sh` 写交易动作到 `actions/YYYY-MM-DD-<market>-actions.md`（港股 HKT / 美股 ET）。记录必含：时间（精确到秒）、标的、动作类型（开仓 🟢 / 平仓 🔴 / 移损 🟡）、方向、量、参考价、止损价、止盈目标价（预期值，不设止盈条件单）、单笔预算、预估 max_loss、置信度、依据、下单结果（order_id、成交价）。
5. **盘中排查用开仓单测试后必须立即平仓（2026-08-10 用户立）**：auto 模式盘中为排查问题（开仓失败 / EXPIRED / 下单机制验证等）而用开仓单做测试时，测试单一旦成交**必须立即平仓**（调用对应平仓脚本），排查完不留测试仓位过任何时段——测试仓位暴露在价格波动下有资金损失风险（2026-08-10 实测：00100 大单 EXPIRED 后用 100 股小单排查机制，成交 @330.6 后立即平掉 @329.4，亏约 -239 HKD 测试成本；若忘了平仓，价格波动会放大损失）。排查用单只用于验证机制、不构成正式交易，记录时标注「作废测试单」。**实盘账户排查铁律（2026-08-10 用户立）**：若账户切换为实盘（非模拟），盘中遇到需要开仓单测试才能排查的问题时，**一律先用模拟账户排查**——先用模拟账户复现 / 验证机制，排查清楚后再在实盘按正常流程操作；**模拟账户也排查不出问题时，暂停盯盘、请求用户许可，经用户明确同意后才允许在实盘排查**（实盘测试单有真实资金损失风险，未经许可不得自行在实盘用测试单排查，模拟排查不出 ≠ 可以默认在实盘试）。

> 质量优先（开仓过两道闸 🟢 高置信 + 初始净预期赔率 ≥ 2.4）、复盘由用户指令触发盘中不复盘、不记账、零额外延迟——这些是公共操作原则，见 `SKILL.md`。

## 交易动作记录格式

AI 拍板后调脚本下单，脚本返回 order_id 和成交价，最后 `log_action.sh` 写入 `actions/` 目录。

**动作 emoji**：开仓 🟢 / 平仓 🔴 / 移损 🟡。

**表格格式规范**：表格内不放装饰性 emoji，字段名用纯文字；圆形彩色 emoji（🟢🔴🟡）可在表格内用于动作类型标记；只有开仓表格的参考价和止损价加粗显示。每条动作**表格前**加「框线 + 3 个圆形同色 emoji + 标题 + 3 个同色 emoji + 框线」醒目装饰，再接表格。

**开仓动作 🟢**（对话表格）：

```
════════════════════════════════════
🟢🟢🟢 开仓 · <标的代码> <中文名> · 做多/做空 🟢🟢🟢
════════════════════════════════════
```

| 项 | 值 |
|---|---|
| 方向 | 做多/做空 |
| 量 | N 股 |
| 参考价 | **$X**（**加粗**）|
| **成交价** | **$P**（脚本返回的实际成交价，非参考价）|
| 止损 | **$Y**（**加粗**）|
| 止盈 | $Z（止盈目标价，预期值）|
| **初始预期赔率** | **R 倍**（**净赔率** ≥2.4 才开仓；成交后重算净修正预期赔率）|
| 单笔预算 | $B |
| 预估 max_loss | $M |
| 置信度 | 🟢高 |
| 依据 | 一句话 |

**平仓动作 🔴**：

```
════════════════════════════════════
🔴🔴🔴 平仓 · <标的代码> <中文名> · 平多/平空 🔴🔴🔴
════════════════════════════════════
```

| 项 | 值 |
|---|---|
| 标的 | 代码 中文名 |
| 方向 | 平多 / 平空 |
| 开仓价 | $X（开仓成交价）|
| 平仓价 | $P（市价成交价：主动平仓 = modify 止损触发 / 直接市价单，止损被动触发 = 触发价）|
| 盈亏 | ±$M（实际成交价算）|
| **实际落地赔率** | **±R 倍**（净盈亏 ÷ 开仓 max_loss = 仓位 × 开仓止损距；**平仓必填**，见下）|
| 过程指标 | mfe_R / mae_R（平仓脚本自动输出，见下；有则抄入，无则省略）|
| 理由 | 动能减弱 / 做空时回踩前低不破（下跌动能衰竭）/ 做多时回踩前高遇阻（上涨遇阻）/ 做空时资金流转正（买盘涌入）/ 做多时资金流转负（卖盘涌出）/ 到硬平仓时点（止损条件单被动触发只标记，不在此列）|

> **平仓必填实际落地赔率（2026-08-03 用户立；2026-08-04 改净口径；2026-08-12 改真实费率）**：平仓动作表格必须含「实际落地赔率 = **净**盈亏 ÷ 开仓 max_loss」（max_loss 用**开仓时**止损距离反推 = 仓位 × 开仓止损距，**毛值**、移动止损不改这个基准；净盈亏 = 毛盈亏 − [开仓边费 + 平仓边费]，开仓 / 平仓各按各自成交额算单边费——auto 平仓额用脚本返回的真实成交价 / 止损触发价；费率 = 老虎真实费率见 `risk-management.md`「费率与成本」，含佣金最低 / 印花税 / 阶梯平台费）。**盈亏金额看不出「承担了多少风险换来的」**——同样赚 $5000，max_loss $5000 是 1R、max_loss $10000 只算 0.5R；实际落地赔率才反映真实性价比，与开仓记录的初始预期 / 修正预期赔率对照，能直接看出「预估→修正→落地」的打折程度（如 2026-08-03 MU 空：初始 2.86R → 修正 2.06R → 实际 −0.92R，预估乐观但被板块 V 反打破止损）。被动平仓（止损触发）也照填。**开仓条目在平仓后回填实际落地赔率**，让该笔三阶段赔率（初始预期 / 修正预期 / 实际落地，均净口径）齐全于一处。

> **费用与成交价的唯一权威口径（2026-08-16 立，消除双口径并存）**：同一笔交易的**费用、成交价、max_loss 三个数字，唯一权威 = 脚本 JSON 输出 + `fee_schedule.py` 复算**——动作记录（actions/）转录时**直接抄脚本输出的字段值**（`fill_price` / `avg_fill_price` / `stop_loss` / 脚本返回的止损触发价），费用一律按 `fee_schedule.fee_per_side` 复算（review.py 与其同源），**禁止手算 / 心算后再写一个略不同的数**。背景：2026-08-10 药明、08-12 旭创等约 8 笔交易在源记录与 review.py 复算间存在两套费用 / 两套 R（最大差 13,914 HKD），复盘报告按 review.py 自洽、但读者拿复盘表对源文件会得出「同一笔 R 不同」；根因是源记录手写费用、review 脚本精算，两套口径并存。裁定：**复盘统计一律以 review.py / fee_schedule 口径为准**；源记录若与复算不一致，在复盘时以复算值修正源记录并注明「2026-08-16 按脚本口径校正」。max_loss 同理——「实际」字样的 max_loss 必须用成交价口径（仓位 × |成交价 − 止损价|），参考价口径的只能标「预期 max_loss」（2026-08-13 MINIMAX 开仓条目已按此修正）。

> **平仓过程指标 mfe_R / mae_R（2026-08-05 立，复盘数据约束方案 b 落地）**：平仓脚本（close_position_tiger / _us）在成交后**自动输出** `mfe_R` / `mae_R`（+ `entry_price` / `raw_high` / `raw_low`）——持仓期间极值取当日盯盘 log 采样近似（日内当天开当天平）、止损距 = 开仓价 − 活动止损触发价（毛值，与复盘口径一致）；无盯盘 log 或缺止损价则不输出该字段。**转录动作表格时照抄这两个字段**（有则必抄），复盘时直接补进 trades.csv 的 `raw_high` / `raw_low` 列、review.py 即能算 MAE / MFE / 回吐 / 锁利效率 η，不必回拉历史 K。口径与 review.py 一致：MFE_R = 有利方向最大幅度 ÷ 止损距（正）、MAE_R = −不利方向最大幅度 ÷ 止损距（负，越接近 0 防守越好）。

**移动止损 🟡**（浮盈中上移锁利）：

```
════════════════════════════════════
🟡🟡🟡 移动止损 · <标的代码> · 新止损 $Y 🟡🟡🟡
════════════════════════════════════
```

| 项 | 值 |
|---|---|
| 标的 | 代码 中文名 |

## auto 专属硬护栏（下单前逐条自检，违反不得下单）

> 公共硬护栏（标的范围 / 衍生品禁令 / 单持仓 / 盯盘时段 / lot_size / 单笔预算与 max_loss 概念）见 `SKILL.md`「硬性护栏」。下面是 auto 模式专属的下单护栏。

1. **开仓止损用附加止损腿（OrderLeg('LOSS')，主单成交才激活），一律市价触发（2026-07-31 用户新规）**。「主订单 / 附加订单」**不是订单的固有分类**——订单本质按类型分（`LMT`/`MKT`/`STP` 等），「主/附加」只是开仓把主单 + 止损腿打包一次提交时的相对称呼（主单 = 开仓市价单 MKT（默认，`--order-type lmt` 切限价）、附加 = 跟随提交的止损腿），**只在开仓场景才有**（2026-08-07 paper 实测：MKT 主单 + 附加腿同样支持、腿落成独立 STP——不再限定限价主单）。开仓场景的操作要点：
   - **开仓**：一次提交主单（默认 MKT 市价单，高波动标的不被限价 + 超时甩开；`--order-type lmt` 切回限价单控价）+ 附加止损腿 `OrderLeg('LOSS', 止损价)`（`trade_utils_tiger.submit_order_with_stop_tiger`）。附加止损随主单提交、主单成交才激活，开仓失败止损不残留；附加腿的方向与触发符号由券商后端按主单方向自动定（与主单相反）、无需传 side。
   - **禁止限价止损**（独立止损用 `STP_LMT` 限价触发单）：止损单一律市价触发（`STP` 触发后市价成交）。限价止损委托价不合理时有无法及时成交的风险（老虎官方：止损限价单「若委托价格设置不合理，有无法及时止盈或止损的风险」），故本 skill 提到「止损单」默认指市价止损单；`move_stop` 移损 fallback（无活动止损 / modify 失败）下新止损单时也一律用市价止损单。
   - **止损只能用条件单（`STP` 或附加腿 `LOSS`），不能用反向的普通订单（`LMT`/`MKT`）冒充**：`LMT`/`MKT` 没有「价格到触发价才成交」的语义，要么挂单要么立即成交，起不到条件止损作用（2026-07-31 MU 事故的真因之一正是误用市价单当止损——提交即按市价成交、瞬间平仓亏 $119，见 CHANGELOG 2026-07-31）。这才是「禁止反向订单止损」的正确含义——不是说止损单不能反向（止损单本就和开仓反向），而是说**不能用一笔反向的普通订单冒充条件止损单**。
   - **触发价 = 目标止损价**（允许小范围偏差）；用户也会在 App 手动新增止损单，故最新止损价不能凭记忆，`monitor_segment.py` 每轮采样查账户当日订单获取最新止损价。
2. **AI 直接下单**：港美股默认都用老虎开放平台模拟账户，AI 拍板后调用对应脚本直接下单（港股 `*_tiger.py` / 美股 `*_tiger_us.py`，市价单（默认）/ 限价单 + 止损条件单）。如用户不使用默认账户会特别说明。
3. **开仓 / 平仓触发**：① 开仓必带止损条件单（脚本自动设置，止损单用市价单）；② 平仓在动能减弱 / 做空时回踩前低不破（下跌动能衰竭）/ 做多时回踩前高遇阻（上涨遇阻）/ 做空时资金流转正（买盘涌入）/ 做多时资金流转负（卖盘涌出）/ 到硬平仓时点时由 AI 调脚本执行；③ AI 最高频盯盘，触发条件一到立即执行，出手要快。

## 执行反馈

AI 调用脚本下单后，脚本 JSON 输出 order_id 和成交价，AI 据此记录动作文件并按成交价继续盯盘。若脚本报错（价格不在范围内 / API 错误），AI 据错误信息调整策略。持仓状态从脚本输出跟踪，不需要假设。
