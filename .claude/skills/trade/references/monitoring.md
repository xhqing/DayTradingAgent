# 盯盘机制与采样（详细参考）

> 本文件是 trade skill `SKILL.md` 的盯盘持续性、后台采样、防中断、方向研判、脚本库、采样频率工程参数的详细参考。`SKILL.md` 只保留盯盘工作流骨架（preflight → 方向研判 → hot_list → 监控循环 → 停盯）；机制细节、脚本用法、采样参数全部在本文件。盯盘启动、段间循环、被打断恢复时读取。

## 盯盘持续性

**AI 不自主启动盯盘，收到用户的盯盘指令才开始**；启动后**未叫停就持续盯，不中途停下等用户**。靠**后台分段采样脚本（`monitor_segment.py`，每段 40 秒）+ 段结束完成通知驱动**维持（机制详见下「采样频率」），任务不因单轮对话结束而终止——无机会时一行带过继续盯，不暂停问「要不要继续」。方向研判、找标的、盯盘面、开仓、平仓全程连续推进，直到**用户喊停、或撞上强制终止盯盘边界**为止。港股两个强制边界：港股 12:00 午休前（主动平仓 + 终止盯盘，13:00 午市不自动恢复、等用户指令）、港股 16:00 收盘前（主动平仓 + 终止盯盘）。美股不设固定终止时点——盯到**用户发出停止盯盘指令**（大概率北京晚上睡觉前）或**美东 16:00 收盘**（取先到者），停前主动平仓、不留单。

## 后台采样不间断规矩（盯盘持续性的机制保障，最高优先级）

盯盘启动后，**后台分段采样（`monitor_segment.py`）必须持续运行——每段结束立即重启下一段，形成不间断循环**。这是「未叫停就持续盯」**唯一的实现机制**：靠每段采样结束的 task-notification 自动唤醒 AI，AI 读完数据重启下一段，循环往复；**用户不需要每次呼叫，AI 自己靠通知醒**。

**只有以下两种情况允许停止采样**：① **用户明确喊停**（发出「停止盯盘」指令）；② **休市 / 收盘**（港股 12:00 午休前已主动平仓后、港股 16:00 收盘后；美股美东 16:00 收盘后）。**除此之外的任何情况都不得停采样**——包括平仓后空仓、观望、无机会、横盘震荡、等下一个机会等，采样都必须照常运行（空仓观望时优先换标的密盯而非降频死盯，见「采样频率·标的不值得密盯时优先换标的」；早盘 09:30-12:00 不得放稀）。

**为什么不能停**：停了采样 = 没有段结束通知 = 没有自动唤醒源 = AI 静默着不会自己醒来找机会，等于事实上暂停了盯盘，「未叫停就持续盯」名存实亡。**2026-07-23 教训**：阿里平仓后 AI 停了采样、只说「空仓观望」，结果没有唤醒源，用户不呼叫 AI 就不醒——「未叫停就持续盯」成了空话。**只要用户没喊停、且未休市/收盘，后台采样就不能停；AI 靠采样通知自动循环盯盘找机会，不依赖用户呼叫**。

## 采样链防中断（AI 自检 + 备份唤醒，保 40 秒密采样的可靠性保障）

上文规矩靠「每段 task-notification 唤醒 AI 重启」驱动，但**通知机制非 100% 可靠**——会话长时间运行 / 上下文压缩 / 状态切换时 task-notification 可能失效，一旦失效采样链即断（AI 不被唤醒、采样不重启）。

**2026-07-28 中断事故**：盯盘 3.5 小时后最后一段结束通知没唤醒 AI（会话状态切换致失效）+ AI 刚平仓止损主观放松（没主动重启采样）→ 采样断 9.5 小时（空仓无持仓损失，但错过美股剩余 4 小时行情）。排查确认非系统睡眠（caffeinate 在跑）、非数据源掉线（OpenD 在监听）、非进程崩溃（分段正常 CallClose 退出），纯是通知没送达 + AI 没自检。

**核心原则：保 40 秒密采样是重中之重——靠「AI 自检 + 备份唤醒」防中断，绝不改持续模式**。

⚠️ **不得改为长时段持续模式**（脚本一次跑 30-60 分钟不退出）：task-notification 只在「命令结束」时触发，脚本不退出就没有结束事件、AI 中间不会被唤醒；若改用 ScheduleWakeup 定时唤醒，其最小间隔 60 秒（> 40 秒），**违反「早盘 ≤ 40 秒密采样」规矩**。长时段持续模式与「每 40 秒唤醒 AI」互斥，只适合不需频繁介入的低频监控（午盘缩量、只盯关键位突破），**盘中密采样场景禁用**。**正解：保持分段 40 秒（task-notification 主驱动）+ AI 自检纪律 + 备份唤醒**。

### 防中断三件套

1. **AI 自检纪律（最关键、确定有效）**：每次被唤醒（无论 task-notification 还是备份唤醒）**第一个动作 `ps aux | grep monitor_segment` 查采样进程在不在** → 不在则立即重启（不等、不假设通知会再来）。不依赖「通知一定来」，而是「每次醒都确认采样在跑」——即便 task-notification 偶发失效，只要 AI 被任何机制唤醒一次，就能发现并重启采样。
2. **大动作后强制复查采样链**：**平仓 / 止损后必须复查采样仍在跑**——平仓/止损是「易放松点」，刻意复查采样（这是「后台采样不间断规矩」「空仓也不得停采样」的兜底执行）。
3. **备份唤醒（增强，消单点故障）**：盯盘启动时设 `ScheduleWakeup` 每 5-10 分钟定时自检（`delaySeconds` 300-600，`prompt` 带「采样链自检：ps 查 monitor_segment 在跑否、不在则重启」），task-notification 正常时它不抢戏、失效时它兜底唤醒 AI 重启采样；每次触发后重新设一个（滚动续保）到收盘/喊停。❌ **ScheduleWakeup 已实测不可用（2026-08-05）**：非 /loop 上下文调用直接报「Wakeup not scheduled. Either the /loop dynamic runtime gate is off or the loop reached its maximum duration」，普通盯盘会话无法用它定时唤醒——**备份唤醒仅存于 /loop 场景**，普通盯盘回退到核心靠①②（AI 自检 + 大动作复查）——这两条已能堵住「通知失效 + 主观放松」的漏洞；**盘前→开盘的唤醒衔接另走「盘前启动：港股只预热、美股盘前即可交易」节的提前启动 monitor_segment 规则**（task-notification 从盘前持续驱动、不依赖定时唤醒）。
4. **每段自查未擅自降频（D11，2026-08-04 立）**：AI 每次被唤醒读段结束输出时，自查「monitor_segment 循环在跑、本段由 monitor_segment 产生（非 cron / 直接 snapshot 替代）」——软约束（会忘），但与「多层防护」（见下「不因市况降频」节）的 hook / gap 复盘 / 用户监督配合，提高降频暴露率。

**盯盘启动清单显式列入三件套**：启动时 ① 盘前启动的按「盘前启动」节提前启动 monitor_segment 保开盘唤醒（ScheduleWakeup 已实测不可用、不再尝试）；② 每次唤醒第一个动作 ps 自检采样；③ 大动作（平仓/止损）后复查采样链。

## 时间断层哨兵（被动感知，`monitor_segment.py` 内）

`monitor_segment.py` 启动时读各标的 log 最后采样时间，距现在 ≥ 5 分钟（正常段间循环 < 1 分钟）即输出醒目警告：「⚠️ 时间断层哨兵：距上次采样 X 分钟，先跑 `resume.py` 重建上下文、刷新现价，禁止直接用断层前旧数据下单。」——即便 AI 没主动意识到断层，脚本强制提醒（AI 不能只靠记忆执行规定、要靠工具强制，见 `references/trading-strategy.md`「盘中动态修正方向」）。

## 盯盘启动方向研判（盯盘第一步定当日基调）

盘中找标的（hot_list）是「看今天什么在动」，但缺一步先定「今天大方向偏多还是偏空」。本研判用**多维度独立打分后综合**，定当日方向倾向，缩小找标的范围（只做顺势方向）——避免见涨追涨、逆势开仓。

**时机**：盯盘启动的**第一步**，在 `preflight` 之后、`hot_list` 之前——**无论用户何时叫醒盯盘（盘前预热或已盘中）都先跑一次**，产出：一句话「今日港股/美股偏多 / 偏空 / 中性震荡」。盘前启动用隔夜外围 + 指数结构判基调；盘中启动数据更全（有实时资金流 / 量价），照样走这五维度。核心是「**先定方向再找标的**」，时点不限、不是只在盘前做。

**五个维度独立给倾向**（每维偏多 +1 / 中性 0 / 偏空 −1，最后求和定向）：

| 维度 | 看什么 | 来源 |
|---|---|---|
| **宏观基调** | **最近一根**美股日 K 收盘涨跌 / 美 10 年期国债收益率方向 / 美元指数 / VIX；今日有无央议息、CPI/非农、重大政策 | 富途 `get_market_snapshot` 查美股主指数 / ETF；外围消息看新闻。⚠️ **「最近一根」≠「昨夜」**：周一开盘时最近一根是**上周五**（周末美股休市），节假日后开盘同理跨假期——须跨周末/假期核对期间事件（地缘/政策/数据），不许说「昨夜」、不许忽略中间跨度 |
| **技术趋势** | 目标市场指数近 5 日 K 线结构（上升 / 下降 / 横盘）、距关键支撑阻力远近 | `scripts/kline.py <指数代码> 5` |
| **量价** | 指数近几日涨跌是否带量（量价配合 = 趋势健康，背离 = 虚弱） | kline 量柱 |
| **资金流** | 目标板块 / 标的资金净流向（盘前数据有限，开盘后用 `capital` 复核） | 富途 `get_capital_flow`（盘中）|
| **事件催化** | 当日有无个股 / 板块级事件（财报、产品发布、政策落地）——事件日波动大、方向不定 | 财经日历 |

**综合定向**：
- 和 ≥ +2 → 今日偏多，找标的优先找顺势做多机会（hot_list 后叠「近 5 日上升趋势」过滤）。
- 和 ≤ −2 → 今日偏空，优先找顺势做空机会。
- 其余 → 中性震荡，按区间交易思路（支撑买 / 阻力卖，见 `references/trading-strategy.md` 区间震荡条），降低开仓预期。

## 位置评估（当前价在大趋势中的位置 = 盘中方向假设的关键，优先级高于五维度求和定向）

五维度求和给的是「大趋势方向」（偏多/偏空），但日内盘中走哪边还要看「**当前价在大趋势中的位置**」——同一支下跌趋势股，处在上沿（超买）和处在下沿（超跌）的盘中方向完全不同：

| 当前价位置 | 盘中倾向假设 | 即使大趋势 |
|---|---|---|
| **下沿（超跌区）**：接近最近 ≥4 个月日线低点连线 / 重要支撑 / 短期大幅超跌 | **超跌反弹做多假设**（等企稳做多、不空）| 即便大趋势空，下沿超跌最可能深 V 反弹 |
| **上沿（超买区）**：接近最近 ≥4 个月日线高点连线 / 重要阻力 / 短期大幅超买 | **回调做空假设**（等遇阻做空、不多）| 即便大趋势多，上沿超买最可能回调 |
| **中段** | **顺势大趋势方向** | 下跌中段续空、上涨中段续多 |

**怎么判断位置**：盯盘启动时 `python3 scripts/kline.py <标的> 120`（如 `US.MU 120`，约 4 个月交易日；**判断大趋势至少拉 4 个月日线**——短周期看不出真趋势通道）画高点连线（上沿阻力）+ 低点连线（下沿支撑），开盘价/现价接近哪沿即位置判据；**大趋势方向 × 位置 = 今日盯盘方向假设**（例：大趋势空 + 下沿超跌 → 超跌反弹做多假设；大趋势空 + 中段 → 顺势做空假设）。

2026-07-17 反面教训：MU 开盘 804，从 7/9 高 1035 一个月跌 -22%、804 处在这段下跌**下沿**（接近一个月低点）= 超跌区。即便半导体大趋势下跌，开盘在下沿超跌最可能深 V 反弹——我却只看「大趋势偏空」就定做空、等「反弹遇阻做空」，完全错过 804→880 深 V（-22% 超跌后 +9.5% 反弹）。**正确：开盘前 `kline.py US.MU 30` 看位置（下沿超跌）→ 立超跌反弹做多假设 → 等企稳做多**，而非等「突破 2-3 道阻力」才被动转多（那已错过最佳段）。**位置预判是主动打头、盘中动态修正是被动兜底，两者叠加**（位置预判可能错，动态修正来纠偏）。

**重要边界**（避免误用）：
1. **本研判是「大方向参考 + 选标的过滤」，不是盘中信号**。方向偏多不代表立即追多，仍要等盘中合格入场点（回踩企稳 / 真突破站稳，见 `references/trading-strategy.md`「做多合格入场只有两种」）。
2. **宏观基调维度较慢**，只影响「今日整体偏多偏空」的背景判断，不进实时盯盘链路（盯盘看秒级盘口，宏观是背景）。
3. **事件催化日**（CPI / 非农 / FOMC / 财报）方向不定但波动剧：优先上逐笔每秒密采样（见下「重要数据日优先密采样 WebSocket」），开盘后等波动消化再入场、不抢第一波。
4. 中性震荡日**不是不开仓**，而是切区间交易（支撑买 / 阻力卖）、降单笔预期、止损更紧。

## 盯盘脚本库（前置准备固化，盯盘直接调勿临场重写）

路径 `.claude/skills/trade/scripts/`（富途 API 签名已验证，盘后实测可用）：

- **盯盘第一步** `python3 scripts/preflight.py` — 时间 / 港股美股时段 / 富途 OpenD 端口 / signals 当天文件 / **自动启用 caffeinate 防系统睡眠**（防时间误判 + 数据源掉线 + 防睡眠断采；**先跑这个**）。
- **找标的** `python3 scripts/hot_list.py HK 15`（或 `US`）— 热度榜 + 叠 snapshot 查成交额/振幅/换手（找标的铁律第一步）。
- **标的快照** `python3 scripts/snapshot.py HK.07709,HK.07747` — 现价/OHLC/lot/成交额/振幅/买卖比/量比。⚠️富途脚本（snapshot/kline/hot_list）代码均须带市场前缀 `HK.`/`US.`，美股写裸 `SPY` 报 `format of code SPY is wrong`，正确 `US.SPY`。
- **富途指数代码 ≠ 股票简称**：查指数趋势用 `kline.py HK.800000`（恒生指数 HSI）/ `HK.800700`（恒生科技 HSTECH），**写 `HK.HSI`/`HK.HSTECH` 报「未知股票」**——富途里指数是 `8xxxxx` 编码、不是股票简称。指数 `volume=0`、`turnover` 为成分股成交额属正常。方向研判的「技术趋势/量价」维度查这两个代码（用盈富 `HK.02800` 作恒指 ETF 代理亦可，但它含 H 股权重、非纯恒指走势）。
- **趋势+回撤** `python3 scripts/kline.py HK.07709 8` — 近 N 日 K 线 + 斐波那契回撤位（0.382/0.5/0.618/0.786）。

## VWAP 必看（看全貌必带 VWAP）

盯盘判行情性质 / 方向 / 位置时，**必须把 VWAP（富途 `get_market_snapshot` 的 `avg_price` 字段 = 成交量加权均价）和价格一起看**，`monitor_summary.py` 全貌摘要已自动输出 VWAP（含现价相对 VWAP 的上方 / 下方位置）。VWAP 的三个作用：

1. **日内多空分界**——价格在 VWAP 上方 = 多头占优、下方 = 空头占优，站上 / 跌破 VWAP 并企稳 = 日内多空转换（呼应「盘中动态修正方向」③）。
2. **趋势日判断**——VWAP 震荡向上（均价逐级抬升）= 多头趋势日、向下 = 空头趋势日，**低开高走 + 价格站上 VWAP = 多头反弹日**。
3. **顺势入场**——多头趋势日价格回踩 VWAP 企稳 = 经典做多入场（动态支撑），空头趋势日反抽 VWAP 遇阻 = 做空入场。

**为什么必看**：只看价格区间 / 箱体 / 盘口 / 资金流、漏了 VWAP，会把「低开高走的多头反弹日」误判成「震荡日」，导致策略方向错（震荡日等两端区间交易 vs 多头日顺势做多）。**2026-07-22 MU 教训**：MU 低开 938.2（昨收 970.82）高走 979、VWAP 959、价格全程在 VWAP 上方，只盯价格 966–979 反复就判「震荡日」、策略偏保守等深回踩 952，是错的——VWAP 向上 + 价格在 VWAP 上方 = 多头反弹日，应顺势做多（等浅回踩 966 / VWAP 959 企稳，而非等深回踩 952）。

**📊 段结束必看 VWAP 输出（强制锚点，2026-08-03 立）**：`monitor_segment.py` 段结束自动打印「📊 VWAP 检查」——每个被采标的的现价 / VWAP / 相对位置（上方多头占优 / 下方空头占优）。**段结束唤醒 AI 后第一眼必看这段输出**（它和段结束通知一起到，跳过它 = 跳过整段输出），作为方向框架的地面真相，不靠记忆去跑 `monitor_summary` 才看 VWAP。**2026-08-03 07709 教训**：盯盘全程只看 `tail` 单点价格/买卖比、没看全貌 + VWAP，把「低开高走偏多日」（VWAP 36.72 上方）定性成「空头日」一上午、错过回升段——根因是看 VWAP 靠记忆触发、无强制锚点。**边界**：段结束 VWAP 检查给「现价 vs VWAP 位置」这一个维度；**全貌摘要（`monitor_summary.py` 的箱体测试 / 买卖比演变 / 行情性质判别）仍要定时重跑**（每 10 分钟或行情性质可能变化时），两者互补不替代——VWAP 位置是方向即时片断、全貌是行情性质全览。

## 采样频率：后台分段采样脚本、每段 40 秒

盘中（港股 09:30-12:00 / 13:00-16:00、美股美东 04:00-16:00 含盘前，2026-08-18 立规）用采样脚本**后台连续密采样**——独立进程、不受会话状态影响，每段跑固定时长（标准 **40 秒**），段结束自动触发 harness 的 task-notification 通知 AI 读取分析 + 重启下一段。实际分析周期 = 40 秒采样 + 读数分析重启开销 ≈ 55-65 秒（略长于 40 秒）。盯盘启动后 AI 自主循环「启动后台段 → 等段结束通知 → 读数据 + 分析 + 汇报（汇报必含下次段结束时间）→ 重启下一段」，直到用户喊停或撞上强制终止边界。

### 为什么不用 cron

cron（无论 session-only 还是 durable 写盘）在此环境触发**不可靠**——它只在 REPL 特定 idle 态触发，会话卡顿（如富途 `capital_distribution` 接口卡死占用会话）、用户消息插队、Stop hook（如 `/goal`）都会挡住它，实测一上午多次中断（10:17、10:38、10:56 等，用户反复提醒才发现）。**后台任务完成通知（task-notification）是 harness 核心机制、远比 cron 可靠**，用它驱动盯盘循环不再无故中断。⚠️ task-notification 也**非 100% 可靠**（会话长时间运行 / 上下文压缩 / 状态切换时偶发失效，2026-07-28 实测过一次断链 9.5 小时），**靠「采样链防中断」三件套兜底**（AI 自检 + 大动作复查 + 备份唤醒，见上「采样链防中断」段）。判别：看到 cron 注册还在（`CronList` 有）却不触发 = 此环境 cron 失效，转分段采样。

### 突破即时响应（关键位提前通知）

每只标的的关键位（阻力 up / 支撑 dn）随命令行传入（targets 的 `SYM:up:dn`，见上「分段采样盯盘」用法），**不写死在脚本里**。脚本检测到某只标的 high 创本段新高且 ≥ 它的 up、或 low 创新低且 ≤ 它的 dn，立即 `break` 退出、提前触发通知，突破响应延迟从段时长（≤40 秒）压到 ~10 秒（下一次采样）。**多只票任一破位都提前结束整段**（第一时间叫 AI 来看）。盯盘启动做方向研判时为每只候选标的定好关键位、随命令行传入。

### 不因市况降频

无论趋势 / 区间震荡、有无持仓、早盘 / 盘中 / 尾盘、有无机会，一律每段 **40 秒盯盘、10 秒间隔** 密采样。**盘中（港股 09:30-12:00 / 13:00-16:00、美股美东 04:00-16:00 含盘前）AI 不得以任何理由自主修改采样频率**——不放稀 DURATION（脚本 >40 已强制夹回）、不在段与段之间加 `sleep` 等待拉长段间隔（DURATION 虽仍是 40、但段间 `sleep` = 等效降频，2026-08-04 教训）、不换 cron / 直接调 snapshot 绕过 `monitor_segment.py`（2026-08-04 cron 教训）。**采样频率是死规矩，不是 AI 可按市况权衡的参数**——市况好坏只决定「盯哪个标的」，不决定「盯多密」。

**密采样定义 + 早盘必密**：**分段采样段时长 ≤ 40 秒才叫「密采样」，> 40 秒（60-180 秒）算稀疏采样**；**早盘必须密采样**——**早盘 = 港股 09:30-12:00 HKT / 美股 09:30-12:00 ET**（整个上午交易时段），此时段段时长必须 ≤ 40 秒、不得放稀到 60-180 秒（早盘波动集中、机会与风险都在这，稀疏采样会漏掉冲高又回落的完整动作、分不清真突破与诱多）。开盘首小时（港股 09:30-10:30 / 美股 09:30-10:30 ET = 北京夏令时 21:30-22:30、冬令时 22:30-23:30）急涨急跌最剧烈，可更密到 30 秒。美股 09:30 开盘前后（盘前尾段 09:00-09:30 + 开盘首小时）是盘前流动性切换到盘中流动性的过渡带、波动常加剧，同样保持 ≤40 秒密采样（盘前全程本就属可交易时段、无放宽理由）。

**段时长盘中固定 40 秒、AI 不得自主调**：盘中一律 `monitor_segment.py <targets> 40 10`，**不存在「更稀 60-180 秒」的合法选项**——原「更稀可改 60-180 秒」allowance 已于 2026-08-04 撤销（AI 一旦被允许降频，就会在震荡无机会时滥用：要么放稀 DURATION、要么段间 `sleep` 死盯一个标的空耗，违背下文「没机会换标的」）。脚本 DURATION > 40 强制夹回 40 只是工具护栏，AI 不得尝试传 > 40、更不得用 `sleep N; monitor_segment` 把段间隔从 ~10 秒拉到几分钟来绕过（2026-08-04 阿里僵局时 AI 用 `sleep 600` 降频死盯，被用户两次抓住）。开盘首小时急涨急跌最剧烈可更密到 30 秒（`monitor_segment.py <targets> 30 10`），这是「更密」不是「降频」，允许。

### 单段循环是唯一合法形式：禁止一条命令连跑多段（2026-08-05 教训）

**段结束进程归 0 = 正常，不是断链**。`monitor_segment.py` 单段跑完即退出、等 AI 收到段结束 task-notification 后重启下一段——段间进程短暂归 0 是设计使然（真实断链 = 段结束通知到了 AI 没重启）。

**禁止一条 Bash 命令串联多个 monitor_segment（`&&` 连跑 2 段以上）**：连跑 = 段间 AI 不醒来分析、段结束通知只在全部段跑完后触发一次 = 等效把采样间隔拉到几分钟 = 降频违规（2026-08-05 教训：AI 误把「段结束进程归 0」当断链、用 `&&` 连跑 4 段「减少断链点」，被用户当场纠正——单段结束进程归 0 本就正常，连跑才是故障）。

**唯一合法循环**：单段 40 秒 → 段结束 task-notification 唤醒 AI → 读数据 + 分析 + 重启下一段。

**自查**：段结束通知输出若含多个「分段结束」标记（如 ==SEG2==/==SEG3==）或多次 VWAP 检查 = 连跑了 = 违规，立即恢复单段循环。

**工具护栏**：`monitor_guard.py` PreToolUse 已加检测——盘中单条 Bash 命令含 ≥2 次 monitor_segment.py 调用 → 阻断。

### 标的不值得密盯时优先换标的、而非降频（与「不因市况降频」协调）

当觉得当前盯的标的「不值得密盯」（缩量横盘无机会、陷入僵持、赔率凑不足、反复测试关键位不破等）时，**第一优先级是切换到值得密盯的标的**（有波动、有机会潜力、有交易价值的活跃标的），**而不是降低盯盘频率**（放稀到 60-180 秒）死盯当前标的。原因：降频死盯一个无机会的标的 = 既错过别的标的的机会、又在该标的上也抓不到机会（无机会时放稀更抓不到），**双输**；换标的密盯 = 保持密采样捕捉新标的突破，才有机会。

### 采样输出只留关键字段

（price / bid / ask / 买卖比 / 量比 / high / low / 额 + 突破标记），不打印完整 JSON（连续几十段会撑爆上下文）；AI 每段**三层分析**：

1. 先跑 `monitor_summary.py` 看全貌摘要判**行情性质**（震荡/多/空/中性，**每次重判、随时切换策略**——判断行情必须看开盘到当前全貌，最近 N 分钟看不出；**全貌必带 VWAP**，见上「VWAP 必看」条）。
2. 读 log 最近 N 行（`tail -60 tmp/monitor_log_*.csv`）看即时突破/回踩定入场时机。
3. **每段过「做空入场 checklist」+ 每 10 分钟「方向重估」**：a. **每段（约 1 分钟）必检做空信号**——反抽阻力乏力（多次不过 + 买卖比大负）？跌破支撑后反抽遇阻？**做空信号与做多信号同等优先、不能只盯企稳做多**；b. **每 10 分钟必重估方向**（`monitor_segment.py` 满 10 分钟打 ⏰ 提醒强制）——过「盘中动态修正方向」5 触发（见 `references/trading-strategy.md`）+ 自问方向/趋势/行情是否仍与开盘一致、不固守。

2026-07-28 反面教训：兆易空头趋势日，AI 一根筋盯企稳做多、看到反抽 480 乏力 + 买卖比 −54 却仍想做多，错过 R 2.8 顺势做空——根因是每段流程没有「做空 checklist」这一步、做空规则永远不被触发（与 7-27 MU「规定在 skill 里却没调用」同款）。三层结合精简汇报（盯盘汇报精简规则见下「盯盘对话输出要精简」，且**每次汇报必含下次段结束时间**）。

⚠️ **三层分析的产出底线 = 每段一行式判断行 + 分析心跳（2026-08-17 立）**：三层分析是流程、判断行是产出——分析做了但一句判断不给 = 等价空转（2026-08-17 实录：段结束只重启采样、0 分析文本，用户纠正后 10 分钟复发）。产出形态与心跳写盘见下「每段最小输出模板 + 分析心跳」节，那是硬流程不是可选项。

## 密采样工程参数（盘中任何时刻适用）

盘中任何时刻（尤其开盘首小时 港股 09:30-10:30 / 美股 09:30-10:30 ET 流动性集中、急涨急跌最快）都用这套参数——10-30 秒内可能完成一次冲高又回落的完整动作，稀疏采样只看到结果、分不清「真突破」与「冲高诱多」，胜负往往在这几秒到几十秒内决定。工程实测结论：

- **采样间隔统一取 10 秒**。配置读 `config.json` 的 `monitoring.early_session.sample_interval_sec`。
- **API 限流不是瓶颈**：富途 / 老虎连续调 quote/depth/capital（无 sleep）实测约 1.6 次/秒、**零失败零限流**；10 秒间隔负载（0.1 次/秒）远低于压力测试速率，间隔小不会触发限流。
- **物理下限约 15 秒/决策回合**：纯 CLI 调用约 0.6 秒/次，带「采样→读→决策」的回合约 15 秒；要秒级响应只能上 WebSocket 推送（见下条）。
- **采样输出只留关键字段**（price / bid1 / ask1 / 3 档差 / 大单净流），**不打印完整 JSON**：单轮 quote+depth+capital 约 1KB，连续几十轮会撑爆上下文，须定期摘要而非全量输出。

## 被打断就跳过、直接看最新数据

分段采样在跑期间若被用户消息、处理别的事、或漏掉段结束通知打断——**不纠结补读被打断的段、不重叠重启**，直接 `snapshot` 取当前最新数据（或重启一段新采样读当前）分析即可。避免「漏段 → 补读 → 重叠重启 → 多进程混乱」（2026-07-22 上午实战：漏读一段后试图补重启，结果两三个采样进程重叠、TaskStop 找不到 id，乱成一团）。一句话：**采样链断了就从当前时刻续上，不回头补**；用户消息优先处理，处理完用当下最新数据继续盯。

## 盘前启动：港股只预热、美股盘前即可交易（2026-08-18 修订）

**港股**盘前启动时只做准备（preflight、方向研判、hot_list），不执行交易动作；等开盘后才执行。**美股**盘前（美东 04:00-09:30）自 2026-08-18 起就是可交易时段——用户在盘前启动盯盘，preflight + 方向研判 + hot_list 照做，之后**可以直接在盘前执行四类动作 / 发信号**（开仓 / 平仓 / 移损 / 移盈，auto 下单链路已带 `outside_rth=True`），不必等 09:30。但**盘前流动性远低于盘中**（点差宽、成交量小、VWAP 与全貌数据基于盘前成交、代表性弱），开仓自查的形态确认要求相应更严，宁可错过盘前模糊信号等盘中确认。

⚠️ **盘前准备完成后必须安排开盘唤醒（2026-08-05 立）**：AI 是请求-响应式、回合结束即静止——盘前准备完成后直接结束回合，开盘时 AI 不会自动醒来盯盘（2026-08-05 09:24 盘前准备完成 → 09:30 开盘未自动醒、09:40 用户手动提醒；唤醒源只有用户新消息 / task-notification / 定时唤醒，三者缺一即无人叫醒）。**规则：盘前启动的盯盘，盘前准备完成（preflight + 方向研判 + hot_list 定出候选标的）后、若距开盘 ≤ 15 分钟，立即提前启动 `monitor_segment.py` 盯候选标的**（带关键位、`--mode` 按 session 模式传）——段结束 task-notification 从盘前持续驱动 AI 醒来重启下一段、跨开盘自然进盘中，无需另设唤醒源。代价是盘前几段采到静态竞价价（无当日盘面意义、当日 log 开盘后自动接续），唤醒价值大于此代价。**港股盘前段 AI 醒来只重启下一段 + 一句话汇报（含距开盘时间），不做完整三层分析**；开盘后（09:30 起）恢复正常分析。**美股盘前（可交易时段）不受此限**——盘前段就是正常盯盘段，照常分析；美股会话若在美东 04:00 前（北京 16:00 / 冬令时 17:00 前）启动，04:00 前的准备段按港股同款「只预热 + 提前启动 monitor_segment 保唤醒」处理。**ScheduleWakeup 定时唤醒方案已实测不可用**（2026-08-05：非 /loop 上下文调用报「Wakeup not scheduled. runtime gate is off」），开盘唤醒唯一可靠机制就是提前启动 monitor_segment。

## 每段最小输出模板 + 分析心跳（空转防护硬流程，2026-08-17 立）

**背景（为什么立这条）**：2026-08-17 实录——auto 双会话采样链正常（段循环节奏正常、log 持续更新）但**分析链死亡**：一会话 14:02 后 0 分析文本、52 次纯重启采样；另一会话被用户纠正「每段给判断」后 10 分钟内复发。根因：①「每段三层分析」写在 reference 里是软约束（会忘、会衰减，与 2026-07-28 兆易「规定在 skill 里却没调用」同根因）；②「盯盘输出精简」与「每段分析」的张力被模型化解为近零输出。**只重启采样不分析 = 空转**，有持仓时空转 = 漏移损 / 漏主动平仓 = 直接亏钱面。

**规矩：段结束唤醒后，AI 必须先完成「一段分析」再重启下一段采样——分析产出走下面的最小输出模板，同时写分析心跳文件。两者都做完才允许启动下一段。** 这是硬流程，不是可选项；ws 系脚本（ws_segment / futu_ws_segment）段结束输出的「👉 空转防护」提示行与 monitor_segment 的 VWAP 锚点都是这个流程的工具级锚点。

**段内动作顺序 = 分析最先、其余一切靠后（2026-08-18 用户立，优先级高于本节其它顺序表述）**：拿到段结束数据的那一刻，**第一件事就是分析，期间不做任何别的事**——不先启下一段、不先写心跳、不先做任何准备动作。分析完成后**当场分流**：有机会（开仓 / 平仓 / 移损条件成立）→ **立即执行对应动作**（下单不排队、不等下一轮）；没机会 → 再做剩下的事（写分析心跳、重启下一段采样）。为什么：行情瞬息万变，「先启下一段再回来分析」会把手里最新鲜的数据放旧几秒（2026-08-18 实录：AI 自作主张把「先启下一段」排在分析前，被用户两次纠正）；而下单时机差几秒价就可能不同。分析的输入永远是「刚拿到的最新数据」，执行永远紧跟分析当下那一刻的结论。

### 每段最小输出模板（一行式）

每段唤醒后在对话里输出**一行**（格式固定、精简不啰嗦——精简体现在一行内说完，不体现在跳过不说）：

```
[HH:MM] <标的> 现<价> | 关键位 <支撑>-<阻力> | VWAP <值><上/下方> | <本段判断一句话> | 下段 ~HH:MM 结束
```

示例：`[10:23] HK.00100 现342.1 | 关键位 330-347 | VWAP 341.8 上方 | 回踩 VWAP 企稳、多头结构未破，持有观察 | 下段 ~10:24 结束`

- **「本段判断」必须真的给判断**（方向 / 持有 / 平仓 / 移损 / 观望等结论性词），不能只复述数字——复述数字 = 没分析 = 空转。
- **无动作时段照发这一行**（这就是「无机会时一行带过」的具体形态），一行就是合规的精简。
- 严重动作（开仓 / 平仓 / 移损 / 破位）按各自格式发完整信号 / 动作记录，此行照样给（作为该段的收尾判断行）。

### 分析心跳文件（空转的可检测信号）

**每段输出判断行的同一时刻，追加一行到 `tmp/analysis_beat_{YYYYMMDD}_{mode}.csv`**（mode = signal / auto，与采样 log 同口径分文件）：

```bash
echo "$(date '+%H:%M:%S'),<标的>,<一句话判断>" >> tmp/analysis_beat_20260817_auto.csv
```

- **为什么**：对话文本无法被外部程序检测，「采样在跑但分析链死了」此前全系统绿灯（旧 watcher 的「采样在跑 → 一律不报」分支恰好放行空转）。心跳文件给分析链一个**可被外部检测的落盘信号**——monitor_guard 据此在「重启采样但心跳不新鲜」时阻断（见 `.claude/hooks/monitor_guard.py`；watcher 侧的空转警报 2026-08-21 删除，watcher 仅剩白名单漂移检测）。
- **心跳节奏**：每段一次（约 55-65 秒一次），与段结束循环同拍；心跳文件 > 3 分钟无更新 = 分析链疑似死亡（采样可能还在跑）。
- **文件可缺省重建**：文件不存在时 echo 直接创建，无需表头。

## 多会话并行盯盘（方案 A：单持仓互斥 + 各盯各池，2026-08-17 立）

**模式**：同一市场开 N 个会话（建议先 2 个），每会话盯一个标的池。风控语义不变——**全局任意时刻仍至多一笔在场**，后到机会被互斥闸挡住、继续盯等下一机会（先到先得）。资金并行留待方案 B（未立项）。

**标的池自动划分（2026-08-19 立，认领制，替代旧「用户手动划分」）**：每会话启动时从共享候选池**认领**一段未占用标的，系统保证彼此互斥（同一标的不落两会话、无重复盯）——用户不再手动给每个会话划分。机制 = `scripts/pool_claim.py` + flock 锁内「检查占用 → 登记」原子完成：

1. **启动序列内认领（无论 auto 还是 signal 会话都要认领）**：preflight → 方向研判 → `hot_list` 定出本会话候选标的后、启动采样前，跑 `python3 scripts/pool_claim.py claim HK.00700,HK.00981,...`——候选里未被占用的登记给本会话，已被其它会话认领的返回 ❌ 冲突（从候选去掉）。⚠️ 不带「多会话并行时才认领」的条件——**只要认领表机制启用（表里有活认领），任何会话不认领就不给采样**（2026-08-20 港股实录：两个 signal 会话以为「多会话才需要认领」跳过了 claim，与 auto 会话重复盯 00100/01810/09988 一小时；同日修复后 hook 会硬拦，见第 5 条）；
2. **死会话自动释放**：认领时顺手检查全部持有者的会话活跃度（jsonl 停更 > 30 分钟 = 已结束，即旧 monitor_watcher 死会话剔除的同款口径、2026-08-20 watcher 收缩后由 pool_claim 自持），死会话的标的自动释放回池；
3. **停盯释放**：`monitor_unregister.sh` 已联动跑 `pool_claim.py release --all`（停盯注销时同步释放本会话认领）；
4. **池内僵局换标的**：换入的新标的先 `claim`（未占才可用）、换出的旧标的 `release <标的>`——互斥语义持续成立；**不跨池抢标的**；
5. **工具强制（三层拦截，2026-08-20 扩）**：`monitor_guard.py` 在启动采样段时三层检查（PreToolUse 阻断 + 提示处理方式）——① 跨池冲突（targets 含其它会话已认领标的）；② 本会话未认领就采样（认领是采样的前置）；③ targets 含无人认领的孤儿标的（换标的没先 claim 的「先斩后奏」）。同日修复**管道绕过失效**：真实采样命令几乎都带 `2>&1 | grep -vE …` 输出管道，旧「提及未执行」排除逻辑把管道里的 grep 误当命令本体，导致本拦截（连同连跑 / 跑法 / 空转三项检查）对管道形态命令全部失明——2026-08-20 修复后排除词只看管道首段。层②③只在认领表存在活认领时生效（单会话 / 认领制未用 / 认领者全死 → 不拦，不误伤）；hook 侧同口径剔除死会话认领（只读、不写回，真正落盘清理由认领者下次跑 pool_claim 时完成）。
6. **🚫 ETF 优先认领闸（2026-08-28 用户立，硬拦，`pool_claim.py` 内置；2026-08-28 午按用户裁定重构为「按盯盘方向」）**：认领标的时**先选没人认领的 ETF，个股只有在不存在「可认领 ETF」时才能认领**。认领范围 = **按盯盘方向**——候选里 + 热榜里与候选**同方向**的 ETF 必须优先认（同方向判定：`pool_claim.py` 的 `_direction_similar` 按代码 2 位前缀匹配，如 03067 恒科 ETF 与 03110 恒科 ETF 同属 03 段）；**不强制把全市场热榜 ETF 全灌进池子**（那样一认个股就要 release 一堆强加 ETF、池子巨大难盯，2026-08-28 用户明确否决全市场口径）。**为什么（当日实录）**：00700 第二笔止损 −1R 里 0.42R 是印花税，同笔若选 ETF 只亏 −1.19R；「港股优先 ETF」旧规只是偏好、税闸过了就跳过 ETF 核查——本闸把它变成机械强制。**口径（脚本内置）**：① 只拦「实际可认领」的 ETF——被别的会话认走的 ETF 不算（互斥语义优先、不逼 AI 跨池抢）；② 本会话已持有的 ETF 同样构成约束（池里已有 ETF 还来认个股 = 违背优先级）；③ 类型判定失败（`?`）不拦（判不了不瞎拦，认领链路不因分类器故障停摆）；④ 美股候选不参与本闸（美股个股无印花税劣势）；⑤ 拒绝是「本次不登记」而非全局拉黑——`release` 掉 ETF 后可再 claim 个股，**release 掉的 ETF 不自动认回（released 放弃清单）**；⑥ 热榜取不到（富途故障/榜单空）→ 退化为「只按候选内 ETF 判定」（仍拦候选内 ETF 存在时的个股）。**边界**：闸只在 claim 时判类型（复用 `classify_hk_security`）；候选无同方向 ETF、热榜也无同方向 ETF 时，认个股不受阻——**「不存在可认领 ETF」按字面执行，不扩展到「强行找一个不相关的 ETF 顶替」**。

**启动序列**（每会话独立走一遍，互不冲突）：

1. `preflight.py`（正常跑——互斥状态输出会显示 intent 链、常驻白名单、在场会话数、当前标的池划分；caffeinate 全局一进程、第二家自动跳过）；
2. 方向研判、`hot_list` 定候选标的 → **`pool_claim.py claim <候选>` 认领本会话标的池**（见上；signal / auto 会话同规，不认领会被 hook 拦）；
3. 港股用 `futu_ws_segment.py`（避开老虎 WS 单连接互踢）、美股按常规（`monitor_segment.py` 10 秒快照或逐笔实测后升 `futu_ws_segment.py`）；
4. 开仓走 `open_position_tiger.py` / `open_position_tiger_us.py`——脚本已内置 `trade_mutex` 互斥（无需 AI 额外动作）。

**互斥行为（AI 必须知道的语义）**：

- 开仓脚本拿**全局一把 flock 锁**（港美共用、不分市场）→ 闸门三口径：① intent 有 pending（崩溃残留）拒开；② 当日已有在场敞口（开仓成交且无对应平仓）拒开；③ 有活动开仓挂单拒开。任一命中输出 `{"ok":false,"blocked_by":"..."}` 结构化 JSON——**AI 收到 blocked 不是错误，是「别人先到了」：继续盯自己的池、等敞口了结后再开**，不重试、不换池抢开。**被拦口径是 ② / ③（「别人在场」）时，按 blocked JSON 里的 `shadow_hint` 把这笔机会落成【影子交易】纸面样本**（`shadow_trade.py open`，2026-08-27 立——不丢弃被拦机会、复盘可统计；影子是 auto 模式分支、不下单不碰账户，详见 `auto-mode.md`「影子交易」节）。
- intent pending 残留（极少见：进程恰好崩在已提交未确认之间）：按 JSON 里的提示先查当日订单确认无在途单，再 `python3 scripts/trade_mutex.py --clear-intent <行号>` 清掉。
- **第四层兜底**：`monitor_segment.py` 每轮采样检测白名单外双持仓（用户手机 App 手动下单等脚本拦不住的路径），检测到立即段输出 🚨 告警——AI 收到后立即查两笔持仓、**平掉较新的那笔**（平仓脚本 symbol 级隔离不误伤先开仓位）。

**跨会话副作用（已工程化处理，AI 知道即可）**：caffeinate 引用计数（`keep-awake/scripts/off.sh` 最后停盯的会话才解除防睡眠——停盯收尾照常跑 off.sh，不必关心别人在不在场）；`resume.py` 传标的参数时按市场 scope 查断层（港股会话不被美股采样掩盖、反之亦然）。

**美股差异**：美股时段 watcher 不做盯盘检查（watcher 仅港股盘中运行、美股时段不打扰用户，2026-08-12 立；2026-08-20 收缩后 watcher 的中断警报已删，会话崩溃检测全市场统一靠 task-notification 断流 + 用户发现）。逐笔实测升级流程各会话各测各的。

## 盯盘对话输出要精简（唯独盯盘要精简）

实时盯盘盘面秒变，对话输出要精简、信息密度高——结论直接给、动作直接执行、不展开「为什么」的长篇解释（长解释会让用户收到时情况已变、结论失配）。盯盘报告简短陈述关键事实（价格、变化、盘口关键值）+ 直接给判断；无动作一行带过（价 + 变化 + 判断）。

⚠️ **精简靠用通用术语直接陈述，不靠自创缩写；语义清晰仍是底线**（不为短牺牲语义、不自造缩略说法）。**唯独盯盘要精简**——复盘、一般对话、写入文件（含 skill / 文档）都不精简，用大白话把逻辑说清（见全局 CLAUDE.md「输出风格」、项目 `.claude/CLAUDE.md` 工作规则「输出与写作风格」节）。

⚠️ **精简 ≠ 不输出**（2026-08-17 立）：「每段给判断」与「精简」的合规交集 = **一行式模板**（见上「每段最小输出模板 + 分析心跳」）——把判断压进一行是精简，跳过判断不输出是空转（2026-08-17 实录：52 次纯重启采样、0 分析文本）。两条规矩以此衔接：精简约束的是判断行的长度，不豁免判断行本身。
